# Benchmarks

The benchmark program of [docs/36 §3](../docs/36-ROADMAP-v0.4.md) (ADR-079). Every number comes
with the hardware, the store and the load mix it was measured under.

| Path | What |
|---|---|
| `scenarios/*.toml` | One scenario per file: rooms, connections, seeds, the load mix (idle / presence-only / typing and their rates), duration, faults, pass rules, and `[size.quick]` / `[size.short]` overrides. Files with `legacy = "X"` are the docs/22 scenarios, run unchanged by `scripts/bench.sh X` |
| `fixtures/` | `canvas-{s,m,l,50mb}.ocanvas`, generated by `scripts/bench/run fixtures` (seeded, not committed) |
| `results/` | One JSON per run: `<date>-<scenario>-<size>-<machine>.json` and `<date>-browser-<machine>.json` |
| `budgets.toml` | Browser budgets: initial JS and `forbid` (every push), heap and first screen per fixture (nightly) |

## Server scenarios

```sh
CARGO_TARGET_DIR=… scripts/bench/run x10k --size short       # the full 10k mix in ≈ 5 min on a laptop
scripts/bench/run r1k --size quick                           # the pull-request size (200 peers)
scripts/bench/run x10k --size short --connections 5000 --rooms 250   # scaled down: say so with the number
scripts/bench/run storm | soak | a | b | …                   # see scenarios/
DATABASE_URL=mysql://… scripts/bench/run x10k --size quick --store mysql
```

The runner (`oc-bench scenario`, crates/oc-bench/src/scenario.rs) starts the release server on
its own SQLite database (ports 9201/9202, shifted by `E2E_PORT_SHIFT`), ramps the clients in,
records one row per bucket (edit latency p50/p95/p99/max from an editor's frame to a probe peer,
server CPU and RSS, frames, drops, reconnects, joins refused by a full room), runs the faults
(`kill-restart`: `kill -9`, restart on the same database, clients reconnect with backoff), and
judges the pass rules. Rules it cannot measure are listed under `notMeasured`. The server sends
merged frames on a 40 ms tick (docs/22 §9.3), so ≈ 41 ms is the latency floor.

`BENCH_MACHINE` names the machine (`local` until a reference machine is chosen).

## Browser

```sh
cd e2e && npx playwright test -c perf/bench.config.ts   # BENCH_FIXTURES=s,m BENCH_RUNS=3
node scripts/bench/check-browser.mjs bench/results/<date>-browser-local.json
bash scripts/bench/check-fast.sh                        # initial JS budget and --forbid
```

First screen, heap after GC, DOM nodes, script bytes before the first screen and long animation
frames (load and scroll), Chromium with a 4× CPU throttle and 40 Mbit/s, 40 ms RTT.
