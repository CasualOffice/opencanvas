Decisions for the owner
  1. One organisation per deployment, with workspaces inside it (like teamspaces), teams as share groups and a private "My canvases" per person (3a). No multi-tenant mode.
  2. First run asks for a one-time setup code printed in the container log, except when opened from the same machine (1a, 1b).
  3. Sign-in offers a passkey first, then SSO when configured, then e-mail and password (2a). A passkey can be someone's only sign-in (2b).
  4. Every invite is a copyable link; it is also e-mailed only when SMTP is set up. E-mail is optional everywhere (8c).
  5. Public links ("Anyone with the link") are view only in the first release and off until an admin turns them on (5a, 9a).
  6. Inherited access (from a workspace or folder) is shown in the share dialog but changed only where it comes from (5a).
  7. Trash keeps items 30 days. History keeps every save for 24 hours, hourly for 7 days, daily for 90 days, named versions forever (4a, 7a).
  8. Search shows only canvases the person can open, and says so in the empty state (6a, 11c).
  9. Phone: a bottom bar with Home, Search, New, Inbox and You; the canvas uses the engine's own phone editor inside the Workspace header (10a, 10b).
  10. PostgreSQL is left out of the first release (SQLite by default, MySQL or MariaDB optional), see docs/40 §9.
  11. New in this revision (owner decision 8, docs/40 §0), for approval: files are typed. New offers Document, Spreadsheet, Whiteboard and Database, each with its own icon. A spreadsheet opens straight into the full-screen grid, a whiteboard into the full board, a database into its views; a document opens the canvas editor. Mixing blocks stays inside documents (13a to 13j).

OpenCanvas Workspace

A ready-to-use workspace from OpenCanvas by CasualOffice. Run one Docker image, create the admin account, invite people and start writing: no integration and no host app of your own. The Workspace is a separate host application that owns people, sign-in, files and access, and opens canvases in the OpenCanvas editor through the same host contract as any other app (ADR-085, ADR-001 unchanged).

Frames 1a, 3a, 4a, 5a, 6a, 7a, 8a and 9a are live: step through setup, switch the sidebar, grid and list, star canvases, make a canvas from a template, open version history, change roles and link access, type a search, restore from Trash, switch tabs and settings pages. Sample organisation and people are fictional (Acme).

1 · First-run setup

The first visit after docker run -p 8080:8080 ghcr.io/casualoffice/opencanvas-workspace. Four short steps, then Home. The setup code protects a server that is reachable from the internet before anyone has claimed it.

2 · Sign in, sign up from an invite, passkey, SSO

The sign-in page shows only the methods the admin turned on. Branding (logo, name, accent and a short message) comes from Settings › Branding. SSO buttons carry the provider name the admin typed and a generic key icon, never a brand logo.

3 · Home

The sidebar holds search, Home, Recent, Favourites and Shared with me, then the workspaces with their folder trees, then Templates and Trash. The main area continues where you left off, then lists canvases as a grid or a list. Live dots show who is in a canvas right now.

4 · A canvas inside the Workspace

The Workspace header around the OpenCanvas editor: breadcrumb, star, save state, who is here, version history and Share. Everything under the header is the engine's editor, launched with a token from the Workspace like any host.

5 · Share dialog

People, teams and e-mail addresses, each with a role, then general access. Access from the workspace or a folder is listed with where it comes from.

6 · Search across canvases

One search box (⌘K) for titles, text, database rows, board text and, when the admin allows it, comments. Results open at the matching block.

7 · Trash

Deleted canvases and folders wait here for 30 days. Anyone with Full access can restore them to where they were; admins see everyone's trash.

8 · Members and teams

Admins manage people, their organisation role, teams and open invites. Teams are share targets and can come from SSO groups.

9 · Workspace settings

Everything an admin sets after the first run. A value the operator fixed with an environment variable shows as "Set by the operator" and cannot be changed here.

10 · Phone

Home and a canvas at 390 × 844. Touch targets are at least 44 px; the canvas uses the engine's phone editor under a compact Workspace header.

11 · Empty states

Every list has an empty state that says what goes there and offers the next step.

13 · File types owner decision 8 · for approval

Every file in the Workspace has a type. New offers a Document, a Spreadsheet, a Whiteboard or a Database, each with its own icon and colour in Home, search, trash and on the phone. A spreadsheet opens straight into the full-screen grid with a formula bar and sheet tabs; a whiteboard opens into the full board; a database opens into its views. A document opens the canvas editor as today, and that is where blocks mix. The Workspace never shows a spreadsheet file as a canvas with a sheet block in it.

A sheet inside a document, and a spreadsheet file

Two different things that share one engine. Inserting a spreadsheet block into a document keeps the file a document: the sheet sits between paragraphs and can expand to fill the editor for a while. A spreadsheet file is a spreadsheet from the start and never shows document chrome.
