Decisions for the owner
  1. Formula syntax (decided): spreadsheet-like, prop("Price") * prop("Qty"), upper-case functions (IF, SUM, ROUND, DATEADD), & joins text. Confirm function names are upper case in display but accepted in any case.
  2. Result type is inferred, not chosen (1e). Mixed branches (IF returning number or text) are a #TYPE error at edit time, not a silent conversion.
  3. Error cells show the code plus a reason on hover or focus (1d); column sums skip error cells and say how many were skipped.
  4. Formula editor checks as you type and disables Save while there is an error (1c). Confirm no “save anyway” escape hatch.
  5. Relations: two-way on by default within a canvas (2a); across canvases only through a live block already on the canvas, one-way, “No access” chips for readers without access, without revealing counts (2d).
  6. Rollup with no related rows shows a dash, not 0 or 0% (3b).
  7. A deleted target database keeps relation ids for 30 days so restoring it brings the links back (4a).
  8. If the WASM engine fails, show server values read-only and pause formula editing (4b), rather than blocking the database.
  9. Phone formula editing uses insert chips above the keyboard (5a).

Advanced databases

Formulas, relations and rollups for the database block (docs/36 §6.1, ADR-078). Example: Amara Okafor’s “Launch event” canvas with Launch budget, Tasks and Projects databases, and a live block of Vendors 2026 from the Procurement canvas. Magenta labels are review notes, not UI. Icons are Lucide.

1 · Formula field DB-F · ADR-078

A formula is a field type. The owner chose a spreadsheet-like syntax: fields are read with prop("Name"), functions are upper case (IF, SUM, ROUND), operators are + - * / & = <> < >. Only the expression is stored; values are computed by oc-formula (WASM in the editor, native on the server).

2 · Relations DB-R · ADR-078

A relation field holds row ids of another database. Same canvas: {dbId, rowIds}, optionally two-way. Another canvas: only through a live block of that database ({fileId, dbId, rowIds}), under the live file’s ACL and one-way.

3 · Rollups DB-RU · ADR-078

A rollup reads one field of the related rows and reduces it: count, sum, average, min, max, earliest, latest, percent checked, unique. Across canvases it reads the live projection (ADR-072) and refreshes with it.

4 · Empty and error states DB-F · DB-R

What a formula, relation or rollup shows when there is nothing to show, when its source is gone, and when the engine can’t run.

5 · Phone DB-F · DB-R · DB-RU

Phones edit fields in bottom sheets; tables become cards in the existing compact view.
