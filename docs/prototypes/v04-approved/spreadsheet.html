  1. A new “Spreadsheet” block kind (free grid, typed per cell), next to the database block, which stays typed records with prop() formulas. “Open as spreadsheet” on a database either views it live (typed columns, free columns on the right) or converts a copy (8a). Confirm both options.
  2. Formulas (owner decision): per cell, Excel syntax and function names, A1 refs, ranges, $ absolute refs, Sheet!A1; fill handle and paste shift relative refs (2a–2e). Confirm the launch set of about 120 Excel functions.
  3. Keyboard (owner decision): Excel model, typing replaces, F2 edits, F4 cycles $ (4a). Ctrl Shift E opens full screen; Esc never closes it.
  4. Paste (owner decision): HTML first, TSV fallback; formats and formulas kept inside OpenCanvas, values and formats from Excel/Sheets; values outside a dropdown list are added as new options (4b).
  5. Sort and filter move real rows (undoable) for editors; viewers filter for themselves only (4e, 10a). Per-person filter views later.
  6. Charts float over the sheet and can be placed on the canvas as a linked chart block (4h). Confirm the linked chart block is in scope for v0.4.

Spreadsheet block

Rework after the owner’s review: “it should be like a spreadsheet”. A new block kind that behaves like Google Sheets or Excel: column letters and row numbers, A1 name box, per-cell formulas with relative, absolute and cross-sheet references, a formatting toolbar, number formats, merge, conditional formatting, several sheets, freeze panes, filters, find and replace, data validation and charts. Kept from the first round: other people’s selections, comments on cells, undo, 100,000 rows virtualized, the selection sum, phone. Example: Amara Okafor’s “Launch event” canvas with a “Launch budget” spreadsheet (sheets Budget, Rates, Summary). Magenta labels are review notes, not UI. Icons are Lucide.

Data model. Each sheet is a Yjs map with ordered arrays of stable row ids and column ids and a sparse cell map keyed rowId:colId → {v, f, s} (value, formula, style id; styles in a shared table). Formulas are stored with references as ids and shown as A1, so concurrent inserts, deletes and moves keep every formula right; a deleted target becomes #REF!. Recalculation: the worker keeps a per-sheet dependency graph (cell → cells that read it, ranges as interval entries); an edit marks its dependents dirty and recalculates them in topological order, visible cells first, with cycles reported instead of looping.

1 · Spreadsheet block, open full screen SS-BLOCK

A new block kind: a free grid like Google Sheets or Excel, with several sheets, per-cell formulas and formatting. In the canvas it shows a window onto the active sheet; full screen gives the whole spreadsheet.

2 · Formulas SS-FX

Per-cell formulas with A1 references, as in Excel: =B2*C2, =SUM(B2:B10), $B$2, Rates!B1. References are stored against stable row and column ids, so inserts and moves by anyone keep them right.

3 · Formatting SS-FMT

Per-cell styles from the toolbar and Format menu, stored as shared style ids so 100,000 formatted cells stay small.

4 · The grid SS-GRID

Rows and columns are real and ordered: insert or delete anywhere, freeze panes, filter a range, find and replace, data validation, charts.

5 · Sheets SS-TABS

Several sheets per spreadsheet block, in tabs along the bottom.

6 · People, undo, comments SS-COLLAB

As in the canvas: everyone’s selection in their colour, undo of your own steps, threads on cells.

7 · Large data SS-BIG

Rows and columns are virtualized as approved for large tables; recalculation runs in a worker.

8 · Next to database blocks SS-DB

Databases stay typed records (fields, views, relations, rollups, prop() formulas). The spreadsheet is the free grid. A database can be opened as a spreadsheet.

9 · Phone SS-PHONE

Full screen is a page with a back arrow; formatting moves to a sheet; the formula bar becomes the editor.

10 · Offline and view only SS-ERR · roles

Formula errors are in 2e. Here: connection loss and the view role.
