Decisions for the owner
  1. Row count always visible in the block header; clicking it (or Ctrl G) opens Go to row (1a, 1b).
  2. Scrollbar position label (“Row 48,210 of 100,000”) shown only while dragging the thumb (1a), not permanently.
  3. Frozen first column = row number + primary field; people can’t freeze more columns in v0.4 (1a). Confirm.
  4. Worker states: nothing under 300 ms, then a header chip with percent and a 3 px bar; old order stays usable (1c).
  5. Placeholders are static grey shapes sized from the header; no shimmer animation (2a). Loading text only after 400 ms (2b).
  6. Failed loads retry automatically with backoff and a visible countdown; stop counting after five tries (2c).
  7. Session-only offline shows “Not on this device” for blocks never loaded (2d); with an offline copy every block is fetched up front.
  8. Bulk edit sets one field to one value in v0.4 (no formulas or find-and-replace in bulk); batches of 2,000; one undo step (3b, 3c).
  9. “Select all N matching” is explicit after selecting the visible screen, never implied (3a).

Large databases and partial sync

Virtualized tables and boards for 100,000 rows (docs/36 §6.1, DB-A4/A5) and the placeholders partial sync shows while a heavy block is not loaded yet (docs/36 §2, ADR-076). Example: Acme Docs’ “Support operations” canvas with a 100,000-row Support tickets database and an Escalations board. Magenta labels are review notes, not UI. Icons are Lucide.

1 · 100,000-row table DB-V · DB100K

Rows and columns are virtualized: only what is on screen (plus a screen either side) is in the DOM. Header and the first column stay put. Sort, filter and group run in a Web Worker index built from Yjs events, so the page never freezes.

2 · Partial-sync placeholders PSYNC · ADR-076

Each database, board and diagram is a subdocument. The first screen paints the text and a placeholder per heavy block, sized from its header (row or card count) so nothing jumps when it loads. A block is requested when it comes within one screen of the viewport.

3 · Bulk edit DB-V

Selection works on the worker index, not on DOM rows, so “all 32,118 in this filter” is one click. Changes go in batches and undo as one step.

4 · Phone DB-V · PSYNC

On a phone the table is the existing card list, virtualized the same way.
