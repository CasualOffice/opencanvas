Decisions for the owner
  1. Plugin views sit in Add view under “From plugins” with the publisher's name; OpenCanvas keeps the database title, tabs, filters and toolbar, and the plugin draws only the area below.
  2. A view receives only the fields its settings name, only for rows the person can see, and writes as the person. The settings panel says this in plain words.
  3. Without the plugin a view shows as a table with a note and a Request it button; its settings are kept.
  4. Plugin importers and exporters are listed after the built-in ones and always carry “Runs on the server”. They get the file only, no network, 50 MB and 60 seconds by default.
  5. A plugin import shows the same compatibility report as built-in imports, and a limit stops it with nothing created.
  6. Plugin actions are grouped under the plugin's name in Then; the form comes from the action's schema and a generated sentence says what is sent where.
  7. A turned-off or revoked plugin pauses only the rules that use it, with the reason in the run history.
  8. Plugin shortcuts never replace built-in ones; commands blocked by policy stay visible, disabled, with the reason.
  9. Connections are per person by default; an admin can share an organisation connection whose token nobody can see. Tokens never reach browser code.
  10. Pasted links that a provider recognises become a saved link card (title and state), refreshed by whoever has a connection.

Extension points

Prototype for review (v0.5, docs/38 §5, ADR-084). What people see of plugins inside a canvas: a database view drawn by a plugin, a plugin importer in the import dialog, a plugin automation action in the rule editor, plugin commands, and connections to outside services. Sample plugins: Swimlanes (Northbeam Labs), Confluence and Obsidian importers (Fieldnote Software), GitHub issues (Kestrel Dev); publishers are fictional and no brand logos are used. Frames 1b and 2a are live.

1 · A database view from a plugin EXT-02 · ADR-084

A plugin view is one more choice in Add view, next to Table, Board, Calendar, Timeline and Workload. It shows the same rows with the same filters; it only receives the fields its settings name, and its edits go through the same checks as any other edit. The example is Swimlanes by Northbeam Labs: a board split into lanes.

2 · An importer from a plugin EXT-04

The import dialog lists the built-in formats and, below them, the importers the organisation has turned on. Plugin importers run on the OpenCanvas server in a sandbox with no network; the result is checked like any other import before the canvas opens. Frame 2a is live: choose a format, then Import.

3 · An automation action from a plugin EXT-06 · ADR-067

Plugin actions appear in the rule editor's Then list under the plugin's name. Their settings form is built from the action's schema and can use row values as tokens. They run on the server as the rule's owner, under the same limits as built-in actions.

4 · Commands and connections EXT-03 · EXT-07

Commands from plugins appear in the command palette and, when the plugin says so, in the / menu and the block menu. Integration providers add connections people manage themselves, and can turn pasted links into previews.

5 · Phone below 45em

Plugin views get the phone width and a compact flag; Swimlanes shows one lane at a time with chips to switch. Plugin importers appear in the phone import sheet with the same notes.

6 · When a plugin is missing, off or revoked

Every extension point has a defined fallback, so a canvas never breaks because of a plugin.
