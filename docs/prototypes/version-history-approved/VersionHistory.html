Version history and changes

Every screen and state for VH-01 (version history) and VH-02 (visual diff), drawn at real sizes (desktop 1280 × 800, phone 390 × 844). Nothing here is built; these are for approval before any UI code (ADR-011). Design: docs/30-VERSION-HISTORY.md, ADR-051 and ADR-052 (Proposed).

The model in one line. The host keeps every saved version of the file; OpenCanvas lists them, shows them, compares them and restores by making a new edit. OpenCanvas stores no versions.

Colours of change (tokens, light and dark): green added, red removed, amber changed, purple moved. Each is also carried by a bar, strike, underline or icon, never colour alone.

Example: the “Sprint 42 planning” canvas with a backlog database and a rollout board. All icons are Lucide; use the switch above for light and dark.

Decisions for the owner are in the notes and in docs/30 §10: who sees history by default (7a/7b), folding automatic saves (1b), naming with no changes (2a), comments on restore (5a), Undo after restore (5b).

1 · Version history panel VH-01

Opened from the canvas menu. The panel lists what the host keeps: grouped by day, named versions with a tag, runs of automatic saves folded into one row with who edited. Picking a row previews it.

2 · Naming a version VH-01

A name marks a point worth coming back to. It saves now with the name; there is still no Save button (ADR-012).

3 · Previewing an old version VH-01

Selecting a version shows it read-only in place of the canvas. The live canvas keeps running underneath; others keep editing.

4 · Changes between versions VH-02

With Show changes on, the preview marks what changed against the version before it, or any version picked with Compare with. The server computes the diff (ADR-052); the editor only draws it.

5 · Restore VH-01

Restoring is a new edit, not a rewrite. The canvas is saved first, then changed back, then saved again as “Restored from …”. Every version stays in the list.

6 · Restore while others are editing VH-01

Other people may be typing when someone restores. Their work is in “Before restore”, and anything they type afterwards is kept.

7 · View-only users VH-01

By default only editors see history (decision 1). A host can grant it to viewers with the history permission.

8 · Hosts without history VH-01

When the host keeps no versions OpenCanvas can read, the panel says so plainly, and links to the host’s own version page when there is one.

9 · Phone VH-01 · VH-02

Below 720 px the panel becomes a full-screen page and the preview gets a bottom bar. Same rules, larger targets (44 px rows and buttons).
