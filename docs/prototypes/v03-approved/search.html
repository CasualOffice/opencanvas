Search: find in a canvas, and across canvases

Every search screen for v0.3 (docs/34 §3, rows SRCH-01..05), drawn at real sizes (desktop 1280 × 800, close-ups 860 wide, phone 390 × 844). Nothing here is built; these are for approval before any UI code (ADR-011).

The model in one line. Find and replace runs in the editor over the open canvas. Search across canvases belongs to the host, which already owns the files and the permissions: every save carries the canvas’s plain text (search.json), the host indexes it, and the editor asks the host’s optional GET /search callback as the person searching. OpenCanvas stores no index (ADR-001).

Example. The Acme Docs host, the “Sprint 42 planning” canvas with its “Sprint 42 backlog” database and a live block “Q4 OKRs”, searching for “SSO”. Amber marks matches. Magenta labels are review notes, not UI. All icons are Lucide.

Decisions for the owner
  1. Find bar floats at the top right of the document column (1a), not a full-width bar under the top bar. On phones it replaces the top bar (5a).
  2. Search in text, databases and boards by default; comments opt-in and find-only (1b). Replace never edits someone’s comment.
  3. ⌘F inside the canvas opens our find, not the browser’s (1a). Outside the canvas the browser’s find is untouched.
  4. Replace all in this canvas skips live blocks and says so; replacing inside a live block is a separate confirmation, applied in its own room (1f).
  5. Pattern search (regular expressions) ships in v0.3 with a 50 ms budget per keystroke (1g). Alternative: drop patterns until v0.4.
  6. Cross-canvas search is the host’s: search.json in every save plus an optional GET /search callback; OpenCanvas keeps no index (section 2, 6). “Search all canvases” is hidden, not disabled, for hosts without the callback (2e).
  7. search.json excludes comments by default ([host.search] comments), never includes in-file history, and caps at 2 MB (6a).
  8. The API search (GET /api/v1/search, MCP canvas_search) needs a user token; a host key cannot “search as everyone” (6b).
  9. Results come from the host’s last index, and the dialog says so in its footer (“they update when a canvas is saved”) rather than overlaying live rooms (2a).

1 · Find and replace in a canvas SRCH-01

Find runs in the editor over the live document: text, database cells and board text, plus comments when asked. Nothing is sent to the server to find; replace is ordinary editing, so the server’s role filter applies as it does to typing.

2 · Search all canvases SRCH-03 · SRCH-04

OpenCanvas keeps no index (ADR-001). The host already indexes its files; every save now carries the canvas’s plain text (search.json), and the editor asks the host’s optional GET /search callback, as the person searching, so the host’s ACL decides what comes back.

3 · The host’s own search SRCH-02 · SRCH-05

Most people search from the host, not from inside a canvas. The host indexes search.json from each save and shows canvas content beside its other files, with deep links to blocks.

4 · Keyboard SRCH-01 · SRCH-04

Every action has a key, and focus always comes back where it was.

5 · Phone SRCH-01 · SRCH-04

Below 720 px the find bar takes the place of the top bar and the options move into a bar above the keyboard. Targets are 44 px.
