Offline-first editing

Every screen and state for offline editing in v0.3 (docs/34 §3, tracker OFF-01..08), at real sizes (desktop 1280 × 800, close-ups 860 wide, phone 390 × 844). Nothing here is built; these are for approval before any UI code (ADR-011).

The model in one line. The canvas’s Yjs document is kept in the browser’s IndexedDB on the person’s own device, only when the host allows it and the person turns it on; the server still stores no documents (ADR-001), reconnecting is always a fresh launch through the host, and Yjs merges what was done offline.

Example. Priya Raman in Acme Docs, canvas “Sprint 42 planning”, 23 changes made on a train. Magenta labels are review notes, not UI. All icons are Lucide.

Decisions for the owner
  1. Offline copies are off by default at both levels: the host enables [host.offline] and sends perms.offline, and the person turns on each canvas per device (2a). auto_recent is the host’s opt-in to keep recent canvases without asking.
  2. The indicator is the existing save pill (1a), not a new banner; banners only for locked, revoked and paused (5a–5d).
  3. Offline copy lifetime: 7 days by default, at most 30; after that the copy locks (title only) and unsent changes stay until the next sign-in (5c).
  4. Became view only while offline: unsent changes are held, with Download my version (needs perms.download) or Discard; never sent as suggestions (5a).
  5. Access removed while offline: the copy and its unsent changes are deleted, and we say how many changes were lost (5b).
  6. Merge summary only for two cases: edits inside a deleted block (offer “Restore my text as a new block”) and the same database cell changed on both sides (show both, offer “Use mine”) (4c). Everything else merges silently.
  7. The server saves a checkpoint version “Before <name>’s offline changes” before applying more than 10 minutes or 200 changes made offline (4b, 4c).
  8. Limits per person per host per device: 50 canvases, 200 MB; per canvas 20 queued files / 50 MB and 5 MB of unsent changes, then editing pauses (2e, 3b, 5d).
  9. Sign-out must clear the device: hosts call OpenCanvas.clearOffline() or load the /v1/offline/clear iframe; the device key is deleted first (6b, 7a). Host-wide revoke per person through POST /api/v1/offline/revoke (6a).
  10. Offline copies are JWT-hosts only in v0.3 (no WOPI claim exists); WOPI hosts keep session resilience (1c).
  11. Collaborators get one toast when a long offline session arrives (4e); short ones arrive like any edit.

1 · Offline indicator OFF-06

The save-status pill in the top bar is the indicator: it already says Saved or Saving, so offline is one more state of the same control, not a new banner. A popover gives the detail. Full-width banners are kept for the three states that stop work: locked, revoked and paused (section 5).

2 · Make a canvas available offline OFF-02 · OFF-06

Two levels of opt-in: the host turns offline copies on ([host.offline] enabled, and perms.offline in this person’s launch token), then the person picks which canvases to keep on this device. Default off on both levels.

3 · Working offline OFF-02 · OFF-05 · OFF-06

Editing offline feels like editing online: same canvas, same undo, same tools. What needs the server is disabled with a reason in place.

4 · Reconnecting and merging OFF-04 · OFF-06

Back online, the editor relaunches through the host (a fresh token via POST /tokens/refresh; the offline grant is never a credential), uploads queued files, then sends the changes in pieces the server checks like any other edit. Yjs merges; people only see a panel when something needs a decision.

5 · Conflicts and limits OFF-01 · OFF-04

What happens when the host’s answer on reconnect is not the one the offline grant assumed, and when local limits are hit. These are the only offline states that use a full-width banner.

6 · Host opt-in OFF-01 · OFF-07

Operator and host integration, for the reader of the integration guide. Off unless both the hosts file and the launch token say yes. OpenCanvas still stores no documents on the server: the copy lives on the person’s device, under the host’s policy, like a download.

7 · Shared computers and signing out OFF-07

Three protections stack: the host doesn’t offer offline on shared sessions (2d), signing out clears the device, and copies are partitioned by host and person so the next person sees nothing.

8 · Phone OFF-06

Below 720 px the pill shows only its icon (amber or red when it matters); tapping it opens a sheet. Targets are 44 px.
