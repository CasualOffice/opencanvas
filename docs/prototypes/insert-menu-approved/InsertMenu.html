Block insert: one menu, many experiences

The redesigned way to insert blocks in v0.2.1: a categorised / menu with Quick insert, Recent, goals and Explore; consolidated variants; intent search; and host profiles. Drawn at real sizes (desktop 1280 wide, close-ups at 860 to 1100, phone 390 × 844) in the editor’s tokens. Nothing here is built; these are for approval before any UI code (ADR-011).

The model in one line. One insert engine and one catalogue (block, variants, aliases, intent words); the host’s profile picks what is offered and how the menu is banded; the browser remembers what each person uses.

Today vs proposed. Today’s menu lists 25 items in Basic, Data, Media and Layout (three headings, three lists, two column items). Proposed: 19 built-in blocks in five categories (Content, Data & planning, Visual & diagrams, Layout, Extensions), with six carrying variants. Example canvas “Checkout redesign kickoff” in Acme Docs, with the approved SDK blocks acme.okr and acme.ticket. Magenta labels are review notes, not UI. All icons are Lucide.

Decisions for the owner
  1. Variant picking: inline segmented for Heading, List, Callout, Columns; second step for Database and Diagram (2a). Enter always inserts the shown (remembered) variant.
  2. Keys: Tab and Shift+Tab change an inline variant; → goes deeper, ← back; arrows never change a variant (2a, 6b). Alternative considered: ← → on the variant, rejected because it fights “back” in a category.
  3. Desktop categories open beside the menu (flyout), phone drills in (1b, 7b).
  4. Media is folded: Image and Embed go to Visual & diagrams; Link preview and File to Content; Toggle and Divider to Layout; Date to Data & planning (1b–1d).
  5. Diagram replaces nothing: Whiteboard stays a separate block next to Diagram (1d). Diagram offers 8 types; BPMN only when the host turns it on (2c).
  6. SDK placement: a new optional manifest field category places a block inside a discovery category with the approved third-party tile; every SDK block is also under Extensions, headed “From your organisation” (1b, 1e, 3d). Optional intents too.
  7. Intents are keyword matching only, local, with a one-line “why” per result (3a–3d). Hosts can replace the chips or turn them off.
  8. Recent: variant-level, at most four shown, skips what is a quick tile, hidden on first visit, localStorage only with a 24-entry cap; remembered variants only from the menu, not from markdown (2e, 4a, 4b).
  9. Profiles: workspace (default), meeting, diagramming; 8 or fewer blocks means a flat list without bands (5a). New host keys [host.insert] profile, quick_insert, hide, intents, chips (5e).
  10. Hidden blocks are never offered (menu, phone, gallery, markdown) and nothing says they are hidden; existing ones render and edit normally and paste keeps them (5c). Nothing to insert means no menu and no + (5d).
  11. Focus appearance: active item = --accent-soft fill + 1.5 px --accent inset ring, replacing the faint --hover for keyboard focus in all editor menus (6b).
  12. Phone: variants are always a second step; “/” with the keyboard open docks results above it (7c to 7e).
  13. Gallery takes the same five categories and shows variants as chips (8a).

1 · The menu: “What do you want to insert?” INS-01 · v0.2.1

Typing / on an empty line (or pressing the gutter +) opens one menu with four bands: Quick insert (the host’s quick_insert, else the profile’s defaults), Recent (this browser only), Start from a goal (intent chips) and Explore (five categories). The menu is the same engine everywhere; the host’s profile decides which bands and blocks show (section 5).

2 · Consolidated variants INS-02

Six blocks that used to be several menu items each now carry a variant. Two ways to pick it, by how many choices there are and how much a preview helps: inline segmented (2 to 4 short choices) and a second step (choices that need a picture). The remembered variant is per person, kept with Recent in the browser (section 4).

3 · Intent-based discovery INS-03

People who do not know a block’s name can say what they want to do. Chips offer common goals; typing a phrase does the same. Matching is plain keyword matching in the browser (words and simple stems against each block’s and variant’s intent words, plus SDK manifests’ keywords). No AI, no network call, nothing logged.

4 · Recently and frequently used INS-04

What people insert often is one keystroke closer. Kept in this browser only: never sent to OpenCanvas, the host or other people.

5 · Host profiles INS-05

One engine, several experiences. A host picks a profile (the set of blocks and bands) and may adjust it with quick_insert and hide. Hidden blocks are never offered, but blocks already in a canvas are untouched.

6 · Search, keyboard and focus INS-06

The menu is a combobox owned by the editor: focus stays in the text, the active item is announced with aria-activedescendant, and every action has a key.

7 · Phone INS-07

Below 720 px the + in the editing toolbar opens the same menu as a bottom sheet; typing “/” shows results docked above the keyboard. Every target is at least 44 px. Variants are always a second step on the phone: segments that small are hard to hit.

8 · Gallery, with the new categories INS-08 · BSDK-03

The approved gallery (SDK 6e) keeps its layout and takes the menu’s categories, so people meet the same five words in the menu, the phone sheet and the gallery. Extensions is last, as “From your organisation” was.
