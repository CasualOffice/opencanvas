Nextcloud app screens

Every screen and state from integrations/nextcloud/UI-SCREENS.md, drawn at real device sizes (desktop 1280 px, phone 390 px). Nothing here is built; these are for approval before any UI code (ADR-011).

Who draws what. Nextcloud chrome (header, navigation, Files list, sidebar, dialogs, Viewer bar, Talk) is recreated in Nextcloud 31's own style. The area inside a canvas is OpenCanvas, using its approved tokens. Use the switch above to see every frame in light or dark.

Decisions for the owner are called out in the notes: the default open view (S6), the New-menu names (S1a), the new file icon (S2), the "Can comment" placement (S8b) and the empty template case (S3c).

S1 · Files "+ New" menu entries RegisterTemplateCreator + addNewFileMenuEntry

Three entries sit together after the entries from other apps (Office, Whiteboard). They share one file icon family so people learn they all make the same kind of file. The name dialogs are Nextcloud's own; ours only copy its look for the two front-end entries.

S2 · .ocanvas file icon mimetype alias (today: x-office-document)

A new file-type icon, so canvases stop looking like Word documents. It follows Nextcloud's flat file icons: a coloured page with a folded corner and a white glyph. The deep indigo is a step darker than the Office document blue, and the glyph (two text lines over two blocks) reads as "document made of blocks" even at 16 px.

S3 · Template picker stock Nextcloud TemplatePicker

Nextcloud's own picker lists the .ocanvas files people keep in their Templates folder. We change nothing in it; the only work on our side is the preview image for each template. OpenCanvas's 40+ built-in templates stay on OpenCanvas's own start screen and are not repeated here.

S4 · Open view: Viewer modal src/viewer.js

Opening a canvas from Files shows it in Nextcloud's Viewer, so the Files sidebar (Sharing, Versions, Chat) stays one click away. The dark bar is Nextcloud's Viewer header. Everything below it is OpenCanvas in the iframe. Messages that come before OpenCanvas loads (not set up, server down) are Nextcloud screens. Messages during a session (access removed, session ending, conflict) come from OpenCanvas and use its approved banner and card styles.

S5 · Open view: full page templates/editor.php

The same canvas on its own page at /apps/opencanvas/open/{id}, used by the default file action and by links shared in chat or email. It keeps Nextcloud's header and adds a slim bar with the way back to Files. All S4 states (read only, download off, access removed, deleted, unreachable, not set up, session ending, conflict copy) appear the same way here; the frames below show only what is different.

S6 · Files action registerFileAction (src/files.js)

Clicking a canvas's name opens it. Which view opens depends on one choice we still need from the owner: the Viewer (S4, recommended, keeps the sidebar and Talk one click away) or the full page (S5). The other view is then offered in the "…" menu.

S7 · Public link (guest) api/v1/share/{token}/token

A guest opens a public link. Nextcloud's public page provides the header (name, who shared it, Download) and any password step. The canvas fills the rest. Guests on edit links are asked for a name first, so others know who is typing.

S8 · Sharing and permissions Nextcloud sharing sidebar

Sharing stays in Nextcloud's own sidebar; we don't change its controls. We add a short card that says what each level means in a canvas, and, when the admin turns it on, a "Can comment in OpenCanvas" option in the share's advanced settings. Changing a share while the canvas is open takes effect straight away.

S9 · Talk: canvas in chat stock Talk file message + reference provider

Sharing a canvas into a conversation uses Talk's normal "Share from Files": no new code, the file message shows our icon (and later a preview). Pasting a canvas link gets a rich card from our reference provider, which never reveals a canvas the reader can't open.

S10 · Talk: open beside the call Files sidebar chat tab + registerMessageAction

Two ways to have a canvas and a conversation side by side. (1) From Files: the canvas's own conversation lives in the sidebar's Chat tab, and its call can run there too. This works with stock Talk. (2) From any conversation: a message action opens the canvas in a split with that conversation's call. On a phone there is room for one at a time, with a quick switch.

S11 · Talk: new canvas in a conversation Talk "New file" (Templates API)

Because "New canvas" is a server-side template creator, Talk lists it in its own "New file" menu without extra code. Talk then creates the file in the creator's Talk folder and shares it into the conversation. Our database and whiteboard starters are front-end only, so they don't appear here. All of this is stock Talk; the pins in S11c are review notes, not UI.

S12 · Admin settings templates/admin.php

One page under Administration > OpenCanvas. Order follows the setup steps: address, save, copy the allow-list line into OpenCanvas, run the check, then the sharing switches. The token secret is created automatically and never shown; admins only get "End all open sessions". Admin pages are desktop-first, so there is no phone frame.

S13 · Errors (shared) JSON error codes

One set of messages, used in the Viewer, on the full page and on public links. Each says what happened, that the file is safe when it is, and the one thing to do next. Admins get a fix where users get a "tell your administrator". These are Nextcloud screens (empty-content layout) because they happen before OpenCanvas loads, except "locked", which happens while saving and is an OpenCanvas banner.

S14 · App store listing DESIGN.md §10

How the app is presented on apps.nextcloud.com and in Nextcloud's own Apps page. The screenshots are made from the approved screens. The text is the factual positioning from DESIGN.md §10; every claim must be checked against the release notes before publishing.
