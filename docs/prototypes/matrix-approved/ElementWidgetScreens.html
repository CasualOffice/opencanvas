Matrix widget screens (Element)

Every state from integrations/matrix/UI-SCREENS.md, drawn at real sizes: Element Web at 1280 px, Element Web at phone width (390 px in a bezel), and 420 px right-panel crops for the error cards. Nothing here is built; these are for approval before any UI code (ADR-011).

Who draws what. Element chrome (spaces, room list, room header, timeline, right panel, pinned tiles, the consent prompt and the identity dialog) is recreated in Element Web's own style. The widget page (S1 to S4) is ours and uses OpenCanvas tokens, following Element's theme. Everything inside the canvas is the OpenCanvas editor with its approved patterns.

Wording fix. The editor's temporary note and closed screen talked about a meeting. S5, S6 and S7b show room wording; S5f and S6c compare before and after.

Decisions for the owner are in the notes: no extra widget notice (S5), the widget title wording (S5c), "Start a new canvas" on the ended screen (S6a), the "no longer in this room" sentence (S7b), and showing the bot ID to everyone (S4c).

S0 · Element's consent prompt Element AppPermission

Element's own screen, shown before our page loads when someone else added the widget. Nothing to build; it is here so S0 to S2 read as one flow. Our page starts in S1.

S1 · Loading data-state=loading

A quiet skeleton shaped like the editor (bar, title, lines, block), so the canvas drops in without a jump. "Loading canvas…" is read to screen readers through the live region; nothing is shown as text.

S2 · Identity permission data-state=permission

Element asks "Allow this widget to verify your identity". Our page explains why, in one sentence, behind Element's dialog, and suggests ticking Remember this. It does not try to point at the dialog with arrows: Element places it, not us.

S3 · Identity refused data-state=denied

The person chose Deny. One recovery action: reload the widget so Element asks again.

S4 · Errors data-state=error

Right-panel crops at Element's widest default (420 px). Each error says what happened and who can fix it, without internals (no codes, no addresses). Transient errors get one action, Try again.

S5 · Canvas open (temporary) data-state=open

The editor shows "Temporary" next to the title and, on first open in a session, a note that the canvas is not saved, now in room wording. Recommendation: no extra notice from the widget; the editor's note already says it at the right moment, and the plain line under the frame goes away. Element also shows the widget's title ("Temporary canvas: export to keep a copy") when the widget is pinned (S5c).

S6 · Canvas ended editor closed screen

Everyone left and the idle grace passed, or the session was closed. The editor's closed screen gets room wording and one action. Because the widget stays in the room, opening it again starts a new, empty canvas; the button does exactly that (it reloads the widget).

S7 · View only and access removed role view · role none

Two access states inside the editor. View-only members see the approved view-only banner with a line about who can edit. Someone who leaves, is kicked or is banned while the canvas is popped out gets a closed screen in room wording (in the panel, Element removes the widget itself).

S8 · Adding the canvas /addwidget

Adding a widget is Element's UI, not ours; documented only. An "Add canvas" entry point would need an integration manager or an Element module.
