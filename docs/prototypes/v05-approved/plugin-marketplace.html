Decisions for the owner
  1. Install mode by default: people request, admins approve (4a). The other two modes stay available to the admin.
  2. Signatures are required, with no per-person or per-admin override. Only the operator can allow unsigned packages, and only from a named private registry, never from the OpenCanvas Marketplace (5a).
  3. Updates install on their own for patch and minor versions only when the permissions are unchanged; a new major version or any new permission waits for an admin (3d).
  4. A marketplace revocation switches the plugin off on every server within one hour (hourly index check); canvases keep their saved copies (5c).
  5. No ratings or reviews in v0.5: install counts, publisher verification and the update date only.
  6. Plugins that run on the server are off until the operator turns on [plugins] server_code; admins see why (5d).
  7. Installing is per organisation (host). No per-person or per-canvas install in v0.5.
  8. Paid plugins and publisher payouts are out of scope for v0.5.
  9. Blocked plugins stay visible in Browse with the reason, rather than being hidden (1a, 5).

Plugin marketplace and manager

The marketplace and plugin manager, inside OpenCanvas. People browse plugins from the OpenCanvas Marketplace and their organisation's own registry, see exactly what each plugin will be able to do and who published it, and request or install it. The organisation admin sets the policy; the operator who runs the server sets the outer limits. Frames 1a, 1b, 4a and 6a are live: pick a category, search, use the filters, and press Install or Request.

1 · Browse PLUG-05 · ADR-083

The marketplace opens inside OpenCanvas from the host's settings or the "Get plugins" link in the Add view, Import, Export and Automations menus. It lists the registries the operator connected (here the OpenCanvas Marketplace and Acme's internal registry). Every card says who published it, whether the publisher is verified, and whether any part runs on the server.

2 · Plugin details PLUG-05 · ADR-083 · ADR-084

One page per plugin: what it adds and where it shows up, its permissions in plain words, the publisher, and on the Security tab the signatures, the sandbox and what is inside the package.

3 · Install, manage and update PLUG-03 · PLUG-05

Installing is per organisation: one admin turns a plugin on for everyone in Acme Docs. Admins see every installed plugin, its version and its state in one place.

4 · Admin policy and requests PLUG-05 · PLUG-06 · ADR-083

The organisation admin is whoever the host marks as plugin admin in the launch token (perms.plugins: "admin"). The operator who runs the server sets the outer limits: which registries exist, whether unsigned packages are possible at all, and whether anything may run on the server. The admin chooses within them.

5 · Blocked, unsigned and revoked PLUG-02 · ADR-083

A plugin that cannot be installed still has a details page, with one banner that says why and who can change it. There is never an "install anyway" button.

6 · Phone PLUG-05

Below 45em the marketplace is one column: categories become chips, details become one scrolling page, and the request form is a sheet. Installing from a phone works the same way (frame 3a as a sheet).

7 · Keyboard and access

Each card is a group named by the plugin, with the name as a link to its details and one action button named in full ("Install Swimlanes for Acme Docs", "Request Swimlanes"). Trust badges are text, never colour alone. Blocked buttons are buttons that explain, not disabled controls that cannot be focused.
