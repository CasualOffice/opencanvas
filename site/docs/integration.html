Integration guide

Status: draft v0.1, 2026-11-21. This is the contract an integrating application implements. Modelled on Collabora Online's WOPI integration (01 §4).

Golden rule: your application decides who may open which file with what role. OpenCanvas trusts that decision for the life of the token and enforces it on every edit. Your application stores the file.

1. Choose a handshake

2. Register your host

opencanvas.hosts.toml (or hosts table):

[[host]]
id              = "acme"
name            = "Acme"
mode            = "jwt"                    # jwt | wopi | both
jwt_alg         = "HS256"                  # or RS256 / EdDSA: jwt_public_key (PEM) or jwt_jwks_url
jwt_secret      = "env:ACME_OC_SECRET"
api_key         = "env:ACME_OC_API_KEY"    # for server→server REST calls to us
callback_base   = "https://api.acme.example/opencanvas"
allowed_origins = ["https://app.acme.example"]
# frame_ancestors = ["https://chat.example"] # optional: extra origins that may frame THIS host's editor (§4)
asset_origins   = ["https://cdn.acme.example"] # extra image origins for exports (unsigned GET);
                                           # your callback_base origin is always allowed
[host.flags]
embeds          = ["youtube", "vimeo", "loom", "figma", "maps"]
export_formats  = ["md", "html", "pdf", "ocanvas"]   # formats this host allows: md, html, json, docx, pdf, ocanvas, svg/png (board images); omit for all
import_formats  = ["md", "html", "csv", "drawio", "excalidraw"]  # formats editors may import (POST /v1/import); absent or empty = import OFF;
                                           # any other value is refused at start-up
autosave_secs   = 60
on_conflict     = "copy"                   # copy | reload
team_templates  = true                     # gallery "From your team" from GET /templates (§5, TPL-01); default off
temporary_wording = "meeting"              # storage = "ephemeral" only (§8a, ADR-049): "meeting" (default) or "room"

People (docs/21 revision 2): the @mention list is the people with access to the canvas, the same for every viewer. Everyone with access sees real names and the detail second line. OpenCanvas never shows or stores e-mail.

3. JWT launch token

Signed by your backend, short-lived (≤ 10 h; 5–15 min recommended — it is exchanged for a session ticket on open).

{
  "iss": "acme",                    // = host id
  "aud": "opencanvas",
  "exp": 1763730000,
  "jti": "9f1c…",                   // single-use
  "file": {
    "id": "doc_8812",               // your stable id
    "name": "Sprint 42 notes",
    "version": "17",                // your current version/etag
    "context": { "type": "channel", "id": "c_55" }   // optional, for UI only
  },
  "user": {
    "id": "u_123",                  // stable, opaque: the identity (names are display only)
    "name": "Asha Rao",
    "detail": "Design · Bengaluru", // optional second line that tells same-named people apart
    "avatar": "https://…/a.png",    // http(s) only
    "color": "#7c3aed"              // optional; we derive one otherwise
  },
  "members": [                      // optional (docs/21): everyone with access to THIS canvas,
    { "id": "u_200", "name": "Ravi Menon", "detail": "Engineering" }   // ≤ 500; same user shape
  ],                                // (id, name, detail?, avatar?, color?); never e-mail
  "role": "edit",                   // view | comment | edit
  "perms": {
    "export": true,
    "download": true,
    "print": true,
    "commitMessage": true,          // may write "Save version" messages
    "mention": true
  },
  "mode": "edit",                   // edit | view | preview
  "callbackToken": "opaque-…",      // we send it back on every callback; you validate it
  "start": "page"                   // optional (ADR-048): open a new canvas straight into the page
}

**Skipping the start screen (start, ADR-048).** A new, empty canvas opens on the template picker. When your own UI already asked what kind of canvas it is (a "Blank or Meeting notes" dialog), put "start": "page" in the token: the canvas opens on its first line instead, and templates stay available inside the editor. The server passes it on as &start=page after the ticket in the editor URL fragment. Any other value is ignored, and servers up to 0.1.1 ignore the claim (the picker shows). It changes nothing for a canvas that already has content.

4. Embed in your page

Option A — iframe form POST (works everywhere, like Collabora)

<form id="oc" target="oc-frame" method="post"
      action="https://canvas.example.com/v1/launch">
  <input type="hidden" name="token" value="{{ jwt }}">
</form>
<iframe name="oc-frame" style="width:100%;height:100%;border:0"
        allow="clipboard-read; clipboard-write; fullscreen"></iframe>
<script>document.getElementById('oc').submit()</script>

Option B — web component

<script type="module" src="https://canvas.example.com/sdk/embed.js"></script>
<open-canvas server="https://canvas.example.com" token="{{ jwt }}"
             theme="auto" style="height:100vh"></open-canvas>
<script>
  const oc = document.querySelector('open-canvas');
  oc.addEventListener('oc:ready',  e => {});
  oc.addEventListener('oc:saved',  e => console.log(e.detail.commitId));
  oc.addEventListener('oc:presence', e => console.log(e.detail.users));
  oc.addEventListener('oc:error',  e => {});
  oc.addEventListener('oc:token-expiring', async e => oc.refresh(await myApi.newToken()));
  await oc.commit({ message: 'Final' });
  oc.setReadOnly(true);
</script>

The SDK is served with CORS for the host's allowed_origins only, and the canvas sets frame-ancestors to the same list: register every origin your pages embed from.

**Nested embeds (frame_ancestors).** CSP frame-ancestors checks every ancestor, so when your page is itself framed by another app (a Matrix widget inside a chat client, §8b), that app's origins must be allowed too. List them in the host's frame_ancestors. They are not added to the server-wide list: launches for this host redirect to /app/?h=<host id>#t=…, and only that page is served with frame-ancestors 'self' <every host's allowed_origins> <this host's frame_ancestors>. Hosts without the setting keep /app/#t=… and the shared list. The h parameter only selects the policy; the session is still the ticket.

postMessage API (iframe ↔ host page)

Messages are { "MessageId": "...", "SendTime": ms, "Values": {...} } (Collabora-compatible envelope).

Links to a block. Your link is your URL (OpenCanvas never shows one of its own inside a host). To open the canvas at a block, either pass block=<blockId> to the launch (a form field next to token, or ?block= on /v1/launch; anything but [A-Za-z0-9_-]{1,64} is dropped) and the editor opens with #t=…&block=<id>, or send Action_ScrollToBlock once the frame has loaded. examples/sample-host does both: its file page reads #block= from its own URL into the launch form, and its Mentions list sends Action_ScrollToBlock.

5. Callbacks you implement (JWT mode)

Base: callback_base. Every call carries Authorization: Bearer <callbackToken> (also sent as X-OpenCanvas-Callback-Token: <callbackToken>, for hosts behind something that strips Authorization, such as a Mattermost plugin; neither header is signed) and X-OpenCanvas-Signature: t=<ts>,v1=<hex>,v2=<hex> so you can verify the call comes from OpenCanvas:

  • v2 = hex HMAC-SHA256(secret, "<ts>.<METHOD>.<path?query>.<body>"). Verify this one. It binds the request method and path, so a captured signature can't be replayed against another endpoint.
  • v1 = hex HMAC-SHA256(secret, "<ts>.<body>"), kept for hosts written before v2.
  • Reject timestamps more than 5 minutes off, and compare in constant time.
  • OpenCanvas never follows redirects from your callbacks: answer directly.

examples/sample-host/server.mjs verifies v2.

Mentions (ADR-027). When someone @mentions people in a comment, or puts a mention chip in the canvas text, we tell you so you can notify them (we never send mail or push ourselves). One call per comment message, and one per block per edit for text mentions; threadId is set for comments, blockId for text (the editor gives the block an id when the mention is inserted, so you can link to it). by is the user whose connection wrote it (from the grant, not from the document); the author is never in mentioned. excerpt is the message or block text, at most 280 characters. A mention that was already in the file when the room loaded, or one the editor re-creates when a paragraph is split or moved, is not sent again. The ids in mentioned come from the canvas's member list (your token members or GET /files/{fileId}/members): check that each person can see the file before you notify them. Delivery is fire-and-forget for the session: the call is written to our notification outbox first, sent at once, and retried with backoff (10 s → 1 h, 8 attempts, same Idempotency-Key) when it fails with a network error, 429 or 5xx. Any other 4xx drops it. Signed like every callback. examples/sample-host logs each call and lists them on the file page. WOPI hosts get no mention calls (WOPI has no notification API); use JWT mode, or mode = "both", if you need them.

People (docs/21 revision 2, ADR-026). Every person is keyed by your stable user.id. The @mention list is the people with access to this canvas, the same for every viewer. Tell OpenCanvas who that is with members in the launch token (≤ 500) and/or the members callback above (for large audiences). Without either, the list is everyone who has opened the canvas (the people map in the .ocanvas: id, name, detail, avatar, last seen). Members merge by id: **callback > token > the saved people map**. Everyone with access sees real names and the detail second line; same-named people show name · detail (then "Last here …", then the id's last 4 characters). E-mail is never shown or stored. A mention stores the id plus a label snapshot: OpenCanvas shows the member's current name, and for someone who no longer has access the snapshot with "No longer has access". Exports use the same names.

Timeouts: 10 s (load/save), 5 s (others). Retries with exponential backoff for save (idempotent by Idempotency-Key). A save is written to our commit outbox before we call you, so it is retried with the same key even across a restart of OpenCanvas.

With jwt_jwks_url we fetch your JWKS (cached 10 min) and pick the key by the token's kid; the algorithm is still pinned by jwt_alg, so a token signed with another algorithm is refused.

6. WOPI mode

WOPI mode has its own page: WOPI mode.

6a. Nextcloud (the opencanvas app)

integrations/nextcloud/opencanvas/ is a Nextcloud app (Nextcloud 30–32) that makes Nextcloud the WOPI host of §6, the way Nextcloud Office does for Collabora. Install, configuration, limits and what has been verified are in integrations/nextcloud/README.md; the design and the choice of WOPI over JWT are in integrations/nextcloud/DESIGN.md.

  • WOPISrc: {nextcloud}/index.php/apps/opencanvas/wopi/files/{fileId}. Register wopi_allowlist = ["{nextcloud}/index.php/apps/opencanvas/wopi"] and give the host an api_key. Proof keys are required: the app refuses calls without a valid proof.
  • Roles: "Can edit" maps to edit and read-only shares map to view. Without "Allow download" (or with a public link's "Hide download"), export, download and print are off.
  • Saves and versions: every save is a normal Nextcloud write, so it shows in Versions under the editor's name. A file changed outside the canvas gets a (conflict copy) next to it.
  • Share changes: the app re-checks access on every WOPI call. When a share is removed or changed, it also calls POST /v1/files/{fileId}/role (§7), so open canvases switch to read-only or close at once.
  • Limits: WOPI mode only. The @mention list is the people who opened the canvas, and mentions send no notifications. The Nextcloud-side screens (New menu, Viewer, guests, Talk) wait for approved prototypes.

7. Server-to-server REST (you → us)

Use X-OpenCanvas-Key: <api_key> + X-OpenCanvas-Host: <host id>.

  • Revoke or downgrade a user live when you change ACLs: POST /v1/files/{fileId}/role {"userId":"u_123","role":"view"} — the user's open session switches to read-only immediately (or is closed with "role":"none"). Roles: view | comment | edit | none. Answers 200 {"connections":1,"sessions":2} (live connections switched, tickets updated); 401 API_KEY_INVALID for a wrong host/key, 400 ROLE_INVALID. The role also applies to launch tokens issued before the call (by their iat): an older token opens with this role, and with "role":"none" it is refused with 403 ROLE_REVOKED. Tokens issued after it, or without iat, use their own role. "role":"none" also takes the user out of the canvas's member list at once (the cached members answer is dropped, open editors refetch it, and an older token's members no longer counts for them) until you grant access again or they open the canvas with a new token.
  • Member list changed (someone added or removed outside a role call): POST /v1/files/{fileId}/members/invalidate → 200 {"invalidated":true}. Drops the cached members answer; open editors refetch /v1/members. Same headers as every call here.
  • Patch content from a bot: POST /v1/files/{fileId}/patch (see 04 §6) with {"ops":[…],"author":{"id","name"}}. Ops: append, insertAfter{blockId}, replace{blockId}, delete{blockId}, each with markdown or Tiptap blocks. Blocks are addressed by their blockId attribute; the answer lists the ids of the blocks you inserted ({"applied":2,"blockIds":["b_…"],"live":true}). If nobody has the file open we load it from you, apply and save straight away (the answer then carries version). Send X-OpenCanvas-Callback-Token: <token> if your callbacks need a bearer for that load/save.
  • Force save before you snapshot/backup: POST /v1/files/{fileId}/commit → 200 {"live":true,"saved":true,"version":"18"} once your PUT answered, 202 {"queued":true} if it failed and will be retried from the outbox, 409 on a conflict.
  • Close everything (file deleted/moved): DELETE /v1/files/{fileId}/session — a final save, then every connection is closed and every ticket for the file is dropped. 200 {"closed":true,"sessions":3}.
  • Import into a canvas (docs/23 FC-10): POST /v1/files/{fileId}/import?format=md|html|csv&author=<userId>[&authorName=][&blockId=][&name=] with the file as the raw body (UTF-8, ≤ 5 MiB). Markdown and HTML become blocks; HTML keeps only http(s), mailto:, relative and # links and http(s)/relative/data:image/ image sources, and drops scripts, styles and event attributes. CSV becomes one database block (first column the title; other columns typed number, date YYYY-MM-DD, checkbox true|false|yes|no, select for ≤ 20 repeated values, else text), ≤ 10,000 rows and ≤ 200 columns (413 IMPORT_TOO_LARGE). It lands after blockId, or at the end, as one change. Needs the format in [host.flags] import_formats (else 403 IMPORT_OFF); the operator's OC_IMPORT=off refuses every import. Answers {"format","blockIds",…,"live"}, plus version when nobody had the file open (saved straight away, like patch). Editors use the same with a session: POST /v1/import?format=&ticket= (edit role only); the session response carries import.formats so the editor shows the entry only when allowed.
  • Diagram files (DGM-15, docs/29 §7): format=drawio (.drawio, diagrams.net .xml, compressed pages too) and format=excalidraw, same 5 MB limit and gate. dryRun=1 converts and answers {"format","dryRun":true,"report"} without changing anything; report is {pages, page, counts: {shapes, connectors, images, containers, needLook}, items: [{level: warn|gray|ok, code, title, detail?, count, examples}]}, most important first. page=<n> (0-based) picks a draw.io page. The import adds a board block after blockId (or at the end), or adds to an existing board with boardId= (to the right of its shapes), and answers {"boardId","blockIds","shapeIds","shapes","connectors","report"}. Unreadable, too deep, too large after decompression or entity-declaring files get 400 IMPORT_INVALID / 413 IMPORT_TOO_LARGE with a plain-words reason. Nothing is ever fetched from a file.
  • Stateless conversion: POST /v1/convert?from=md|html|ocanvas&to=ocanvas|md|html|json|docx|pdf with the file as the raw body. DOCX and PDF embed images only from your callback_base origin (fetched signed) or an asset_origins entry (plain GET) — no redirects, ≤ 10 MB, image/* only; other images become links. Boards become pictures (PNG in DOCX, SVG in HTML/PDF). to=pdf needs the operator to run the Gotenberg sidecar (OC_PDF_RENDERER), else 501.

7a. MCP endpoint (AI-01, ADR-032; off by default)

Turn it on per host with [host.ai] mcp = true, and give it a public URL: OC_PUBLIC_URL, or [host.ai] mcp_audience for this host. Without one, MCP stays off (404) and the server logs a start-up warning; the audience is never taken from the request's Host header. External MCP clients and your own agents call POST /mcp/{hostId} (streamable HTTP, stateless, one JSON-RPC message per POST, JSON answers; MCP 2026-07-28, and 2025-11-25 by version negotiation). Methods: initialize (server/discover), ping, tools/list, tools/call, resources/templates/list, resources/read (canvas://{hostId}/{fileId} Markdown, ….json document JSON). MCP and the headless API (§7b) share one auth check: the same scope ceiling, files rule, /access role and revocation; a canvas:comment token may comment.

Tokens are yours. OpenCanvas runs no OAuth server. You mint an access token (JWT) with the same keys as launch tokens (HS256 secret, PEM or JWKS):

claimvalue
issyour host id, or [host.ai] mcp_issuer
aud{mcp_audience or OC_PUBLIC_URL}/mcp/{hostId} (a token for another host or a launch token is refused)
subthe user id (svc:<name> for a backend job)
expat most 15 minutes ahead
scopespace-separated canvas:read, canvas:comment, canvas:write, canvas:write:direct
rolethe user's role on the files (view/comment/edit; absent = view)
filesthe file ids the token covers; required when you do not implement POST /access (see below)
name, client_idoptional display name; client id recorded in the edit origin mcp:<clientId>

Role source. If you implement the optional POST /access callback (§5), OpenCanvas asks it for the user's role on each file an MCP call touches (cached 30 s) and ignores the token's role claim; none refuses every tool. Without it, the role claim is trusted, but only for the files the token lists in files: a token without files is refused (ROLE_FORBIDDEN, FILES_REQUIRED: …). Setting [host.ai] mcp_all_files = true lifts that and lets one token's role apply to every file of the host; it is broad, so prefer files or /access (SEC-34).

The effective permission is min(scope, role): canvas:write does not let a view user write, and a canvas:read token does not let an editor write. A request without a valid token gets 401 with WWW-Authenticate: Bearer resource_metadata="https://<opencanvas>/.well-known/oauth-protected-resource/mcp/{hostId}"; that RFC 9728 document names your mcp_issuer as the authorization server. Tokens are never forwarded to you; callbacks stay HMAC-signed. Each token gets 120 requests/min (burst 240, [host.ai] mcp_rate_per_min), then 429.

Tools (each takes fileId): canvas_read, canvas_find, db_describe, db_query, board_read, comment_list, members_list (read); comment_add (comment); canvas_patch, db_upsert_rows, db_create, db_add_field, board_add_shapes (write). Edits are live Yjs transactions, broadcast and autosaved like a person's. Canvas content comes back wrapped as untrusted data. Changes to existing blocks carry ifMatch (the block rev from a read; a mismatch returns STALE_BLOCK with the fresh block). By default new content lands directly and changes to existing content become suggestions (stored in the file's suggestions root for a person to accept in the editor); [host.ai] default_mode = "direct" changes that. Deleting more than 5 blocks needs confirm: true. Member lists never carry e-mail addresses. Errors are tool results with isError: true and a code.

7b. Headless API v1 (HAPI, ADR-041; [host.flags] api_v1 = true)

The supported API for programs: bots, integrations, back-office jobs. It is described by an OpenAPI 3.1 document served at GET /api/v1/openapi.json (checked in as crates/oc-server/api/openapi.json; a contract test keeps it and the router identical). Turn it on per host with [host.flags] api_v1 = true (off by default in 0.2.0-alpha; otherwise every /api/v1 call answers 404 API_OFF). The path major changes only for breaking changes; within v1 changes are additive.

Auth, two kinds, one check (shared with MCP, §7a):

  1. Host key, server to server, as in §7: X-OpenCanvas-Host + X-OpenCanvas-Key (full access to your files, admin operations included). Optional X-OpenCanvas-Author: <userId> attributes changes to that user (edit origin api:<userId>; default svc:<hostId>); X-OpenCanvas-Callback-Token is passed on callbacks as in §7.
  2. User-scoped bearer token (Authorization: Bearer <jwt>) for code acting for one of your users. You mint it; OpenCanvas never issues user tokens. Same keys as launch tokens (HS256 secret, PEM or JWKS), same claims as MCP tokens:

| claim | value | |---|---| | iss | your host id, or [host.api] issuer (must be unique among hosts) | | aud | {[host.api] audience or OC_PUBLIC_URL}/api/v1. An MCP token (…/mcp/{hostId}) or a launch token is refused here, and an API token is refused by MCP | | sub | the user id (svc:<name> for a backend job) | | exp | at most 15 minutes ahead (nbf honoured) | | scope | space-separated canvas:read, canvas:comment, canvas:write (canvas:write:direct counts as write), canvas:admin | | role, files | as for MCP: the role on the listed files when you do not implement POST /access | | name | optional display name |

Without a public base URL (OC_PUBLIC_URL or [host.api] audience) user tokens are off for the host (401 TOKEN_INVALID); the audience is never taken from the request. The effective permission is min(scope, role), the role coming from your POST /access callback when you implement it (cached 30 s, dropped by the role API), else from the token's role claim, but only for the files in its files claim (403 FILES_REQUIRED otherwise, unless [host.api] all_files = true). Writes re-check revocation: after POST …/role {"role":"none"} the user's next call is refused. canvas:admin only works when [host.api] token_admin = true; by default the admin operations are the host key's. Errors: 401 UNAUTHENTICATED (no credentials), 401 TOKEN_INVALID (signature, issuer, audience, lifetime over 15 min, not yet valid), 401 TOKEN_EXPIRED, 403 SCOPE_REQUIRED (the operation needs a scope the token lacks), 403 ROLE_FORBIDDEN (the host role is lower, or the file is not in files). The OpenAPI document marks each operation's scope (x-opencanvas-scope).

[host.api]
issuer       = "acme"                        # default: the host id
audience     = "https://canvas.example.com"  # default: OC_PUBLIC_URL
default_mode = "direct"                      # or "suggest" for changes to existing blocks
all_files    = false                         # true: without /access, a token with no `files` covers every file
token_admin  = false                         # true: tokens with canvas:admin may commit, set roles, close sessions

Writes land in the live room as one Yjs transaction, broadcast to editors and autosaved to you like any edit (open the file with POST …/commit when you need it saved now). Changes to existing blocks land directly unless the call sends "mode": "suggest" or the host sets [host.api] default_mode = "suggest". Deleting more than 5 blocks needs "confirm": true.

Idempotency. Every POST /api/v1/files/… accepts Idempotency-Key: <1-255 visible ASCII>. The key is yours per user (host key + X-OpenCanvas-Author, or the token's sub). A repeat of the same request answers the stored result with Idempotency-Replayed: true for 24 h; the same key with another body is 422 IDEMPOTENCY_KEY_REUSED; a duplicate that arrives while the first still runs, on any node, is 409 IDEMPOTENCY_IN_PROGRESS with Retry-After: 1. Failed requests are not stored, so a retry runs again. Keys live in the database (api_idempotency) or, in Redis-only mode, in Redis (oc:idem:…), with request hashes and write answers (ids, counts, revisions) only, never document content. POST /api/v1/convert returns a document and takes no key (it changes nothing).

Errors are RFC 9457 application/problem+json: {"type":"urn:opencanvas:problem:stale-block","title":"Precondition Failed","status":412,"detail":"…","code":"STALE_BLOCK","fresh":{…}}. The code is the same machine code the 0.1 routes use (BLOCK_NOT_FOUND, STALE_BLOCK, ROLE_FORBIDDEN, PATCH_INVALID, DOC_TOO_LARGE, CONFLICT, CONFIRMATION_REQUIRED, …). Statuses: 400 bad input, 401 no or wrong credentials, 403 role or scope, 404 unknown file part, operation or API_OFF, 409 conflict or confirmation, 412 a stale ifMatch / If-Match (with fresh), 413 too large, 503 retry (Retry-After).

The 0.1 routes (/v1/files/{id}/patch|commit|role|import|session|members/invalidate, /v1/convert) keep working unchanged through 0.x, with or without api_v1, and keep their {"error":{"code","message"}} shape. They now carry Deprecation: @1795478400 (RFC 9745, 2026-11-24) and Link: </api/v1/…>; rel="successor-version"; they are retired in v0.3.

8. Lifecycle & guarantees

  • One live room per (host, file). Users who open the same file join the same room — there is no fork. The room loads your file once.
  • Your file is updated by commits only. Autosave commits are flagged X-OpenCanvas-Autosave: 1 so you can collapse them in version history.
  • At-least-once commit with idempotency key; final commit before room close; on graceful shutdown all dirty rooms commit.
  • Nothing is retained after the room closes and TTL passes.
  • Role changes you make during a session take effect only when you call the role API or the token expires — tokens are the contract.

8a. Ephemeral storage (no file storage of your own; ADR-043)

For hosts with nowhere to keep files, such as a meeting app:

[[host]]
id = "meet"
name = "Meeting"
jwt_secret = "env:MEET_JWT_SECRET"
api_key = "env:MEET_API_KEY"
storage = "ephemeral"          # default "host"
# template = "meeting"        # optional: a built-in template id, or a path to an .ocanvas or Markdown file
                               # unset: every canvas starts blank
# callback_base = "https://meet.example/api/opencanvas"   # optional: mentions and members only
  • No load and no save. The room starts blank, or from template, applied once by the server (people joining together never get it twice); no GET/PUT /files/{id}, no commit outbox. The editor gets session.storage = "ephemeral" and the save status {"t": "temporary"}. The editor shows "Not saved · temporary", skips the template picker and shows no host name. The commit API answers clean.
  • template ids: the 40 built-in templates (meeting, standup, retro, oneonone, brainstorm, allhands, …). An unknown id stops the server at startup and lists the valid ones.
  • Destroyed when the room closes: the last person leaves and OC_ROOM_IDLE_MS passes, or you call DELETE /v1/files/{fileId}/session. The server then deletes the WAL, snapshots, outbox and notification rows, sessions, uploads, the epoch row and the Redis keys of the room. Nothing is kept. Tickets stop working.
  • DELETE /v1/files/{fileId}/session closes the room at once: clients get {"t": "closed", "reason": "This canvas ended with the meeting"} and close 1000. Call it when the meeting ends.
  • A restart or deploy keeps it. A draining node tells clients to reconnect and leaves the canvas in storage; it reopens as it was.
  • A short reconnect inside the idle grace (a dropped network, a page reload) finds the canvas as it was. After the grace, launching the same fileId starts a new canvas.
  • Uploads are kept with the room (as in WOPI mode) and destroyed with it.
  • Export and download stay available, subject to export_formats and the token's perms.
  • Mentions and the members callback are used only when callback_base is set.
  • Wording ([host.flags] temporary_wording, ADR-049). "meeting" (default) says the canvas is deleted when the meeting ends and, at the end, "This canvas ended with the meeting". "room" is for a chat room that outlives each canvas: "This canvas isn't saved anywhere. It's deleted after everyone has closed it; download a copy to keep it.", the pill tooltip "Not saved anywhere. Deleted after everyone closes it.", the ended screen "This canvas ended when everyone left" with a Start a new canvas button (posts UI_StartNew; your page opens a fresh canvas), "You're no longer in this room, so this canvas is closed" when access is removed, and "You can view this canvas. Room moderators can edit." for viewers. The session answer carries "wording". Other values stop the server at start-up.

Your users must export to keep anything. Tell them so in your UI.

8b. Matrix rooms (Element widget)

integrations/matrix/ adds a canvas to Matrix rooms as a room widget, like Etherpad or Jitsi widgets. A small bridge (Node 24, no dependencies) is the host:

  • The widget asks the Matrix client for an OpenID token (get_openid), and the bridge verifies it with the user's homeserver (/_matrix/federation/v1/openid/userinfo). The homeserver is resolved by the Matrix server-name rules, and any private address is refused. URL template variables such as $matrix_user_id are never trusted.
  • A bot account checks that the user is joined to the room and that the widget points at the bridge. Power level ≥ state_default gives edit; everyone else gets a configurable role.
  • It mints a launch token (§3) for an ephemeral host (§8a): one canvas per widget. The canvas id is a hash of the room and widget ids. The user id is the Matrix id; the name is the room display name.
  • When someone leaves or is banned, the bot calls the role API (§7, role: "none").
  • The host sets frame_ancestors to the Matrix client origins (§4) and [host.flags] temporary_wording = "room" (§8a); the widget page reloads itself on UI_StartNew.

Verified in Element Web against Synapse: OpenID, membership, a non-member refused, two people co-editing, Matrix names, access closed on leave. Install, configuration and limits (not end-to-end encrypted, temporary only): integrations/matrix/README.md.

8c. Mattermost (plugin as the host)

integrations/mattermost/ is a Mattermost plugin (com.casualoffice.opencanvas) that is a full JWT-mode host: canvases live in channels (/canvas new, /canvas notes, a card in the channel, the editor in the right-hand panel), files go to Mattermost's file store, access follows channel membership, and leaving a channel calls the role API with none. Install and settings: integrations/mattermost/README.md.

[[host]]
id              = "mattermost"
name            = "Mattermost"
mode            = "jwt"
jwt_alg         = "HS256"
jwt_secret      = "env:MM_OC_SECRET"
api_key         = "env:MM_OC_API_KEY"
callback_base   = "https://chat.acme.example/plugins/com.casualoffice.opencanvas/oc"
allowed_origins = ["https://chat.acme.example"]

What a plugin host must know about Mattermost:

  • ServeHTTP receives the path without {subpath}/plugins/{id}, but v2 signs the full path: the plugin puts the prefix back before checking.
  • Mattermost removes Authorization before a plugin sees the request: read the callback token from X-OpenCanvas-Callback-Token (§5).
  • Mattermost re-encodes the query string (keys sorted), so the members call arrives as ?limit=…&q=… although ?q=…&limit=… was signed: the plugin accepts the same pairs in any order.
  • Mattermost sends no frame-src, so the canvas frame needs no CSP change there.
  • The plugin puts "start": "page" in every launch token (§3): its create dialog already asked for the kind, so new canvases open on the page, not the template picker. Its panel listens for Error SESSION_CLOSED to offer Reopen.

Tested end to end against Mattermost 12.1.0 (README "Status").

9. Checklist for integrators

  • Register host, share secret/API key out of band.
  • Backend endpoint that signs the launch JWT after your ACL check.
  • Implement load / save (+ assets). People: give user.detail in the token; add members (≤ 500) and/or GET /files/{fileId}/members (docs/21); call the role API or members/invalidate when access changes.
  • Verify X-OpenCanvas-Signature on callbacks.
  • Add OpenCanvas origin to your CSP frame-src; add your origin to our allowed_origins.
  • Handle 409 (we save a copy or reload, per your policy). With copy, implement POST /files/{id}/copies; editors are told the new file's url and the session turns read-only. With reload, the session's unsaved changes are dropped and everyone reconnects onto your version.
  • Call the role API when ACLs change.
  • Try examples/sample-host end-to-end before going live (WOPI hosts: examples/wopi-host and scripts/e2e-wopi.sh).
