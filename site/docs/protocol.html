Protocol and build contract

Status: binding for the P1 build, 2026-11-21. If a builder needs to change anything here, they update this file and say so in their report.

1. Repository layout

Cargo.toml                 Rust workspace
crates/oc-model            .ocanvas zip read/write, Yjs doc helpers, markdown/html export
crates/oc-server           axum binary `opencanvas`: config, host connector, store, rooms, autosave, routes
migrations/sqlite|mysql    identical logical schema (docs/04 §5)
web/packages/ui            design tokens (tokens.css) + shared TS types (BlockEnv, OcUser, Role)
web/packages/editor        Vite + React app: shell, Tiptap editor, gallery, comments, mobile bar
web/packages/database      React database block (table / board / calendar / gallery, CSV)
web/packages/board         React whiteboard block
examples/sample-host       Node reference host (JWT signing + callbacks + file store)
examples/wopi-host         Node reference WOPI host (CheckFileInfo/GetFile/PutFile/PutRelative)

The server serves the built editor (web/packages/editor/dist) at /app/. OC_WEB_DIR overrides the path.

2. Launch flow

  1. Host page form-POSTs token=<JWT> to POST /v1/launch.
  2. Server verifies the JWT (docs/05 §3, HS256 via the host's jwt_secret), creates a session row, and answers 303 See Other → /app/#t=<ticket>. (The ticket goes in the fragment so it never appears in server logs or Referer headers.) GET /v1/launch?token= does the same, for hosts that use a plain iframe src.
  3. The SPA reads #t, calls GET /v1/sessions/<ticket> → 200:
    { "ticket":"01J…", "room":"r_7k…", "role":"edit",
  "user": {"id":"u_123","name":"Asha Rao","color":"#7a45f0","avatar":null},
  "file": {"id":"doc_8812","name":"Sprint 42 notes"},
  "host": {"id":"acme","name":"Acme"},
  "perms": {"export":true,"download":true,"comment":true,"print":true,"history":true,"restore":true,"commitMessage":true},
  "history": "full", "historySource": "host", "historyHostName": "Acme",
  "isNew": true,
  "ai": {"enabled":true,"modes":["edit","comment","answer"],"mcp":false},
  "import": {"formats":["md","html","csv"]},
  "blocks": [],
  "editor": {"profile":"full","allowProfileSwitch":false,"blocks":["core.text","…"],"quickInsert":[],
             "features":{"comments":true,"versionHistory":true,"ai":true,"diagramming":true,"templates":true,"import":true}},
  "wsUrl": "ws://localhost:8080/v1/collab" }
    (EDP-01) editor: the host's profile (docs/05 §2b), blocks the ids insertion surfaces may offer (core.* and SDK types; core.text always), quickInsert, and features after the aliases (ai and import are the host-level switches, server settings included; ai, import and perms above stay what this person may actually use). The editor filters every insertion surface through one function (editor/profile.ts); an absent editor (older server) means everything. Content of any type always loads and stays editable. (BSDK-01) blocks: the SDK block packages [host.blocks] enables, each {type, version, v, title, icon, description, content, attrs, data, export, migrations, entry, integrity} (docs/05 §2a; v is the data version the package writes, its SemVer major). (VH-01a): history full | link | none, historySource host | file (the list shown first), historyHostName, and in link mode historyUrl + historyPostMessage (docs/05 §5a). perms.history, perms.restore, perms.commitMessage are effective (the role included). ai (AI-02): enabled when [host.ai] enabled = true and the role is not view; modes are the run modes the server accepts for the role (edit: edit, comment, answer; comment: answer, comment; view: none); mcp mirrors [host.ai] mcp. The editor shows the assistant from this; ?ai=1 only turns it on when ai is absent (demo, dev). isNew is true when the host returned 404 / an empty file. The SPA then shows the template gallery. (docs/21 revision 2): user is {id, name, color, avatar, detail?}, never an e-mail. A GET lifts a role-API revoke for that viewer (a fresh token means access). 401 {"error":{"code":"TICKET_INVALID"}} when unknown or expired. (Implementation: isNew = the room's doc has no content and empty meta/databases/boards, so a second user joining after a template was picked gets false.) Launch failures answer 401 {"error":{"code":"TOKEN_INVALID"|"TOKEN_REUSED",…}}; jti is single-use per host (table launch_jti). The algorithm is pinned by the host entry (jwt_alg = HS256 with jwt_secret, or RS256/EdDSA with jwt_public_key PEM or jwt_jwks_url; JWKS is cached 10 min, the token's kid must match a key whose type fits jwt_alg, an unknown kid refetches at most every 30 s), aud must be opencanvas, iss the host id, exp at most 10 h ahead, nbf honoured, 30 s leeway. WOPI launch (docs/05 §6, added 2026-11-21): POST /v1/launch?WOPISrc=<urlencoded> with form access_token (+ access_token_ttl, ms since the epoch) for a host with mode = "wopi" | "both" whose wopi_allowlist admits the URL (else 403 WOPISRC_NOT_ALLOWED); CheckFileInfo decides role, user and perms (401 TOKEN_INVALID when it answers 4xx). Same 303. The ticket lives until access_token_ttl (10 h when absent). GET /hosting/discovery (XML) and GET /hosting/capabilities (JSON). A JWT for a mode = "wopi" host is refused. Open at a block (UX-02): a block form field (or ?block= query) on either launch adds &block=<id> to the fragment (/app/#t=<ticket>&block=<id>) when it matches [A-Za-z0-9_-]{1,64}; the editor scrolls to that block and flashes it.
  4. Tickets live for the launch token's exp. The WS must connect within 60 s of the first GET /v1/sessions, though reconnects with the same ticket are allowed until exp.

3. Collaboration WebSocket

GET /v1/collab/<room>?ticket=<ticket>[&caps=ext,live], upgraded to a WebSocket. This is compatible with the stock y-websocket WebsocketProvider(wsUrl, room, doc, { params: { ticket } }).

(BSDK-02) caps lists client capabilities, comma-separated. ext: the client keeps extBlock nodes (§4.2); the 0.2 editor always sends it. Editors before 0.2 bind the document with y-prosemirror against a schema without extBlock, and y-prosemirror deletes nodes its schema lacks. So an update from a connection without caps=ext that lowers the number of extBlocks is refused (auth frame this editor is out of date; reopen the canvas) and the socket is closed with 4426 "editor out of date: reopen the canvas" (0.1.x clients treat 4400-4499 as final and show their ended screen; reopening loads the current editor). Nothing else changes for such connections. Headless CRDT clients that delete SDK blocks must send caps=ext.

(LIVE-02, ADR-071) live: the client keeps liveBlock and blockRef nodes (§4.4); editors from 0.3 send caps=ext,live. The same rule: an update from a connection without caps=live that lowers the number of those nodes is refused and closed with 4426, so a 0.2 editor sharing the room loses nothing. Every update is also held to the live block rules: adding a reference needs [host.flags] live_blocks and the grant's perms.live; the document may not newly break the depth rule, the 50-reference limit or [host.live] snapshot (auth frame naming the rule). A live block room's ticket comes from POST /v1/live/session (§6); at most [host.live] max_open (≤ 8) of them are connected per parent session, the next upgrade answers 429 LIVE_LIMIT. In a live room the server stamps each awareness state of a derived session with from: {fileId, title} (the embedding canvas; a client's own from is dropped) and sends it only to viewers whose session comes from that same canvas; everyone else gets the state without from.

Binary frames, y-protocols encoding (lib0 varuint message type first):

typemeaning
0sync: 0 = step1, 1 = step2, 2 = update
1awareness update
2auth: the server sends [2, 0 (permission denied), varString reason] when a write is rejected
3query awareness (client → server; the server answers with all awareness states)
100OpenCanvas control: varString JSON, both directions

(Changed 2026-11-21 by the server build: auth is type 2 and query-awareness is 3, as in y-protocols / y-websocket and yrs. The earlier draft said 3 for auth.)

Server → client control JSON: {"t":"saving"}, {"t":"saved","at":<epoch ms>,"version":"18"}, {"t":"save_error","retryInMs":10000,"message":"…"}, {"t":"conflict","policy":"copy","fileId":"doc_9001","url":"…"} (room stays read-only; joiners get it as the save state), {"t":"conflict","policy":"reload"} (followed by closed and close code 1012: the client must drop its local Y.Doc and reconnect, the room now holds the host's version), {"t":"role","role":"view"} (also sent mid-session when the host changes the role), {"t":"closed","reason":"…"} (access revoked → close 1008; closed by the host → close 1000), {"t":"ping"} (heartbeat every OC_HEARTBEAT_MS, default 10 s, on every connection; clients treat 15 s without any frame as a lost connection, docs/06 §5; added 2026-11-21, UX-02), {"t":"restored","by","byName","from","name","at","restoreId"} (VH-01b: someone restored a version; the edit itself arrives as an ordinary update, docs/30 §5), {"t":"reconnect"} (always followed by close 1012: the client keeps its Y.Doc and reconnects; sent on graceful drain and, in cluster mode, when the room moved to another node). (Changed 2026-11-21 by the server hardening: conflict carries policy.) On connect the server sends sync step1 and the current awareness states. When the client's step1 arrives the server answers with step2, then {"t":"role",…} and the current save state (saved with the last known host version, or saving). Client → server control messages are accepted and ignored for now.

Server rules:

  • view role: sync step2 and update messages are dropped, and an auth frame is sent once.
  • comment role: an update is accepted only if it touches nothing but the comments root (applied to a scratch copy of the doc first; updates that create other roots or cannot fully integrate are refused). The auth frame is sent once per connection.
  • Awareness: the server rewrites the user field from the grant before fan-out ({"id","name","color","avatar","detail"?}), so nobody can spoof another person's name or colour. (docs/21 revision 2) Every recipient gets the same states: real names for everyone with access. Entries over 2 KB, or for a client id owned by another connection, are dropped.
  • An update that would push the encoded doc over OC_MAX_DOC_MB (20) is refused with an auth frame document size limit reached; while a conflict is being handled every write is refused.
  • Frames over OC_MAX_FRAME_KB (1024) close the socket with code 1009. More than 60 non-awareness frames/s (burst 120) closes it with 4429 "rate limit" (not 1008, which only means access revoked / session expired). Awareness frames (type 1) have their own bucket of 120/s (burst 240); excess awareness frames are dropped silently, never fatal. Clients should still batch (y-websocket awareness throttling, 50 ms update windows). (Changed 2026-11-21: was 1008 with awareness counted against the same bucket; fast typing tripped it.) When the ticket expires the server sends {"t":"closed","reason":"session expired"} and closes with 1008; on shutdown (SIGTERM drain) it commits dirty rooms, then sends {"t":"reconnect"} and closes with 1012. (Changed 2026-11-21 by CLU-01: was {"t":"closed","reason":"server shutting down"}.)
  • Cluster mode (ADR-006): the socket may land on any node. A node that does not own the room relays it to the owner over an internal WebSocket; the protocol above is unchanged, roles are enforced by the owner. If the owner dies the client gets reconnect + 1012 (or a dropped socket) and reconnects with the same ticket.
  • Room ids are r_ + 26 lowercase base32 chars of sha256(<hostId>:<fileId>).

3.1 AI control messages (AI-02, ADR-034; docs/24 §10)

Client → server (type 100 JSON); answers go only to the sending connection:

MessageWhoEffect
{"t":"ai-run","runId","prompt","selection"?,"selectionBlockIds"?,"mode"?,"confirm"?}edit: modes edit (default), comment, answer; comment: answer (default) and comment only; view: refusedStarts a run on the room owner node. runId is chosen by the client, [A-Za-z0-9_-]{1,64}, unique per room. selectionBlockIds (optional; one per selection line, or one for the whole selection) only places injection flags. confirm (boolean; default true in mode edit, ignored otherwise): the run stops after ai-plan and calls no tool (so writes nothing) until ai-approve
{"t":"ai-approve","runId"}the user who started the runLets a run waiting on its plan act ("Nothing changes until you run it"). Ignored for any other run, user or state. Without it the wait ends after 10 minutes: outcome cancelled, reason: "plan_timeout"; the run's time limit starts on approval
{"t":"ai-cancel","runId"}the user who started the runAborts the model call or the wait for approval; the current tool call finishes; outcome cancelled
{"t":"ai-undo","runId"}the user who started the runReverts every change made with origin ai:<runId> (once; in memory, lost if the room moves)

Server → client:

MessageWhen
{"t":"ai-plan","runId","plan":[{"n","text","kind"}],"awaitingApproval","flags"}After the plan call (modes comment and edit). plan is the steps in order, n from 1, kind one of create, update, suggest, read (a server-side classification of the step text; the panel marks suggest steps). awaitingApproval: true when the run waits for ai-approve. flags (always present, often empty): prompt-injection flags on the selection, see below
{"t":"ai-step","runId","step","tool","ok","error"?,"flags"?}After each tool call; error is a code (not_allowed, forbidden, bad_input, not_found, stale, confirmation_required, internal). flags when a read tool returned instruction-like content
{"t":"ai-done","runId","outcome","summary"?,"reason"?,"steps","writes","undoable","usage":{"input","output"},"flags"?}outcome: done, cancelled (reason: "plan_timeout" when approval never came), limit (reason: steps, time, tokens, writes, quota), error, refused (with reason), undone

Prompt-injection flags (docs/24 §9.1 T1). The server scans the content a run reads (the selection before the plan, then every read tool's result) with a deterministic heuristic for text addressed to the assistant: "ignore previous/your instructions", "disregard the above", "you are now", "send/email/post/forward this … to …", a line starting with a speaker label (assistant:, AI,, Claude:, system:), and system-prompt markers (system prompt, <|im_start|>, [INST], <<SYS>>, a stray </canvas_data>). Each hit is {"blockId": string|null, "kind": "instruction_in_content", "excerpt"} (the matched line, at most 120 characters; blockId null for a whole-page read or an unplaced selection line), at most 20 per message. ai-done.flags is every flag of the run. Detection never blocks the run and never changes what the model gets: the content is still sent as data inside <canvas_data> and tool results, and the system prompt still says it is never an instruction. The panel shows one note on the plan or answer card when flags exist. The excerpt goes only to the requesting connection; it is never logged or sent in audit events.

Other people see the agent only as an awareness entry (user.id = "ai:<runId>", name = "Assistant", agent: true, cursor.blockId at the last touched block) and its edits. A run is cancelled when its user's last connection leaves. Audit events go to the host as POST {callback_base}/ai/events through the notification outbox, signed like every callback: {runId, fileId, userId, agent, event, counts, at} with event one of run.started, tool.called, run.finished, run.cancelled, run.undone. No prompts, outputs or tool arguments are sent or logged.

  • textColor(color) mark: color ∈ gray red amber green blue purple pink (the tone tokens' --<tone>-fg, AA in light and dark). Anything else is ignored on parse and in exports. HTML <span data-color="blue">; exports: HTML inline color (light palette), DOCX run colour, Markdown plain text.

  • fileAttachment gains display (card | preview; absent = preview for PDFs, card otherwise) and height (inline preview height in CSS px, 240-1600; absent = 70 % of the viewport, at most 900). Exports never embed a viewer: HTML <p class="oc-file" data-display><a>name</a> <span class="oc-file-meta">PDF · 2 KB</span></p>, Markdown [name](url) (PDF, 2 KB), DOCX a link.
  • columns gains widths ("25,75": whole percents, one per column; absent = equal; 2-4 columns; the editor snaps boundaries to quarters). column gains title (a label line above its blocks; absent = none). HTML exports the grid and a bold title line; Markdown a bold line.

Block ids. Any block node may carry an optional string attribute blockId (convention b_ + 26 lowercase base32 chars, e.g. b_01jd…). It is how the host patch API (§6) addresses blocks; ids are unique within a document. Blocks the patch API inserts always get one (the caller's attrs.blockId is kept, else one is generated). The editor must declare blockId as a global attribute on block nodes (Tiptap addGlobalAttributes, default null, not rendered) and keep it when a node is edited; a split keeps it on the first half only and pasting/duplicating clears it. Without that, y-prosemirror drops the attribute the first time a user edits the block. (Added 2026-11-21 by the server API build.) (VH-00, 2026-11-24): an editable editor gives every block in BLOCK_ID_TYPES that has none an id: local edits in the same transaction (a split's second half, a new block), and documents loaded or changed from Yjs (older files, blocks an 0.1.x client inserts) in a follow-up transaction outside the undo history. A later copy of an id already used gets a fresh one (the first in document order keeps it); a paste drops only the ids still in the document, so cut and paste or a drag that moves a block keeps its id. Read-only editors and an empty, not yet loaded fragment are never written. Two editors that assign ids to the same block at once converge on one (a Yjs attribute is last-writer-wins). 0.1.x clients already declare the attribute, so they keep the ids. Shared fixture crates/oc-model/tests/fixtures/blockids.ydoc.bin (web blockId.test.ts, Rust tests/roundtrip.rs: Yjs → document.json → .ocanvas).

Diagram fields (ADR-045, accepted 2026-11-24; DGM-03/04/08/16): every key above is optional and additive. Readers keep keys they do not know; writers set only the keys they change (never rewrite a shape's map), and keep every field of a binding they re-point (copy/paste). A shape whose type is not one of the nine above is kept; both exporters draw it as a rect (with its text, label, fill) when it has a box (w > 0, h > 0, no pts) and draw nothing otherwise (shared fixture crates/oc-model/tests/fixtures/board-diagram.{json,web.svg}); the editor canvas does not draw it yet (placeholder UI awaits a prototype, ADR-011).

Text wrapping (UX pass): sticky, rect, ellipse and diamond text wraps greedily at whitespace to w − 28 (sticky, 14 px), max(20, w − 16) (rect), max(20, w × 0.72) (ellipse), max(20, w × 0.6) (diamond); connector labels to 180 px at 12.5 px. Every UTF-16 unit counts size × 0.56 px; longer words are cut. A sticky's stored h grows on commit to ceil(30 + (lines − 1) × 20 + 22) and never shrinks; exports apply the same rule. The web and Rust exporters implement this identically (shared fixture crates/oc-model/tests/fixtures/board.{json,web.svg}).

Board awareness (UX pass): board {x, y, sel}; sel lists the peer's selected shape ids, and board may carry only sel while the pointer is outside the board.

Database view prefs (databases/<id>/views Y.Map, JSON per view name table board calendar gallery; source web/packages/database/src/types.ts ViewPrefs): q search; cal calendar month YYYY-MM; filter {f, vals[]} / sort {f, dir: 1|-1} (single rule, kept for older clients). (UX pass): sorts [{f, dir}] applied in order, wins over sort (writers keep sort = first); filters [{f, vals}] ANDed, wins over filter (writers keep filter = first); widths {fieldId: px} table column widths; group field id the board view groups by (status/select); date field id the calendar places rows on; cover gallery cover: "none", "color" (default) or a URL field id. (Open items, ADR-025): fields field ids in this view's order (unknown ids ignored, fields missing from it follow in the shared order; column moves write this, never the shared fields array); hidden field ids hidden in this view (the title field is always shown). filters rules may be typed: {f, op, v?, v2?} with op per field type — text/title/url contains is empty (case-insensitive, on the cell's text); number/progress eq ne lt le gt ge between empty (v, v2 numbers; ne also matches empty cells; between is inclusive in either order); date is before after (v YYYY-MM-DD), next past (v days, inclusive of today), empty. Data newer than the installed package is kept untouched, read-only, and shown as its fallback under "Updated by a newer version".

7. Autosave

No manual save anywhere (ADR-012). A room saves when it is dirty and:

  • 2 s have passed since the last update (OC_AUTOSAVE_DEBOUNCE_MS), or
  • 10 s have passed since the first unsaved update (OC_AUTOSAVE_MAX_MS), or
  • the last client leaves, or the process gets SIGTERM.

Saves are serialized per room. Each commit (.ocanvas bytes, idempotency key, base version, sealed callback token) is written to commit_outbox as pending before the PUT; retries resend the same row. 200 marks it done (payload dropped), 409 conflict, a newer commit marks older pending rows superseded. A failure is retried with backoff (1 s, 2 s, 5 s, 10 s, …) and sends save_error. At startup (and every 60 s) a sweeper reopens every room with a pending row (from WAL, or from the outbox payload when there is no WAL) so the save continues after a restart.

A 409 stops autosave and applies the host's [host.flags] on_conflict (default copy): copy → POST /files/{id}/copies with the room's state, then conflict with fileId/url; the room is read-only and closes as soon as the last client leaves. reload → GET the host's file, replace the room's state with it, send conflict + closed, close every socket.

Every accepted update is appended to room_updates before fan-out. A room writes the updates that queued while its previous append ran as one batch (one row and seq per update, one epoch-guarded statement, all or nothing), then fans them out in order; on SQLite one writer task commits the batches of many rooms in one transaction (group commit, docs/22 §9.3). Every 500 updates or 30 s the WAL is compacted into room_snapshots. A room that was dirty when the process died is rebuilt from snapshot + WAL on the next join instead of reloading from the host. A clean room with no clients for OC_ROOM_TTL_SECS (600) closes and its rows are purged.

WOPI mode (docs/05 §6): the same outbox and autosave; HostClient sends the save to the WOPI host (PutFile with X-COOL-WOPI-Timestamp = the tracked LastModifiedTime; 409 + COOLStatusCode 1010 = conflict; policy copy = PUT_RELATIVE). The saved control's version is the host's LastModifiedTime. Assets of a WOPI room live in room_assets (migration 0003) and are inlined as assets/<id> + assets/index.json on every save; rows of rooms that are gone and have no pending commit are swept by the 60 s sweeper (10 min grace).

8. Secrets and limits

OC_KEK (base64 of 32 bytes) seals the host callback token (in WOPI mode: the access token) in sessions.grant_json and commit_outbox.token with AES-256-GCM (enc:v1:<base64(nonce‖ct)>, bound to the row id). The server refuses to start without it unless OC_DEV=1 (then tokens are stored in clear, with a warning). OC_MAX_DOC_MB (20) caps the encoded document; 60 frames/s (burst 120) per socket.

Convergence fuzz: cargo test -p oc-server --test fuzz runs OC_FUZZ_ITERS (200) random rooms; OC_FUZZ_ITERS=10000 cargo test --release -p oc-server --test fuzz -- --nocapture for the long run, OC_FUZZ_SEED=<n> OC_FUZZ_ITERS=1 to replay a failing seed.
