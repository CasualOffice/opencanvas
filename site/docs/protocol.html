Protocol and build contract

Status: binding for the P1 build, 2026-11-21. If a builder needs to change anything here, they update this file and say so in their report.

1. Repository layout

Cargo.toml                 Rust workspace
crates/oc-model            .ocanvas zip read/write, Yjs doc helpers, markdown/html export
crates/oc-server           axum binary `opencanvas`: config, host connector, store, rooms, autosave, routes
migrations/sqlite|mysql    identical logical schema (docs/04 §5)
web/packages/ui            design tokens (tokens.css) + shared TS types (BlockEnv, OcUser, Role)
web/packages/editor        Vite + React app: shell, Tiptap editor, gallery, comments, mobile bar
web/packages/database      React database block (table / board / calendar / gallery, CSV)
web/packages/board         React whiteboard block
examples/sample-host       Node reference host (JWT signing + callbacks + file store)
examples/wopi-host         Node reference WOPI host (CheckFileInfo/GetFile/PutFile/PutRelative)

The server serves the built editor (web/packages/editor/dist) at /app/. OC_WEB_DIR overrides the path.

2. Launch flow

  1. Host page form-POSTs token=<JWT> to POST /v1/launch.
  2. Server verifies the JWT (docs/05 §3, HS256 via the host's jwt_secret), creates a session row, and answers 303 See Other → /app/#t=<ticket>. (The ticket goes in the fragment so it never appears in server logs or Referer headers.) GET /v1/launch?token= does the same, for hosts that use a plain iframe src.
  3. The SPA reads #t, calls GET /v1/sessions/<ticket> → 200: json { "ticket":"01J…", "room":"r_7k…", "role":"edit", "user": {"id":"u_123","name":"Asha Rao","color":"#7a45f0","avatar":null}, "file": {"id":"doc_8812","name":"Sprint 42 notes"}, "host": {"id":"acme","name":"Acme"}, "perms": {"export":true,"download":true,"comment":true,"print":true}, "isNew": true, "wsUrl": "ws://localhost:8080/v1/collab" } isNew is true when the host returned 404 / an empty file. The SPA then shows the template gallery. 401 {"error":{"code":"TICKET_INVALID"}} when unknown or expired. (Implementation: isNew = the room's doc has no content and empty meta/databases/boards, so a second user joining after a template was picked gets false.) Launch failures answer 401 {"error":{"code":"TOKEN_INVALID"|"TOKEN_REUSED",…}}; jti is single-use per host (table launch_jti). The algorithm is pinned by the host entry (jwt_alg = HS256 with jwt_secret, or RS256/EdDSA with jwt_public_key PEM or jwt_jwks_url; JWKS is cached 10 min, the token's kid must match a key whose type fits jwt_alg, an unknown kid refetches at most every 30 s), aud must be opencanvas, iss the host id, exp at most 10 h ahead, nbf honoured, 30 s leeway. WOPI launch (docs/05 §6, added 2026-11-21): POST /v1/launch?WOPISrc=<urlencoded> with form access_token (+ access_token_ttl, ms since the epoch) for a host with mode = "wopi" | "both" whose wopi_allowlist admits the URL (else 403 WOPISRC_NOT_ALLOWED); CheckFileInfo decides role, user and perms (401 TOKEN_INVALID when it answers 4xx). Same 303. The ticket lives until access_token_ttl (10 h when absent). GET /hosting/discovery (XML) and GET /hosting/capabilities (JSON). A JWT for a mode = "wopi" host is refused.
  4. Tickets live for the launch token's exp. The WS must connect within 60 s of the first GET /v1/sessions, though reconnects with the same ticket are allowed until exp.

3. Collaboration WebSocket

GET /v1/collab/<room>?ticket=<ticket>, upgraded to a WebSocket. This is compatible with the stock y-websocket WebsocketProvider(wsUrl, room, doc, { params: { ticket } }).

Binary frames, y-protocols encoding (lib0 varuint message type first):

typemeaning
0sync: 0 = step1, 1 = step2, 2 = update
1awareness update
2auth: the server sends [2, 0 (permission denied), varString reason] when a write is rejected
3query awareness (client → server; the server answers with all awareness states)
100OpenCanvas control: varString JSON, both directions

(Changed 2026-11-21 by the server build: auth is type 2 and query-awareness is 3, as in y-protocols / y-websocket and yrs. The earlier draft said 3 for auth.)

Server → client control JSON: {"t":"saving"}, {"t":"saved","at":<epoch ms>,"version":"18"}, {"t":"save_error","retryInMs":10000,"message":"…"}, {"t":"conflict","policy":"copy","fileId":"doc_9001","url":"…"} (room stays read-only; joiners get it as the save state), {"t":"conflict","policy":"reload"} (followed by closed and close code 1012: the client must drop its local Y.Doc and reconnect, the room now holds the host's version), {"t":"role","role":"view"} (also sent mid-session when the host changes the role), {"t":"closed","reason":"…"} (access revoked → close 1008; closed by the host → close 1000), {"t":"reconnect"} (always followed by close 1012: the client keeps its Y.Doc and reconnects; sent on graceful drain and, in cluster mode, when the room moved to another node). (Changed 2026-11-21 by the server hardening: conflict carries policy.) On connect the server sends sync step1 and the current awareness states. When the client's step1 arrives the server answers with step2, then {"t":"role",…} and the current save state (saved with the last known host version, or saving). Client → server control messages are accepted and ignored for now.

Server rules:

  • view role: sync step2 and update messages are dropped, and an auth frame is sent once.
  • comment role: an update is accepted only if it touches nothing but the comments root (applied to a scratch copy of the doc first; updates that create other roots or cannot fully integrate are refused). The auth frame is sent once per connection.
  • Awareness: the server rewrites the user field from the grant before fan-out ({"id","name","color","avatar"}), so nobody can spoof another person's name or colour. Entries over 2 KB, or for a client id owned by another connection, are dropped.
  • An update that would push the encoded doc over OC_MAX_DOC_MB (20) is refused with an auth frame document size limit reached; while a conflict is being handled every write is refused.
  • Frames over OC_MAX_FRAME_KB (1024) close the socket with code 1009. More than 60 non-awareness frames/s (burst 120) closes it with 4429 "rate limit" (not 1008, which only means access revoked / session expired). Awareness frames (type 1) have their own bucket of 120/s (burst 240); excess awareness frames are dropped silently, never fatal. Clients should still batch (y-websocket awareness throttling, 50 ms update windows). (Changed 2026-11-21: was 1008 with awareness counted against the same bucket; fast typing tripped it.) When the ticket expires the server sends {"t":"closed","reason":"session expired"} and closes with 1008; on shutdown (SIGTERM drain) it commits dirty rooms, then sends {"t":"reconnect"} and closes with 1012. (Changed 2026-11-21 by CLU-01: was {"t":"closed","reason":"server shutting down"}.)
  • Cluster mode (ADR-006): the socket may land on any node. A node that does not own the room relays it to the owner over an internal WebSocket; the protocol above is unchanged, roles are enforced by the owner. If the owner dies the client gets reconnect + 1012 (or a dropped socket) and reconnects with the same ticket.
  • Room ids are r_ + 26 lowercase base32 chars of sha256(<hostId>:<fileId>).

4. Y.Doc layout (shared by server export and web)

roottypecontents
contentXmlFragmentTiptap/ProseMirror document (Collaboration extension, field: "content")
metaMaptitle string, icon lucide name, tone Tone, template id
databasesMap<dbId, Y.Map>per database: name, icon, tone, fields Y.Array<Y.Map{id,name,type,options(JSON array)}>, order Y.Array<rowId>, rows Y.Map<rowId, Y.Map<fieldId,value>>, notes Y.Map<rowId,string>, view string, views Y.Map (per-view prefs JSON)
boardsMap<boardId, Y.Map>shapes Y.Map<shapeId, Y.Map>, order Y.Array<shapeId>
commentsMap<threadId, Y.Map>quote, resolved, messages Y.Array<Y.Map{user,text,at}>

Tiptap node types (names are part of the file format, so don't rename them): paragraph, heading(level 1-3), bulletList, orderedList, listItem, taskList, taskItem(checked), blockquote, codeBlock(language), horizontalRule, image(src,alt,caption), callout(tone,icon), toggle(open) > toggleSummary + toggleContent, database(dbId), board(boardId), bookmark(url,title,description,site), embed(provider,url,title), fileAttachment(name,size,url,mime), columns > column, table/tableRow/tableHeader/tableCell, mention(id,label) inline, commentMark(threadId) mark.

Block ids. Any block node may carry an optional string attribute blockId (convention b_ + 26 lowercase base32 chars, e.g. b_01jd…). It is how the host patch API (§6) addresses blocks; ids are unique within a document. Blocks the patch API inserts always get one (the caller's attrs.blockId is kept, else one is generated). The editor must declare blockId as a global attribute on block nodes (Tiptap addGlobalAttributes, default null, not rendered) and keep it when a node is edited; a split keeps it on the first half only and pasting/duplicating clears it. Without that, y-prosemirror drops the attribute the first time a user edits the block. (Added 2026-11-21 by the server API build; the web part is still to do.)

Field types for databases: title text status select tags person date number checkbox url progress. Option objects: { "v": "In progress", "c": "blue" }. Date values: YYYY-MM-DD. Person values: user id.

.ocanvas as written by the server: manifest.json (format, version 1, schemaVersion 1, createdWith, title from meta.title, commit {id, authors, at}), document.json and ydoc.bin. ydoc.bin is a Yjs v1 update (Y.encodeStateAsUpdate(doc)); readers also accept v2. document.json is {type:"doc", content:[…], meta, databases, boards, comments} where content nodes are {type, attrs?, content?} and text is {type:"text", text, marks?:[{type, attrs?}]} (y-prosemirror mark--hash keys are reduced to mark). If ydoc.bin is missing the doc is built from document.json (content and meta exactly; nested maps best-effort).

5. Host callbacks (JWT mode). The server calls the host.

Base callback_base from the host registry. Headers on every call: Authorization: Bearer <callbackToken from JWT>, X-OpenCanvas-Signature: t=<unix>,v1=<hex HMAC-SHA256(jwt_secret, "<t>.<body>")>.

CallNotes
GET /files/{fileId}200 bytes (.ocanvas zip, or text/markdown), ETag; 404 = new file
PUT /files/{fileId}body .ocanvas; If-Match, Idempotency-Key, X-OpenCanvas-Autosave: 1, X-OpenCanvas-Authors: <json ids>; 200 {"version":"…"}, 409 conflict
POST /files/{fileId}/assetsmultipart file → 201 {"assetId","url","mime","size"}
GET /users?q=&fileId=[{"id","name","avatar"}]
POST /files/{fileId}/copiesconflict policy copy: body .ocanvas, Idempotency-Key; 200/201 {"fileId","url"}

The HMAC key is the host's callback_secret if set, else jwt_secret. If-Match is the quoted version from the last load/save (ETag of GET, else the JWT file.version). The PUT carries Content-Type: application/vnd.opencanvas+zip; 412 is treated like 409. For uploads the multipart body is forwarded byte for byte and the signature covers those bytes. OC_CALLBACK_BASE_OVERRIDE, when set, replaces every host's callback_base (dev/compose only; logged as a warning).

6. Server REST used by the SPA

GET /v1/sessions/:ticket · POST /v1/assets?ticket= (multipart, proxied to host; WOPI mode: stored with the room, 201 {"assetId","url":"/v1/assets/<id>","mime","size"}, ≤ 10 MB each, ≤ 50 MB per file) · GET /v1/assets/:id?ticket= (WOPI mode only, else 404) · GET /v1/users?ticket=&q= (proxied) · GET /v1/export/:fmt?ticket= with fmt = md|html|ocanvas|json|docx|pdf · GET /v1/export/board/:boardId.svg|png?ticket= · GET /healthz · GET /readyz · GET /metrics.

Host → server (docs/05 §7), headers X-OpenCanvas-Host: <id> + X-OpenCanvas-Key: <api_key> (api_key in the host entry; 401 API_KEY_INVALID otherwise): POST /v1/files/:fileId/role {"userId","role":"view|comment|edit|none"} → {"connections","sessions"}; DELETE /v1/files/:fileId/session → final save, close all, drop tickets → {"closed","sessions"}; POST /v1/files/:fileId/patch → {"applied","blockIds","live"} (+ version when no room was live); POST /v1/files/:fileId/commit → 200 {"live","saved","version"} / 202 {"queued":true} / 409 CONFLICT; POST /v1/convert?from=md|html|ocanvas&to=ocanvas|md|html|json|docx|pdf (raw body in, file out). Optional X-OpenCanvas-Callback-Token: the bearer used for callbacks made for that request (loading / saving a file with no live room, fetching images); without it the bearer is empty and the host authenticates the call by the HMAC signature. Details in docs/04 §6 and docs/05 §7.

DOCX (export/docx, convert to=docx): minimal WordprocessingML written with zip (no new crate). Headings, marks, links (http/https/mailto only), bullet/numbered/task lists, quotes, code, tables, callouts (shaded paragraphs), databases (caption + table), boards (a PNG rendered at 2×, shown at 1×, caption "Whiteboard", alt text = the board's texts; a text note only if rendering fails), bookmarks/embeds/files (links). Images that were not fetched (see Images in exports) become links.

Boards (oc_model::board, changed 2026-11-21): to_svg(doc, boardId) is a port of the web exportBoardSvg (light palette, fitted to content + 32 px, stickies, rect/frame, ellipse, diamond, swatch, text, pen, arrows incl. bound ends and elbow routes, images as <image href>); a parity test compares it byte for byte with the web output. to_png(svg, scale) renders with resvg and the embedded Geist Regular/SemiBold (OFL), no system fonts; only inline data: images are drawn (remote URLs and file paths are never read); ≤ 16384 px a side, ≤ 64 Mpx. Exports: HTML inlines the board SVG (<figure class="board">); Markdown keeps the note and, for ticketed exports, adds [Whiteboard (SVG)](<OC_PUBLIC_URL>/v1/export/board/<id>.svg?ticket=<ticket>) (the link carries the session ticket and stops working when it expires); GET /v1/export/board/:boardId.svg (image URLs kept) / .png (allowed images inlined) need perms.export; unknown board 404 BOARD_NOT_FOUND.

PDF (ADR-010): OC_PDF_RENDERER=gotenberg:<url> → the print HTML is posted to Gotenberg's /forms/chromium/convert/html (A4, 0.6" margins, backgrounds) and the PDF is streamed back (502 PDF_RENDERER_FAILED if it fails). The print HTML is self-contained: allowed images and board images inlined as data: URLs, other images are links, CSP default-src 'none'; img-src data: so the renderer fetches nothing. Unset → 501 {"error":{"code":"PDF_RENDERER_NOT_CONFIGURED"}} (the editor uses its print stylesheet instead).

Images in exports (DOCX, board PNG, PDF): fetched only from allowed origins — the host's callback_base origin (relative /… resolves there; signed + callback token), the original callback_base origin while OC_CALLBACK_BASE_OVERRIDE is active (fetched through the override, signed), and the host's asset_origins = ["https://cdn…"] (plain GET, no signature or token). No redirects, ≤ 10 MB, Content-Type: image/* required, ≤ 50 per export; anything else is skipped.

perms.print (added 2026-11-21 with WOPI mode; JWT perms.print, WOPI DisablePrint, default true) is additionally required for pdf. ocanvas export needs perms.download, the others perms.export (403 otherwise); unknown formats answer 404 FORMAT_UNSUPPORTED. Exports carry Content-Disposition: attachment; filename="<file name>.<ext>". POST /v1/assets needs the edit role and multipart/form-data (≤ 25 MB); the host's status and body are passed through. Every response carries Content-Security-Policy: frame-ancestors 'self' <all hosts' allowed_origins> and Referrer-Policy: no-referrer.

7. Autosave

No manual save anywhere (ADR-012). A room saves when it is dirty and:

  • 2 s have passed since the last update (OC_AUTOSAVE_DEBOUNCE_MS), or
  • 10 s have passed since the first unsaved update (OC_AUTOSAVE_MAX_MS), or
  • the last client leaves, or the process gets SIGTERM.

Saves are serialized per room. Each commit (.ocanvas bytes, idempotency key, base version, sealed callback token) is written to commit_outbox as pending before the PUT; retries resend the same row. 200 marks it done (payload dropped), 409 conflict, a newer commit marks older pending rows superseded. A failure is retried with backoff (1 s, 2 s, 5 s, 10 s, …) and sends save_error. At startup (and every 60 s) a sweeper reopens every room with a pending row (from WAL, or from the outbox payload when there is no WAL) so the save continues after a restart.

A 409 stops autosave and applies the host's [host.flags] on_conflict (default copy): copy → POST /files/{id}/copies with the room's state, then conflict with fileId/url; the room is read-only and closes as soon as the last client leaves. reload → GET the host's file, replace the room's state with it, send conflict + closed, close every socket.

Every accepted update is appended to room_updates before fan-out; every 500 updates or 30 s the WAL is compacted into room_snapshots. A room that was dirty when the process died is rebuilt from snapshot + WAL on the next join instead of reloading from the host. A clean room with no clients for OC_ROOM_TTL_SECS (600) closes and its rows are purged.

WOPI mode (docs/05 §6): the same outbox and autosave; HostClient sends the save to the WOPI host (PutFile with X-COOL-WOPI-Timestamp = the tracked LastModifiedTime; 409 + COOLStatusCode 1010 = conflict; policy copy = PUT_RELATIVE). The saved control's version is the host's LastModifiedTime. Assets of a WOPI room live in room_assets (migration 0003) and are inlined as assets/<id> + assets/index.json on every save; rows of rooms that are gone and have no pending commit are swept by the 60 s sweeper (10 min grace).

8. Secrets and limits

OC_KEK (base64 of 32 bytes) seals the host callback token (in WOPI mode: the access token) in sessions.grant_json and commit_outbox.token with AES-256-GCM (enc:v1:<base64(nonce‖ct)>, bound to the row id). The server refuses to start without it unless OC_DEV=1 (then tokens are stored in clear, with a warning). OC_MAX_DOC_MB (20) caps the encoded document; 60 frames/s (burst 120) per socket.

Convergence fuzz: cargo test -p oc-server --test fuzz runs OC_FUZZ_ITERS (200) random rooms; OC_FUZZ_ITERS=10000 cargo test --release -p oc-server --test fuzz -- --nocapture for the long run, OC_FUZZ_SEED=<n> OC_FUZZ_ITERS=1 to replay a failing seed.
