Getting started

The server, the editor and the sample host on your machine, from the project's README. To look around first, open the demo: it runs in your browser with no server.

**On main, not yet released:** integrations for Nextcloud (a WOPI app: files, versions and shares stay in Nextcloud), Mattermost (a plugin: canvases in channels) and Element / Matrix (a room widget), each tested end to end in the real host; the groundwork for structured diagramming (docs/29): faster large boards, ports, connectors that route around shapes; and a UI that follows the reader's text size (rem units, ADR-050). See the execution tracker for what is done and what is left.

v0.1.1: Jitsi Meet integration. Every Jitsi meeting can get a shared, temporary canvas with one Prosody plugin and config (guide, changes). Best-effort support with no SLA. Before you deploy, read the 0.1.x release notes, its upgrade notes (WOPI proof keys are now required) and known limitations (memory, durability modes, single node first) before you deploy it. The AI assistant and MCP endpoint are experimental and off by default.

Goal

Give any product a shared workspace page (notes, plans, task databases, whiteboards) without handing over its users or its data. OpenCanvas is built for integration: a host application embeds it in an iframe, signs a short launch token saying who opens which file with which role, and receives the saved file back through its own storage. It aims to be:

  • Yours to control. The host owns authentication, ACL, users and files. OpenCanvas never becomes the system of record; it keeps only a transient room log and a save outbox.
  • Live. Edits merge in real time with a CRDT (Yjs), with cursors, presence, comments and follow mode, and the roles are enforced on the server.
  • Light to run. One container with SQLite to start; MySQL, MariaDB and Redis when you need a cluster. See the measured capacity and sizing.
  • Usable. A considered editor on desktop and phone, accessible to WCAG 2.2 AA, with autosave only.

How it fits

Your app  ── signs launch token (who, which file, which role) ──▶ OpenCanvas iframe
          ◀── load / save / assets / members / copies callbacks ──  OpenCanvas server
  • You own authentication, users, ACL, files, versions and retention.
  • OpenCanvas owns the editor, real-time merge (Yjs CRDT), presence and cursors, preview, export, and autosave back to your storage.
  • OpenCanvas keeps nothing once a session is saved and idle. Its database only holds the transient room log and the save outbox.

Run it

You need Rust (stable), Node 24 and pnpm 9.

cd web && pnpm install && pnpm --filter @opencanvas/editor build && cd ..
OC_DEV=1 cargo run --release -p oc-server     # http://localhost:8080
node examples/sample-host/server.mjs          # http://localhost:4000

Open http://localhost:4000 and open a file. In a second tab, pick another user under "Signed in as" and open the same file to see live collaboration. Use the "Access control" column to change roles while people are editing.

To review the UI without a backend, use the editor in demo mode: run pnpm --filter @opencanvas/editor dev and open http://localhost:5173/app/#demo.

docker compose up --build runs both services. OC_DEV=1 allows starting without OC_KEK. In production, set OC_KEK (32 bytes, base64) and the other variables listed in docs/13.

Embed it

<script type="module" src="https://canvas.example.com/sdk/embed.js"></script>
<open-canvas server="https://canvas.example.com" token="{{ launch_jwt }}" style="height:100vh"></open-canvas>

The host contract (token claims, callbacks, postMessage events and REST) is in docs/05. docs/15 has the exact wire formats.

Other ways in:

  • WOPI: open it from an existing WOPI host such as Nextcloud (docs/05 §6).
  • Jitsi Meet: add integrations/jitsi/mod_opencanvas.lua to Prosody and a few .env lines; everyone in a meeting gets the same temporary canvas under Shared document (guide).
  • No file storage of your own: storage = "ephemeral" gives temporary canvases that are deleted when the session ends (docs/05 §8a).

Assistant and MCP (experimental)

Experimental and off by default. AI runs only in the OpenCanvas server and stays off until the operator turns it on (OC_AI_CONFIG with [ai] enabled = true, then [host.ai] per host). One server switch governs everything: with it off (the default, or OC_AI=off) there is no assistant, no MCP endpoint and no model call for any host. Its interfaces may change in any release. Select text, press ⌘J (Ctrl+J) and ask: the assistant shows a plan, waits for you to run it, builds in place with its own cursor, turns changes to existing text into suggestions you accept or reject, and can undo the whole run. It acts only within your role. External agents use the MCP endpoint, POST /mcp/{hostId}, with tokens your app issues.

Canvas content is sent to the model server you configure. Agent mode needs a model with tool calling; others get answer mode only. Try a scripted run in the demo (#demo, no AI server). Details: docs/24; configuration: docs/13.

# OC_AI_CONFIG=/etc/opencanvas/ai.toml
[ai]
enabled = true

[ai.providers.claude]                 # Claude Platform
kind        = "anthropic"
api_key_env = "OC_AI_ANTHROPIC_KEY"
model_agent = "claude-opus-5-5"
model_fast  = "claude-sonnet-5-5"

[ai.providers.ollama]                 # or vLLM, llama.cpp: any OpenAI-compatible server
kind        = "openai-compatible"
base_url    = "http://ollama:11434"
model_agent = "qwen3:14b"
# hosts.toml, per host
[host.ai]
enabled      = true
provider     = "claude"
default_mode = "suggest"              # changes to existing text arrive as suggestions
mcp          = true                   # POST /mcp/{hostId}; off by default

Configure

The essentials; the full list is in docs/13.

VariableWhat it does
OC_PUBLIC_URLThe server's public URL (also the MCP token audience; set it in production)
OC_KEK32-byte base64 key that seals secrets at rest (required unless OC_DEV=1)
OC_HOSTS_FILEThe hosts you trust: JWT keys, callback URL, allowed origins and per-host flags
DATABASE_URLUnset: SQLite. mysql://… for MySQL or MariaDB
REDIS_URLEnables cluster mode (room leases, relay, hot edit log)
OC_DURABILITYmemory (default without Redis) or wal (every edit written)
OC_AI_CONFIG / OC_AIAI is off unless configured; OC_AI=off turns it off for every host
OC_IMPORToff disables Markdown, HTML and CSV import for every host

Per host, in the hosts file: export_formats, import_formats (off by default), on_conflict (copy or reload) and [host.ai].

Security and privacy

  • Launch tokens are verified (HS256, RS256, EdDSA, JWKS) and single use; callbacks to the host are signed. Roles (view, comment, edit) are enforced on the server for every edit.
  • Exported and imported HTML is sanitised; embeds come from an allow-list and run sandboxed.
  • The release audit for v0.1.0-alpha.1 is in docs/18; report issues as described in SECURITY.md.
  • With AI turned on, the parts of a canvas the assistant needs are sent to the model server the operator configures. Nothing is sent when AI is off.

Alongside the releases, structured diagramming is its own workstream (docs/29): diagram mode on a board, shape libraries, ports, connectors that route around shapes, auto-layout, generic icons plus your own, and draw.io, Excalidraw and Mermaid import. It ships when each part is ready and does not move the release commitments above.

OpenCanvas integrates with any application through standardized APIs and SDKs and depends on no specific CasualOffice product. Priorities and detail: docs/09 and the roadmap page.
