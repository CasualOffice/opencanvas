Getting started

The server, the editor and the sample host on your machine, from the project's README. To look around first, open the demo: it runs in your browser with no server.

OpenCanvas Workspace: ready to use in one command

Don't have an app to embed it in? OpenCanvas Workspace is the complete self-hosted workspace around the engine: accounts, files, sharing and search, in one container on one port.

docker run -p 8080:8080 -v opencanvas:/data ghcr.io/casualoffice/opencanvas-workspace

Open <http://localhost:8080>, create the first admin account (from the same machine no code is needed; from elsewhere, enter the one-time setup code printed in the container log), and invite your team.

What you get:

  • Typed files. New offers a Document, a Spreadsheet, a Whiteboard / Diagram or a Database. Each opens straight into its own full-screen editor and has its own icon in Home, search and trash.
  • Sharing. Share with people, teams or a whole workspace as Full access, Can edit, Can comment or Can view; links for everyone in the organisation; public links (admin-controlled, with an optional expiry and password). Revoking access closes open sessions at once.
  • Search across titles and content (⌘K), filtered to what each person may open.
  • Trash and version history. Deleted files are kept 30 days; history keeps every save for a day, then thins out, and named versions forever.
  • Passkeys as well as passwords, invite links, and admin reset links.
  • Admin. Members, teams, invites, branding, sign-in rules, public-link policy, retention and backups, in the app.

For production, [deploy/workspace/compose.yml](deploy/workspace/compose.yml) runs the same image as a Workspace and two engine nodes, with MariaDB, Redis and nginx in front.

Current limits, honestly: no single sign-on (SSO) yet (it is on the backlog), e-mail is not sent yet (invites and password resets are links you copy), and backups are manual (Back up now in Settings, or copy the /data volume; there is no schedule or one-command restore yet). The Workspace guide covers install, setup, invites, sharing, backups, upgrades and every WS_* setting; the design is in docs/40.

Features

Editing

  • Blocks: text, headings, lists, checklists, toggles, callouts, code, tables, images, files, link cards, sandboxed embeds and columns, from a categorised insert menu.
  • Spreadsheet block and linked charts, as above.
  • Databases: typed fields with table, board, calendar, gallery, Timeline and Workload views; filter, sort, CSV import and export; formulas, relations and rollups.
  • Whiteboards and diagrams: shapes, sticky notes, pen, attached arrows, shape libraries, connector routing, layout, and draw.io and Excalidraw import (diagram guide).
  • 40 templates in 9 categories. Autosave only, on desktop and phone.

Collaboration

  • Edits merge in real time with a CRDT (Yjs), with cursors, presence, follow mode and comments.
  • View, comment and edit roles enforced on the server; role changes apply live (collaboration).

Platform

  • Headless API (/api/v1) with TypeScript (@opencanvas/client) and Rust (opencanvas-client) clients, and signed webhooks (integration guide §7).
  • Block SDK: write your own sandboxed blocks.
  • Editor profiles: each host picks notebook, meeting, project, diagramming, document or the full workspace.
  • Live blocks shown and edited in several canvases; find and replace, and search across canvases through the host's search; automation rules; offline editing. All four are off until the host turns them on (release notes 0.3.0).
  • Version history: named versions, comparison and restore; availability depends on the host and permissions.
  • Assistant and MCP endpoint: experimental, off by default, run only in the server with a model the operator configures on the Claude Platform or an OpenAI-compatible server (OpenAI, vLLM, Ollama, llama.cpp) (AI and MCP).

Integrations

  • Jitsi Meet, Nextcloud, Mattermost and Element / Matrix. Host integrations for WOPI files, channel canvases and room widgets.
  • Any WOPI host, or the <open-canvas> web component and signed launch tokens for your own app.

Storage and scale

  • One container with SQLite to start; MySQL, MariaDB and Redis when you need a cluster.
  • SQLite by default. MySQL 8.4 and MariaDB 11.4 work when DATABASE_URL=mysql://… is set; REDIS_URL turns on cluster mode. Docker image and Helm chart (operations, capacity and sizing).

Run it

With Docker, using a hosts file written from the integration guide:

docker run -p 8080:8080 -v oc-data:/data \
  -v "$PWD/hosts.toml:/etc/opencanvas/hosts.toml:ro" \
  -e OC_PUBLIC_URL=https://canvas.example.com \
  -e OC_KEK=$(openssl rand -base64 32) \
  ghcr.io/casualoffice/opencanvas:0.4.3

From source, with the sample host (Rust stable, Node 24 and pnpm 9):

cd web && pnpm install && pnpm --filter @opencanvas/editor build && cd ..
OC_DEV=1 cargo run --release -p oc-server     # http://localhost:8080
node examples/sample-host/server.mjs          # http://localhost:4000

Open http://localhost:4000 and open a file; in a second tab pick another user under "Signed in as" to see live collaboration. docker compose up --build runs both services. OC_DEV=1 allows starting without OC_KEK; in production set OC_KEK (32 bytes, base64) and the variables in operations. For the UI alone, run pnpm --filter @opencanvas/editor dev and open http://localhost:5173/app/#demo.

Embed it

<script type="module" src="https://canvas.example.com/sdk/embed.js"></script>
<open-canvas server="https://canvas.example.com" token="{{ launch_jwt }}" style="height:100vh"></open-canvas>

The token claims, callbacks, postMessage events and REST API are in the integration guide; the wire formats are in the build contract.

How it works

Your app  ── signs launch token (who, which file, which role) ──▶ OpenCanvas iframe
          ◀── load / save / assets / members / copies callbacks ──  OpenCanvas server
  • Your app owns authentication, users, permissions, files, versions and retention.
  • OpenCanvas owns the editor, real-time merge, presence, export and autosave back to your storage.
  • OpenCanvas never becomes the system of record: it keeps only a transient room log and a save outbox.
  • HS256, RS256, EdDSA and JWKS launch tokens are single use, and callbacks are signed (security).

Releases and roadmap

The latest release is 0.4.1 (2026-11-28), which closed the spreadsheet, chart and Timeline gaps in the 0.4.0 release notes; every version is in the CHANGELOG. Next: v0.4.2 finishes partial sync (spreadsheets as parts, the first screen under 2 s); v0.5 brings plugins with a marketplace, backlinks, a knowledge graph and SDK extension points; OpenCanvas Workspace, a first-party host, is a parallel track; v0.6 is advanced automation and app building (roadmap). Support is best-effort, with no production SLA.
