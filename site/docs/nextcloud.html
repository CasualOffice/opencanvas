Nextcloud

Create and edit .ocanvas files in Nextcloud with the opencanvas app: Nextcloud keeps the files, shares and versions as the WOPI host.

opencanvas/ is a Nextcloud app (app id opencanvas, Nextcloud 30–32, PHP 8.1+). It lets people create .ocanvas files in Files and edit them together in OpenCanvas: rich text, databases and whiteboards in one file. Nextcloud keeps the files, sharing, permissions and versions. OpenCanvas does the editing and stores no documents.

  • Nextcloud is a WOPI host for OpenCanvas, the same way it is one for Collabora through Nextcloud Office.
  • Design and decisions: DESIGN.md.
  • Screens: UI-SCREENS.md; approved prototype in docs/prototypes/nextcloud-approved/, with screenshots of the built app in its screenshots/.

Status: alpha.

  • The backend and the approved screens S1-S8, S12 and S13 work end to end in a real Nextcloud 31 with real browsers (see "Verified").
  • Nextcloud Talk (TALK-01, v0.4): canvas cards in conversations, the Canvas panel beside the chat or call, and a temporary meeting canvas per call (see "Nextcloud Talk").

Nextcloud is a registered trademark of Nextcloud GmbH. Mattermost is a trademark of Mattermost, Inc. OpenCanvas is an independent open-source project, not affiliated with or endorsed by either company.

How it works

  1. Open. Someone opens an .ocanvas file. Nextcloud mints a short-lived access token for that person and file, and the page form-POSTs it into an iframe at {opencanvas}/v1/launch?WOPISrc={nextcloud}/index.php/apps/opencanvas/wopi/files/{fileId}.
  2. Load. OpenCanvas calls the app's WOPI endpoints:
    • CheckFileInfo returns who the person is and what they may do.
    • GetFile returns the file.
  3. Save. Saves are PutFile calls. Each save is a normal Nextcloud write, so it shows in Versions and in Activity under the editor's name.
  4. Conflicts. If the file changed outside the canvas, OpenCanvas saves a "(conflict copy)" next to it (PUT_RELATIVE).
  5. Proof keys. Every WOPI call carries an RSA proof signed by OpenCanvas. The app checks it against OpenCanvas's discovery, so only your OpenCanvas server can read or write files through these endpoints. Calls without a valid proof get 500.
  6. Access checks. Every call checks access live. When a share is removed or changed, the app also calls OpenCanvas's role API, so an open canvas switches to read-only or closes at once.
  7. One room per file. Everyone who opens the same file edits the same live canvas: the room id is the WOPISrc.

Permissions:

In Files:

  • Clicking a canvas opens it in Nextcloud's Viewer; the row's "…" menu has Open in full page (/apps/opencanvas/open/{id}, with a bar back to the folder, Share and Download).
  • The + New menu has, after a separator: New canvas (Nextcloud's own name dialog and template picker; OpenCanvas opens it on its start screen), New database canvas and New whiteboard canvas (our name dialog, then POST api/v1/create with kind). The file opens as soon as it is created.
  • .ocanvas files show the indigo canvas icon.
  • The Sharing tab shows what each share level means in a canvas. With the admin's comment switch on, a view-only share's advanced settings get Can comment in OpenCanvas.
  • Public links to a canvas open it under Nextcloud's public header. Guests on edit links give a name first (kept in the browser); view-only guests open at once as "Guest".
  • When a canvas can't open (not set up, OpenCanvas down, proof rejected, over 100 MB, no access, not found, links turned off) a Nextcloud screen says what happened and what to do; admins get the fix.

In Nextcloud search (SRCH-05, ADR-065). Canvases appear in the unified search (the magnifier in the header) under Canvases:

  • Every save of an .ocanvas (OpenCanvas's PutFile, a conflict copy, an upload, a WebDAV PUT, a copy) carries search.json, the canvas's plain text with block ids. The app reads it into its own table oc_opencanvas_search (text only; deleted with the file). This is Nextcloud's index: OpenCanvas keeps none. Files saved before OpenCanvas 0.3 have no search.json and are indexed on their next save.
  • Results are only files the person can open in Nextcloud, checked at search time, so a removed share hides a canvas at once. A result shows the canvas title, the matching text, its heading and its folder, and opens the canvas on the full page at the matching block (#block=<id>, sent to the editor as Action_ScrollToBlock once it has loaded).
  • occ opencanvas:search-index [user…] indexes existing canvases (run once after an upgrade).
  • Comments are in search.json only when OpenCanvas's [host.search] comments = true.

Nextcloud Talk

With Talk (spreed) enabled, built to docs/prototypes/v04-approved/nextcloud-talk.html (TALK-01):

  • Post to a Talk conversation (sharing sidebar card): pick a conversation, add an optional message, post. The message carries the canvas link, which Talk shows as an OpenCanvas card (a reference provider, lib/Reference/CanvasReferenceProvider.php, resolved per reader). Posting never grants access. If people in the conversation can't open the file, the dialog says how many and offers "Share the file with the conversation" (Can edit / Can view), a normal Talk room share.
  • The card: title, where the file lives, two lines of text, when it was edited, "Open beside chat" and "Full screen" ("Open" on a phone). Someone without access sees only the title and who shared it, and "Ask … for access", which posts a Talk message mentioning the sharer.
  • The Canvas panel (a "Canvas" button in Talk's top bar): beside the chat or call at 38 rem, as a 25 rem sidebar tab when the window is 64 rem wide or less, full screen (Talk's top bar with the call controls stays visible; Esc returns), and full screen with a draggable call tile on a phone (under 45 rem). Empty state ("No canvases here yet"), error state (Retry, Copy error; the call is not affected) and the no-access card.
  • Meeting canvas per call: during a call, "New meeting canvas" starts a temporary canvas that everyone in the call edits. It lives in the app's data (appdata_*/opencanvas/meetings), not in anyone's Files. Moderators can turn off "Participants can start a canvas" for the conversation. When the call ends, everyone is read only at once and the moderator is asked to save or discard. Save writes <conversation> meeting canvas <date>.ocanvas into the moderator's Talk folder and, by default, shares it with the conversation (Talk posts it). With no answer within 10 minutes, or if no moderator was present, it is discarded (background job ExpireMeetings, every 5 min, plus a check on every look).
  • Guests (public conversations) see meeting canvases with their Talk name and "(Guest)", read only unless the moderator turns on "Guests can edit"; they never save, export or download. Shared files keep their own Nextcloud permissions: Talk never raises them.
  • Moderator menu: Guests can edit, Lock canvas (everyone else read only), Follow me (everyone with the panel open on the same canvas scrolls with the moderator; for a shared file only Follow me appears), Save to Files, Download.
  • Role changes (lock, guests, call end, discard) reach open editors at once through OpenCanvas's role API when opencanvas_api_key is set; every WOPI call also re-reads the role.
  • Meeting canvases use {wopi_base}/meetings/{id} as WOPISrc, under the same allow-listed prefix.
  • Talk has no public PHP API for participants or call state: the app reads them through Talk's classes (lib/Talk/SpreedGateway.php, checked with Talk 21 on Nextcloud 31) and the browser uses Talk's OCS chat API. A Talk upgrade that changes those classes turns the panel off (no button) rather than failing.

Install

Use an OpenCanvas 0.1.2 server for the features described in this guide. See Operations.

1. OpenCanvas: register Nextcloud as a WOPI host in opencanvas.hosts.toml:

[[host]]
id              = "nextcloud"
name            = "Nextcloud"
mode            = "wopi"
wopi_allowlist  = ["https://cloud.example.com/index.php/apps/opencanvas/wopi"]
allowed_origins = ["https://cloud.example.com"]
api_key         = "env:NC_OC_API_KEY"      # lets Nextcloud switch open canvases when shares change
[host.flags]
on_conflict     = "copy"

Start OpenCanvas with a proof key. It refuses a WOPI host without one:

openssl genrsa -out proof.pem 2048
OC_WOPI_PROOF_KEY=/path/to/proof.pem NC_OC_API_KEY=$(openssl rand -hex 24) opencanvas

2. Nextcloud: install and enable the app.

cp -r opencanvas /var/www/nextcloud/custom_apps/   # or apps/
chown -R www-data: /var/www/nextcloud/custom_apps/opencanvas
occ app:enable opencanvas                 # registers .ocanvas (config/mimetypemapping.json)
occ maintenance:mimetype:update-js        # so the browser knows the type too

3. Configure the app.

occ config:app:set opencanvas opencanvas_url --value=https://canvas.example.com
occ config:app:set opencanvas opencanvas_api_key --value=<same as NC_OC_API_KEY> --sensitive
# optional
occ config:app:set opencanvas opencanvas_internal_url --value=http://opencanvas:8080
occ config:app:set opencanvas wopi_base --value=https://cloud.example.com/index.php/apps/opencanvas/wopi
occ config:app:set opencanvas opencanvas_host_id --value=nextcloud
KeyMeaningDefault
opencanvas_urlWhere browsers reach OpenCanvasrequired
opencanvas_internal_urlWhere Nextcloud reaches OpenCanvas (discovery, role API)opencanvas_url
wopi_baseThe WOPI base OpenCanvas calls. It must be reachable from OpenCanvas and match its wopi_allowlist.{overwrite.cli.url}/index.php/apps/opencanvas/wopi
opencanvas_api_key (sensitive)The host's api_key in OpenCanvas. Without it, share changes take effect only at the next WOPI call or reopen.empty
opencanvas_host_idThe host id in OpenCanvasnextcloud
allow_public_linksGuests on public link sharestrue
allow_comment_roleRead-only shares with the opencanvas/comment share attribute get the comment rolefalse
  • The token secret is generated on first use and stored as a sensitive value.
  • If Nextcloud runs on a private address (Docker, LAN), also set occ config:system:set allow_local_remote_servers --value=true --type=boolean. Otherwise Nextcloud refuses to fetch discovery from OpenCanvas.

4. Check the connection. Open Administration > OpenCanvas: enter the address (and the internal address and API key), save, copy the WOPI base into wopi_allowlist, and the connection check runs its four steps (OpenCanvas answers, opens .ocanvas, publishes a proof key, accepts this Nextcloud) with the fix for any failing one. Or, from a shell:

curl -u admin -X POST -H 'OCS-APIREQUEST: true' https://cloud.example.com/index.php/apps/opencanvas/settings/check

It should answer {"ok":true,"steps":[…],"discovery":true,"ocanvasAction":true,"proofKey":true, "accepts":true,"wopiBase":"…"}. Put the wopiBase it shows into OpenCanvas's wopi_allowlist.

5. Front end. The app's screens are built with Nextcloud's standard tooling (@nextcloud/vite-config, Vue 2.7, @nextcloud/vue 8, @nextcloud/files 3). Build before installing from git; js/ is not committed, as for other app-store apps:

cd opencanvas && npm ci && npm run build   # writes js/opencanvas-{files,viewer,fullpage,public,admin}.mjs
npm test                                   # JS unit tests (vitest)

Limits

  • Viewer header. Nextcloud's Viewer "…" menu can't take app entries, so "Open in full page" is in the Files row menu only; "View only"/"Download off" badges are in OpenCanvas's own bar.
  • File icon. Nextcloud only resolves file-type icons from core/img/filetypes. The app shows its icon in the browser (Files, Viewer, public pages) without writing into core; places Nextcloud renders on the server (emails, activity) show the generic document icon.
  • Full page Share. It opens the Files sidebar in Files (not beside the full-page canvas).
  • Mentions. The @mention list is the people who have opened the canvas, not everyone it is shared with, and mentions send no Nextcloud notifications (OpenCanvas WOPI mode; DESIGN.md G1).
  • Sessions. They last at most 10 h, then the canvas relaunches.
  • Images. Pictures are stored inside the .ocanvas: 10 MB per image, 50 MB per file, files up to 100 MB.
  • Comment role. Read-only shares get view, not comment, unless an admin turns on the comment role (DESIGN.md §5).
  • Versions (VH-01c). Each autosave is a version; Nextcloud's expiry thins them out. The app advertises OpenCanvas_SupportsVersions and answers GET {WOPISrc}/versions and {WOPISrc}/versions/{v}/contents over files_versions (editors only), so the OpenCanvas history panel lists, previews, compares and restores them. A named or restore save (X-COOL-WOPI-IsAutosave: false + X-OpenCanvas-Commit-Message) sets the version's Nextcloud label and our metadata opencanvas_kind / opencanvas_restored_from (Nextcloud 29+, IMetadataVersionBackend; older servers keep the name only in the file's manifest). Authors are Nextcloud's own author metadata (the save runs as the editor). In-file history is off for this host by default ([host.versions] file = false, docs/05 §2).
  • Do labelled versions survive expiry? Read from Nextcloud 31 apps/files_versions/lib/Storage.php (2026-11-24): labelled versions are skipped by the max-age expiry (expireOlderThanMaxForUser) and by the quota expiry loop in expire(), but not by its low-space fallback (oldest versions deleted until the quota fits, no label check), nor when a version has no database row. So named versions are kept in normal operation and can still go when a user runs out of space. Not yet confirmed in a running Nextcloud (the real-host pass for VH-01c is pending).
  • Locks. None. An outside change to an open file produces a conflict copy.
