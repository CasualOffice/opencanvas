FAQ

Short answers, with links to the pages that say more.

Can I use it in production today?

OpenCanvas 0.1.2 has best-effort support and no production SLA. Review the deployment limits before committing it to a production workflow.

What does the licence allow?

OpenCanvas is open source under the Apache License 2.0, copyright 2026 CasualOffice.

  • Allowed: using, modifying, self-hosting, embedding and redistributing it, in open or closed, commercial or non-commercial products and services.
  • Attribution: when you redistribute OpenCanvas or a work derived from it, keep the NOTICE file and the licence.
  • Fonts: the bundled fonts are under the SIL Open Font License 1.1.

The LICENSE file states the exact terms and is the authority; this summary is not legal advice.

Does OpenCanvas keep my documents?

Only while a session is live. The server keeps a snapshot and the recent updates so it survives a restart and late joiners can catch up, and deletes them after the session is saved and idle. The file lives in your app; OpenCanvas writes it back there. See Architecture.

How do users sign in?

To your app, not to OpenCanvas. Your backend checks access and signs a short-lived launch token naming the file, the user and the role (view, comment or edit). OpenCanvas trusts that decision for the life of the token, enforces it on every edit, and switches a user's role live when your app calls the role API. See the integration guide.

Is there a Save button?

No. Every change saves to your app on a short timer, when the canvas goes idle, when the last person leaves and when the server shuts down. Saves go through a durable outbox, so a restart resends them. If your copy of the file changed elsewhere, your chosen policy runs: save a copy, or reload.

We already use Collabora through WOPI. Can we reuse that?

Yes. OpenCanvas is a WOPI client: discovery, CheckFileInfo, GetFile, PutFile and PUT_RELATIVE, with an allow-list for the WOPISrc URLs it will call. Proof keys are not supported yet. See WOPI mode.

What can it import and export?

Export: Markdown, HTML, JSON, the native .ocanvas file, Word, and PDF when the operator runs the optional Gotenberg sidecar (otherwise the editor prints to PDF). Whiteboards export as SVG and PNG. Import: Markdown, HTML and CSV. See Operations.

How does it scale?

One node runs on SQLite. For more users, run several nodes against MySQL or MariaDB with Redis: each room has one owner node, other nodes relay to it, and if the owner dies another node takes the room over from its log. See Operations and Architecture.

Does the demo send anything anywhere?

No. The demo is the real editor running against a document in your browser, with simulated collaborators. There is no server behind it, and exports that need a server say so. Its assistant plays a scripted run: no model is called.

Where does the assistant send my content?

Only to the model server the operator configures: the Claude Platform, or a self-hosted model through vLLM, Ollama or llama.cpp. The OpenCanvas server makes that call, never the browser, and it keeps no prompts or answers. AI is off unless the operator turns it on for your app. A self-hosted model needs tool calling for the assistant to edit; without it, it can only answer. See AI and MCP.
