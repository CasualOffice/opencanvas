FAQ

Short, direct answers, each followed by the page that says more. Numbers link to where they were measured.

What is OpenCanvas?

OpenCanvas is an open-source, real-time collaborative canvas that other applications embed, the way they embed Collabora Online for office files. One document holds rich text, databases and whiteboards, with live cursors and comments. Your application keeps the users, the permissions and the file; OpenCanvas does the editing and saves the file back to it.

See the facts for the release, the stack and the measured capacity.

Can I use it in production today?

OpenCanvas 0.4.3 is an early release with best-effort support and no production SLA. You can run it, but read the known limitations before you rely on it: durability depends on the persistence mode you choose, and scale-out across several machines has not been demonstrated yet. Source: CHANGELOG.md, “## [0.4.3] - 2026-11-28”

The limits are in the release notes and on the home page.

Is OpenCanvas free?

Yes. OpenCanvas is open source under the Apache-2.0 licence, so you may use, modify, self-host, embed and redistribute it, including in commercial and closed-source products, at no cost. The one duty when you redistribute it is to keep the NOTICE file and the licence with it.

What does the licence allow?

OpenCanvas is under the Apache License, copyright CasualOffice. You may use, modify, self-host, embed and redistribute it, in open or closed, commercial or non-commercial products and services. When you redistribute OpenCanvas or a work derived from it, keep the NOTICE file and the licence. The bundled fonts are under the SIL Open Font License.

The LICENSE file states the exact terms and is the authority; this summary is not legal advice.

Does OpenCanvas keep my documents?

Only while a session is live. The server keeps a snapshot and the recent updates of an open canvas so it survives a restart and late joiners can catch up, and deletes them after the session is saved and idle. The file itself lives in your application, and OpenCanvas writes every change back there.

See Architecture.

How do users sign in?

They sign in to your application, not to OpenCanvas. Your backend checks access and signs a short-lived launch token naming the file, the user and the role: view, comment or edit. OpenCanvas trusts that decision for the life of the token, enforces it on every edit, and switches a role live when your app calls the role API.

See the integration guide.

Is there a Save button?

No. Every change saves to your application on a short timer, when the canvas goes idle, when the last person leaves and when the server shuts down. Each save goes through a durable outbox, so a restart resends it. If your copy of the file changed elsewhere, the policy you chose runs: save a copy, or reload.

We already use Collabora through WOPI. Can we reuse that?

Yes. OpenCanvas is a WOPI client: it uses discovery, CheckFileInfo, GetFile, PutFile and PUT_RELATIVE, calls only the WOPISrc URLs on its allow-list, and signs every call to your WOPI host with the WOPI proof headers. Nextcloud's integration works this way.

See WOPI mode and Nextcloud.

How is OpenCanvas different from Collabora Online?

They share an integration model and edit different things. Collabora Online edits office documents: text, spreadsheets and presentations. OpenCanvas edits a canvas: blocks, databases and whiteboards in one document. In both, the host application keeps the file and the permissions, and the editor runs the live session and saves back to the host.

The project's research note studies Collabora's integration in detail.

How does it compare with Slack Canvas, Zoom Canvas and Microsoft Loop?

Those canvases live inside their vendor's product and the vendor stores the file: Slack, Zoom, or OneDrive and SharePoint for Loop. OpenCanvas is built to be embedded in your own application, stores the file in your application through callbacks, and runs on your own servers. Loop's portable live components have no OpenCanvas equivalent yet; they are planned.

The comparison table on the home page has the details, from the vendors' public documentation.

Which apps does it integrate with?

There are ready integrations for Jitsi Meet (a temporary canvas in every meeting), Nextcloud (.ocanvas files through WOPI), Mattermost (canvases in channels) and Element / Matrix (a room widget). Any other web application can embed OpenCanvas with a launch token signed by its backend, or open it as a WOPI client.

See Jitsi Meet, Nextcloud, Mattermost, Element / Matrix and the integration guide.

What can it import and export?

It exports Markdown, HTML, JSON, its native .ocanvas file and Word, and PDF when the operator runs the optional Gotenberg sidecar; otherwise the editor prints to PDF. Whiteboards export as SVG and PNG. It imports Markdown, HTML and CSV into a canvas, when the host turns import on: it is off by default.

See Operations.

How many users can one server handle?

The project's sizing guide gives up to 1,000 concurrent users on 1 vCPU and 512 MB, and up to 5,000 on 2 vCPU and 2 GB; beyond 5,000, run cluster mode. These figures come from load tests on one laptop, with most people watching and some typing, so measure on your own hardware. Source: docs/22, “In short: up to 1,000 concurrent users on 1 vCPU and 512 MB; up to 5,000 on 2 vCPU and 2 GB; beyond 5,000, cluster mode.”

See Capacity and sizing, which also has the nonstop-typing, crash and cluster runs.

How does it scale?

One node runs on SQLite with no database to set up. For more users, run several nodes against MySQL or MariaDB with Redis: each room has one owner node, the other nodes relay to it, and if the owner dies another node takes the room over from its log.

See Operations and Architecture.

What is it built with?

The server is written in Rust, on tokio and axum, and ships as one binary or a Docker image. The editor runs in the browser and is built on Tiptap (ProseMirror) with Yjs, the CRDT that merges everyone's edits. Storage is SQLite by default, or MySQL or MariaDB, with Redis for a cluster.

See Architecture.

Does the demo send anything anywhere?

No. The demo is the real editor running against a document in your browser, with simulated collaborators. There is no server behind it, and exports that need a server say so. Its assistant plays a scripted run: no model is called and nothing leaves your browser.

Where does the assistant send my content?

Only to the model server the operator configures: the Claude Platform, or a self-hosted model through vLLM, Ollama or llama.cpp. The OpenCanvas server makes that call, never the browser. AI is off unless the operator turns it on for your app. A self-hosted model needs tool calling for the assistant to edit; without it, it can only answer.

See AI and MCP.
