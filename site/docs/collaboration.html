Collaboration and presence

How edits merge, how cursors and presence work, undo, connectivity and comments in OpenCanvas.

Status: draft v0.1, 2026-11-21.

1. Merge semantics (what users see when they collide)

SituationResult
Two users type in the same paragraphBoth texts kept, interleaved by position (Yjs YATA). No lost characters.
Both bold overlapping rangesUnion of marks. One bolds, other unbolds same range → last writer per character.
One deletes a block while another types in itDelete wins; the typing is lost and the typer is notified ("Block removed by Asha · Undo"). Their undo restores it.
Both move the same blockLast move wins (single final position, never duplicated).
Table: one adds a column, other adds a rowBoth applied; new cells empty.
Board: two users drag the same shapeLast position wins per field; colour change by the other is kept.
Board: concurrent pen strokesAll strokes kept (append-only).
Task checkbox toggled by two usersLast writer wins.
Comment resolved while someone repliesReply kept; thread re-opens with indicator.

These are verified by the convergence fuzz harness (04 §9), and each row is a named test case.

2. Presence model (awareness)

Each connection publishes a small state (≤ 2 KB, ≤ 20 Hz):

{
  "user":   { "id": "u_123", "name": "Asha Rao", "color": "#7c3aed", "avatar": "…", "role": "edit" },
  "cursor": { "anchor": <RelativePosition>, "head": <RelativePosition> },
  "board":  { "id": "brd_1", "x": 412.5, "y": 80, "tool": "pen", "selection": ["s_9"] },
  "view":   { "blockId": "b_44" },          // what they are looking at, for "follow"
  "typing": true,
  "idle":   false
}
  • user fields are overwritten by the server from the session grant — clients cannot spoof names/colours.
  • Cursor positions are Yjs relative positions, so they stay correct while text around them changes.
  • Colour: host-provided or derived from hash(user.id) into a 12-colour palette that passes 3:1 contrast in light and dark themes.

3. Cursor & selection rendering

  • Text: caret = 2 px bar in user colour + name label (shown on move, fades after 2 s idle, shown on hover). Selection = 20 % tint of user colour. Labels collision-avoid (stack upward) when carets are on the same line.
  • Board: pointer arrow + name tag in user colour, interpolated (60 fps lerp) between 20 Hz updates; selection outline in user colour; "laser" tool leaves a fading trail.
  • Off-screen collaborators: avatar stack in the top bar. A click on an avatar, or a long press (450 ms, for touch), starts follow mode: the canvas scrolls to their caret (or their board) and keeps it in view until you scroll, use the wheel or press a key. A click on the avatar you follow stops it; a long press never stops it. The avatar shows a ring and aria-pressed while you follow; the "People here" list (+N) follows on click too. Someone with no caret (a viewer, or idle) gets a toast instead. (Changed 2026-11-21, UX-02: the draft said click jumps and long-press follows, with ↑/↓ edge hints; edge hints are not built.)
  • Block-level presence: a thin coloured bar in the left gutter of blocks someone is editing — cheap and readable on narrow embeds.
  • Typing indicator in the avatar stack.
  • Viewers are shown as presence (eye badge) but have no caret.

4. Undo/redo

  • Y.UndoManager with trackedOrigins = {localOrigin} — undo only reverts your changes, never a collaborator's.
  • Capture timeout 500 ms groups keystrokes into words.
  • One stack for the whole canvas: the editor's Y.UndoManager (y-prosemirror) is passed to database and board blocks as BlockEnv.undoManager; they add their maps to its scope and their origins to its tracked origins. ⌘Z / ⌘⇧Z in the text step through text, header, cells and shapes in the order they were made (m-open-items e2e). Structural actions (file actions, adding or removing columns) close the current capture so each is its own step.
  • Undo stack resets on reload (it is not persisted).

5. Connectivity

StateUIBehaviour
Connectednone—
Reconnecting"Reconnecting" statusedits continue locally, buffered
Offline"Offline · kept here" status + banneredits buffered (memory; IndexedDB if host enables)
Back online"Synced" toastYjs sync step1/2 merges buffered changes
Role downgradedbanner "You now have view access"editor switches to read-only, local unsynced edits shown as discarded diff
Token expiringsilent refresh via host; else banner—
Session closed by hostmodal "This canvas was closed by the app"—

Detecting a lost connection (UX-02). A closed socket shows "Reconnecting" at once. A silent drop (Wi-Fi gone, a proxy that stops forwarding) closes nothing, so the server sends a control {"t":"ping"} every 10 s on every connection (docs/15 §3) and the client treats 15 s without any frame as lost: it shows "Reconnecting", drops the socket and reconnects. After a silent drop, or a browser offline event, "Offline" follows 3 s later (so within 20 s of the drop); any other outage turns into "Offline" after 20 s. The browser's online event reconnects at once instead of waiting for the backoff.

Exponential backoff 0.5 s → 10 s with jitter. Server owner change in cluster is invisible to users beyond a ≤ 5 s reconnect.

6. Save state indicator

Saved · 2 min ago → Unsaved changes → Saving… → Saved (or Save failed · retrying). Click opens a small popover: last commit, authors, "Save version…" (message input) if perms.commitMessage.

7. Comments (P2)

  • Anchors: text range (relative positions start/end) or board shape id or whole block id.
  • Stored in the comments Y.Map → travel inside the .ocanvas file.
  • Commenters (role comment) can write only that subtree (enforced server-side).
  • Mentions in comments and canvas text call the host's POST /mentions (docs/05 §5) so the host can notify (we never send emails/notifications ourselves). Not in WOPI mode.
