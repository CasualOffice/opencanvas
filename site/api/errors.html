Errors

Every error answer is RFC 9457 problem details, application/problem+json, with a machine code you can branch on. The code is stable; the human detail is not.

The shape

{
  "type": "urn:opencanvas:problem:stale-block",
  "title": "Precondition Failed",
  "status": 412,
  "detail": "a block changed since it was read; re-read it and retry",
  "code": "STALE_BLOCK",
  "fresh": {
    "stale": [
      {
        "blockId": "b_01m87jv4rtkdxymn93jwtx35sk",
        "rev": "5641be1fd2cb",
        "markdown": "Ship on Friday.\n"
      }
    ]
  }
}
MemberMeaning
typeurn:opencanvas:problem:<code in lower case, hyphens>. A stable name, not a URL to fetch.
titleThe HTTP reason phrase of status.
statusThe HTTP status, repeated in the body.
detailWhat went wrong, in words, for logs and people. It can change between releases; do not parse it.
codeThe machine code: branch on this. The same codes the 0.1 routes use.
freshOnly with STALE_BLOCK: the current state to retry against.

Unknown members may be added later; ignore them. Even answers the router gives before an operation runs (an unknown path, a wrong method) are problem details, so a client parses one error format.

Handling them

StatusWhat to do
400Fix the request; detail says what is wrong. Do not retry it unchanged.
401Fix the credentials: the host key, or mint a new token.
403The scope or the user's role does not allow it. Do not retry.
404Unknown file part or operation, or the API is off (API_OFF).
409CONFIRMATION_REQUIRED: send again with "confirm": true. IDEMPOTENCY_IN_PROGRESS: retry after Retry-After. CONFLICT: your save callback reported a conflict.
410CURSOR_EXPIRED: start the walk again without a cursor.
412STALE_BLOCK: re-read (or use fresh), apply your change again, send it with the new revision.
413The body or the resulting document is too large.
422IDEMPOTENCY_KEY_REUSED: a new request needs a new key.
429Wait Retry-After seconds, then retry.
5xx503 and 502 are transient: retry after Retry-After with backoff. 501: the server is not set up for it (PDF).

The TypeScript and Rust clients turn these into typed errors and retry 429, 503 and 409 IDEMPOTENCY_IN_PROGRESS for you; see SDKs.

Every code

Any operation on a file

Authentication, the API switch, rate limits and availability: every /api/v1 operation on a file can answer these.

CodeStatusMeaning
TOKEN_EXPIRED401The bearer token's exp has passed. Mint a new one; tokens live at most 15 minutes.
TOKEN_INVALID401A bearer token failed a check: signature, issuer, audience, a lifetime over 15 minutes, or not yet valid (nbf). Also answered when the host has no public base URL, so user tokens are off for it.
UNAUTHENTICATED401No credentials, an unknown host, or a wrong host key. The answer carries WWW-Authenticate: Bearer realm="opencanvas".
FILES_REQUIRED403The host does not implement POST /access, so a token's role claim counts only for the files in its files claim, and this token has none. Add files, implement /access, or set [host.api] all_files = true.
ROLE_FORBIDDEN403The user's role on the file is below what the operation needs (the effective permission is min(scope, role)), the token does not list the file in files, or the host revoked the user.
SCOPE_REQUIRED403The token's scope does not cover the operation. Admin operations need canvas:admin, which counts only when the host sets [host.api] token_admin = true.
API_OFF404The host has turned the API off ([host.flags] api_v1 = false in its entry of the hosts file).
RATE_LIMITED429A token bucket is empty: the caller's, or the file's write bucket. Wait for Retry-After seconds. The RateLimit header says which bucket and when it refills.
INTERNAL500An unexpected server error, or the host's POST /access callback failed. The server logs the cause; retrying may help.
UNAVAILABLE503A dependency is briefly unavailable: the idempotency store, the node that runs the file's live room, or the ticket store. Retry after Retry-After.

Router fallbacks

Answers the router gives before an operation runs.

CodeStatusMeaning
UNAUTHORIZED401A fallback for a 401 that did not carry its own code.
FORBIDDEN403A fallback for a 403 that did not carry its own code.
METHOD_NOT_ALLOWED405The path exists but not with this method; Allow lists the methods it takes.
UNSUPPORTED_MEDIA_TYPE415A fallback for a request the router could not read.
ERRORotherAny other error status without its own code.

0.1 routes only

The deprecated /v1/... routes answer {"error": {"code", "message"}} with these and the codes above.

CodeStatusMeaning
PATCH_INVALID4000.1 patch: an op is malformed.
API_KEY_INVALID4010.1 routes: the host id or key is missing or wrong.

The 0.1 routes

The deprecated /v1/files/{fileId}/... routes keep their old error shape, {"error": {"code": "...", "message": "..."}}, with the same codes. Only /api/v1 answers problem details.
