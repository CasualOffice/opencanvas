Blocks

List, read and find blocks, and change them in one atomic batch.

  • GET /api/v1/files/{fileId}/blocks
  • GET /api/v1/files/{fileId}/blocks/{blockId}
  • GET /api/v1/files/{fileId}/blocks:find
  • POST /api/v1/files/{fileId}/blocks:batch
  • POST /api/v1/files/{fileId}/live
  • GET /api/v1/files/{fileId}/references

List top-level blocks

GET/api/v1/files/{fileId}/blocks

Top-level blocks in document order, a page at a time. Each page answers has_more and next_cursor (and a Link header when more follow); pass the cursor back unchanged. Cursors are signed Yjs positions: paging survives concurrent edits, and every block that exists for the whole walk comes back exactly once.

Credentials
Host key, or a user token with canvas:read.
Least role
view on the file (effective permission min(scope, role)).
Operation id
listBlocks

Parameters

NameInTypeDescription
fileIdrequiredpathstringThe host's file id 1 to 1024 characters.
limitqueryinteger1-100, default 100 1 to 100.
cursorquerystringOpaque, signed cursor from next_cursor (bound to this file and query, valid 1 h)

Responses

200OK

Headers

HeaderDescription
ETagThe document (or block) revision, quoted.
Idempotency-Replayedtrue when this is the stored answer of an earlier request with the same Idempotency-Key
RateLimit-PolicyToken buckets that apply: "subject";q=<burst>;w=<seconds to refill>, and "file-writes" on writes
RateLimitThe bucket closest to empty: "<name>";r=<remaining>;t=<seconds until full>
Link<…?cursor=…&limit=…>; rel="next" when more follow

Body application/json

FieldTypeDescription
blocksrequiredarray of Block-
blockIdrequiredstring | null-
revrequiredstring-
noderequiredobject-
revstring-
has_morerequiredboolean-
next_cursorrequiredstring | null-

Read one block (also nested ones)

GET/api/v1/files/{fileId}/blocks/{blockId}

One block by its blockId, top-level or nested (a paragraph in a column, a task in a list). The block's rev comes back as ETag.

Credentials
Host key, or a user token with canvas:read.
Least role
view on the file (effective permission min(scope, role)).
Operation id
getBlock

Parameters

NameInTypeDescription
fileIdrequiredpathstringThe host's file id 1 to 1024 characters.
blockIdrequiredpathstringThe block's blockId attribute

Find blocks whose text contains q (case-insensitive)

GET/api/v1/files/{fileId}/blocks:find

Blocks whose text contains q, case-insensitively, in document order, with an excerpt and the block's position (path, indexes from the top). types keeps only those block types (paragraph, heading, taskList, ...).

Credentials
Host key, or a user token with canvas:read.
Least role
view on the file (effective permission min(scope, role)).
Operation id
findBlocks

Parameters

NameInTypeDescription
fileIdrequiredpathstringThe host's file id 1 to 1024 characters.
qquerystringText to find
typesquerystringComma-separated block types
limitqueryinteger1-100

Responses

200OK

Headers

HeaderDescription
RateLimit-PolicyToken buckets that apply: "subject";q=<burst>;w=<seconds to refill>, and "file-writes" on writes
RateLimitThe bucket closest to empty: "<name>";r=<remaining>;t=<seconds until full>

Body application/json

FieldTypeDescription
matchesrequiredarray of object-
blockIdstring-
revstring-
typestring-
pathstringIndexes from the top, dot-separated
excerptstring-

Other members may appear; ignore the ones you do not know.

Change blocks in one atomic transaction

POST/api/v1/files/{fileId}/blocks:batch

Change blocks in one Yjs transaction: all ops apply, or none. Ops: append and insertAfter (with markdown or Tiptap blocks), replace, delete, and editText (textEdits: [{find, replace}]). An op with ifMatch whose block changed since you read it answers 412 STALE_BLOCK with the fresh block, and the If-Match header does the same for the whole document. Deleting more than 5 blocks needs "confirm": true.

New content lands directly. Changes to existing blocks land directly too, unless the call sends "mode": "suggest" or the host sets [host.api] default_mode = "suggest": then they become a suggestion (suggestionId) for a person to accept. The answer's rev is the new document revision (also the ETag).

List the live blocks and block references

GET/api/v1/files/{fileId}/references

The liveBlock and blockRef nodes in this canvas (LIVE-01, docs/27 §2.4) with the caller's access to each source, from your POST /access answers (cached 30 s). "Where is this live block used" is yours to answer: OpenCanvas keeps no usage index, and tells you with the live.embedded and live.removed events instead.

Credentials
