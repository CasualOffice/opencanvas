API changelog

The API-relevant entries of CHANGELOG.md, newest first. The OpenAPI document is version 1.0.0; within /api/v1 changes are additive, and a breaking change gets a new path major.

Unreleased

  • Added Offline copies, server side (OFF-01, OFF-07, ADR-063/064): [host.offline] (off by default; checked at start-up; JWT hosts only), the launch token's perms.offline and offlineReason, an ES256 offline grant in the session answer that the editor keeps with its copy and uses only on the device, a revocation generation per host and person (migration 0011; Redis oc:offgen:) raised by POST /api/v1/offline/revoke, and the GET /v1/offline/clear sign-out page. The server stores one number per host and person, never content.
  • Added <open-canvas view="block"> (LIVE-06): one live block with compact chrome for chats and side panels; its height follows the content (UI_Resize, oc:resize). The SDK gains insertLiveBlock(), livePicker(), liveBlockUsage() and the oc:pick-live-block, oc:live-block-open and oc:live-block-usage events.

0.2.1 (2026-11-26)

  • Added Search across canvases, server side (SRCH-02/03/05, ADR-065): every saved .ocanvas carries search.json, a plain-text projection with block ids and heading trails for the host to index (comments only with [host.search] comments = true; never in-file history; at most 2 MB). POST /api/v1/extract answers it statelessly for a .ocanvas or Markdown body. Hosts may implement GET /search ([host.search] callback = true); GET /api/v1/search and the MCP tool canvas_search proxy it for user tokens only, 10 a minute per user, dropping files the host's /access refuses. OpenCanvas keeps no index and caches no result. The sample host indexes search.json and serves the callback and a search page.
  • Added Portable live blocks, server side (v0.3, behind [host.flags] live_blocks, off by default): the host contract (LIVE-01, docs/05 §2c, ADR-070): [host.live] checked at start-up, the POST /files callback, /access required (with optional name and callbackToken), the token's perms.live and live claims, derived sessions for embedded live files (POST /v1/live/session) and "Make live" (POST /v1/live/make).
  • Added Live block projections, snapshots, exports and render (LIVE-04/05/06, ADR-072): GET /v1/live/projection with ETags, POST /v1/live/refresh under the snapshot policy, exports that inline only what the exporting person can read, and API operations makeLive, listReferences and renderFile (GET /api/v1/files/{id}/render) in the OpenAPI document, both clients and the conformance suite.
  • Fixed A newly inserted SDK block takes focus when its frame is ready only while it is still selected.

0.2.0 (2026-11-25)

  • Added Headless API is the supported contract. /api/v1 with OpenAPI 3.1, RFC 9457 errors, scoped user tokens shared with MCP, Idempotency-Key, signed cursors, rate limits, the events stream and the sync token. Most of it shipped in 0.1.2 behind [host.flags] api_v1.
  • Added Webhooks for the events-stream events (WH-01): [host.webhooks], signed deliveries (X-OpenCanvas-Signature v2, Idempotency-Key = event id) from a durable outbox (migration 0009_webhook_outbox), retries with backoff, each sent once per cluster, same origin as callback_base only.
  • Added Clients: TypeScript @opencanvas/client and Rust opencanvas-client, generated from the OpenAPI document, with retries, idempotency keys, paging, events resume and webhook verification. They share a conformance suite (HAPI-06, HAPI-07).
  • Added MCP canvas tools are adapters over the API operations, with one scope check, limiter and idempotency store, and a parity contract test (HAPI-08). New operation: POST /api/v1/files/{id}/boards.
  • Added Block SDK (data side): - block.json manifests installed by the operator (OC_BLOCKS_DIR, sha384 integrity, OC_BLOCKS_ORIGIN) and enabled per host with [host.blocks]; - JSON Schema validation of attrs and data on every write path; - one generic extBlock node and an ext root; - declarative export templates and fallbacks; - data versions with declarative migrations (BSDK-01, -02, -05).
  • Added API reference on the website (/api/): guides for authentication, errors, pagination, idempotency, rate limits, events, webhooks and the SDKs, and one page per resource generated from the OpenAPI document, with samples in curl, TypeScript, Rust and Python.
  • Added tools/check-openapi.py: every API operation is documented with examples and its error codes.
  • Changed An editor older than 0.2 that would delete an SDK block is closed with 4426 ("editor out of date: reopen the canvas").
  • Changed A webhook sweep claims at most 40 deliveries, and the next sweep starts at once (SEC-48).
  • Security SEC-46: room updates over the WebSocket are checked against installed SDK block schemas, as API and MCP writes are. A broken block could otherwise make the file unopenable.
  • Security SEC-51: a restore's undo cannot be reached with a crafted restoreId by a user whose id is a suffix of the restorer's.

0.1.2 (2026-11-24)

  • Added Version history with named versions, preview and comparison, restore and temporary undo where supported by the host.
  • Added Headless API under /api/v1 with OpenAPI 3.1, scoped tokens, and idempotency keys on file writes.
  • Added API events stream (SSE and WebSocket) with resume, and a headless sync token.
  • Fixed A Jitsi role change takes precedence over launch tokens issued before the change.

0.1.1 (2026-11-23)

  • Added Jitsi Meet (integrations/jitsi/, JIT-02): mod_opencanvas.lua gives every meeting a shared canvas in Jitsi's Shared document slot, like Etherpad. One Prosody plugin plus .env lines, no Docker image or compose changes. Per-person launch tokens, a fresh token on reload, the meeting end closes the canvas. Tested end to end against a stock docker-jitsi-meet (stable-11509-1) with two browsers; guide in integrations/jitsi/README.md.
  • Added Temporary canvases (storage = "ephemeral", ADR-043, JIT-01) for hosts with no file storage: no load or save callbacks; everything is deleted when the room closes (idle grace or DELETE /v1/files/{id}/session). A server restart or deploy keeps the canvas for the reconnect.
  • Fixed Plugin: tokens signed with Jitsi's luajwtjitsi did not verify (non-standard signature encoding); the plugin now signs with Prosody's own HMAC. Jitsi appends its Etherpad options with ?, which broke the token; the launch URL now ends in &ep=.

0.1.0 (2026-11-23)

  • Added Block schema validation (MOD-01) in oc-model on .ocanvas read, REST patch, import and MCP writes, with JSON-pointer paths; unknown nodes are warnings, kept and counted in oc_schema_warnings_total.
  • Security MCP audience (SEC-33): the MCP token audience comes from [host.ai] mcp_audience or OC_PUBLIC_URL, never from the request's Host header. Without either, MCP is off (404) and the server logs one start-up warning.
  • Security MCP file scope (SEC-34): when the host has no /access callback, an MCP token must name its files in a files claim; a token without one is refused (FILES_REQUIRED). The broad behaviour (one token's role on every file) needs [host.ai] mcp_all_files = true.

0.1.0-alpha.1 (2026-11-23)

  • Added Host integration: HS256, RS256, EdDSA and JWKS launch tokens; signed callbacks; the live role API; host members and revocation; the <open-canvas> embed SDK and postMessage API; access expiry warning and quiet renewal (ADR-036).
  • Added WOPI client mode: discovery, CheckFileInfo, GetFile, PutFile, PUT_RELATIVE conflict copies, assets and mentions, and a reference WOPI host.
  • Added AI assistant and MCP endpoint (experimental, disabled by default): server-side model providers (Claude Platform, OpenAI-compatible servers), plan → approve → act → review → undo runs, suggestions, limits, quotas and audit; MCP at POST /mcp/{hostId} with host-issued tokens (ADR-031 to ADR-035).
  • Fixed Saves kept using a revoked editor's token after a role change (docs/23 PERM-05).
  • Security Callback and outbox tokens sealed at rest with AES-256-GCM under OC_KEK; the server refuses to start without OC_KEK outside development.
