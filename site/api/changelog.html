API changelog

The API-relevant entries of CHANGELOG.md, newest first. The OpenAPI document is version 1.0.0; within /api/v1 changes are additive, and a breaking change gets a new path major.

Unreleased

  • Added OpenCanvas Workspace settings: Branding (accent colour, sign-in page message), E-mail (SMTP settings, password write-only), Backups ("Back up now": a consistent database copy and every file in the data volume), and the admins' setup checklist on Home. CI builds the Workspace image and records its size, start time and memory at rest (scripts/workspace/image-smoke.sh).
  • Added Typed files (docs/05 §2f, FTY-02): a launch token's file.type (spreadsheet, whiteboard, database) opens the editor in app mode (&app= in its fragment, no template picker), and a new typed file starts as one spreadsheet, board or database block. An unknown type is refused with 400 TYPE_INVALID; /hosting/capabilities lists fileTypes. The full-page app chrome for each type follows.
  • Added OpenCanvas Workspace back end (crates/oc-workspace, binary opencanvas-workspace, ADR-085): the Workspace host and the engine in one process on one port, talking only through the host contract. First-run setup with a six-word setup code (skipped from the same machine), accounts with Argon2id passwords, sessions, CSRF checks and lockout, invite links, admin reset links, workspaces, folders, teams, typed files, sharing with inheritance, organisation and public links (admin-configurable: allowed, highest role, expiry, password), search from search.json, Trash with retention and version history with thinning. Every access change is sent to the engine's role API, so open sessions follow at once.

0.4.0 (2026-11-28)

  • Added Backup and restore (RLB-03, docs/13): a runbook for SQLite, MySQL/MariaDB and Redis, scripts/restore-drill.sh, and a restore epoch. Start once with OC_RESTORED=1 after a restore. Devices revoked after the backup stay revoked (every offline copy is dropped once), and schedule slots due before the restore are skipped instead of running twice. Migration 0013 adds the restore_epoch table.
  • Added Partial sync in the room (PSYNC-02, ADR-076), behind [host.flags] partial_sync (off by default; leave it off until the 0.4 editor ships): databases and boards become subdocuments on the room socket (message type 101, docs/15 §3.2), loaded when a connection asks, the role checked per request, evicted when unheld; the API, MCP, history, templates, AI tools, automation and saves work on a whole view flattened with the original item ids, so saves stay .ocanvas format v1. Editors without caps=subdoc are closed with 4426 on a split room. Room memory on the 50 MB fixture with 20 viewers (caps=subdoc, first page, no edits; release build, Apple M4, local; one process per figure, test-process RSS): split room opened from its WAL 220 MB (a high-water mark: opening walks every part once, one at a time, to index its ids) against 4,401 MB for the same room whole (2,382 MB in a second run), 5-9%, under the 30% bar (tests/partial_sync.rs room_memory_on_the_fixture).
  • Fixed After a restart with a slow host, rooms reopen and save at full speed (RLB-01c): a room no longer holds one of the OC_ROOM_LOADS slots while the host answers its file request.
  • Fixed Overload never answers 500: while rooms recover after a restart (more than OC_ROOM_LOAD_QUEUE, default 32, waiting to load) or when no database connection is free, launches, session lookups and WebSocket upgrades answer 503 with a Retry-After of 1-5 s. The browser launch shows "Reconnecting…" and posts again; the editor waits out Retry-After for up to 60 s instead of showing an error (RLB-01b).
  • Fixed A launch that failed after its token was recorded (database timeout, server killed mid-launch) spent the token, so every retry was refused as a replay. The token is now spent last (SEC-59).
  • Fixed Partial sync (off by default): one client id writing both the main document and a block's document made the whole view drop the block's content (SEC-54); block edits now count against the document size limit (SEC-55).
  • Fixed After a restart on MySQL/MariaDB, launches failed with 500 for about 20 s while every room reopened at once (connection pool exhausted). Rooms now load at most 8 at a time (OC_ROOM_LOADS), and the pool is 32 connections (OC_DB_MAX_CONNECTIONS; RLB-01b).
  • Fixed Load generator: a client refused by a full room retried every 0.5 s and counted as a drop; it now backs off and is counted as refused.
  • Fixed Automation in a cluster (AUTO-CL): rule operations (API, editor, MCP) sent to a node that does not hold the canvas answered 503; they now run on the owner. A scheduled rule whose canvas was open on another node could be put off for five minutes at a time; the node holding the canvas now runs it. A run cut off by a node that stopped is logged as failed (INTERRUPTED) after an hour instead of staying "running".
  • Added Benchmark program, first part (BENCH-01, BENCH-04, ADR-079): scripts/bench/run <scenario> with scenario files in bench/scenarios/ that state their load mix (X10K, R1K, STORM, SOAK, and the docs/22 scenarios run unchanged), oc-bench scenario (idle, presence-only and typing peers, latency per bucket, kill -9 and restart mid-run with reconnect timing, source addresses), JSON results with hardware, load average and mix in bench/results/, seeded fixtures (oc-bench fixture s|m|l|50mb), bench/budgets.toml, the initial-JS and --forbid gate in scripts/prepush.sh and CI, and a nightly benchmark workflow.
  • Added OFF-08 tests: a three-client simulated day offline in vitest (text, database cells, board objects, block deletes and moves, comments; the real replay frames, cut connections, the pending log and the merge summary; seeds 1, 7, 42 and OC_FUZZ_SEED, a long run behind OC_FUZZ_LONG=1), and Playwright zf-offline-2 (expiry by the browser clock, queued upload end to end, the 5 MB pause).

0.3.0 (2026-11-26)

  • Added Automation, server side (AUTO-01..05, AUTO-07, ADR-067, ADR-068; off unless [host.automation]): rules stored in the canvas (automations root) run by the server as "Automation" on behalf of their owner, re-checked with the host's /access at every run. Triggers: row added, field changed, checklist item checked, comment or mention added, a date reached and schedules (every 15 minutes or more, in the canvas time zone, even with the canvas closed). Actions: set a field, move a row, check or add checklist items, comment, notify through the host's POST /mentions, and call a URL signed like webhooks on allowed origins only. Loop guard (never itself, 3 deep), limits, auto-pause after 10 failures, a metadata-only run log (30 days), automation.ran/automation.failed events, perms.automate, migration 0010, the API (/api/v1/files/{id}/automations…) and MCP tools.
  • Added Offline copies, server side (OFF-01, OFF-07, ADR-063/064): [host.offline] (off by default; checked at start-up; JWT hosts only), the launch token's perms.offline and offlineReason, an ES256 offline grant in the session answer that the editor keeps with its copy and uses only on the device, a revocation generation per host and person (migration 0011; Redis oc:offgen:) raised by POST /api/v1/offline/revoke, and the GET /v1/offline/clear sign-out page. The server stores one number per host and person, never content.
  • Added Offline-first editing in the editor (OFF-02..07, ADR-063/064/073, the approved prototype): a person keeps a canvas on their device ("Available offline on this device"), encrypted in IndexedDB under a per-person device key; it opens and edits without a network (a service worker caches the editor code, never content) and locks when its 7-day grant runs out. The save pill shows where changes are (on this device, or this tab only). Reconnecting is a fresh launch through the host; unsent changes go in frames under the frame and rate limits, long sessions get a "Before <name>'s offline changes" version first and collaborators a toast. A merge summary appears only for edits inside a deleted block (restore as a new block) and both-sides cell changes (use mine). View only on reconnect holds the changes (download or discard); no access deletes the copy. Images added offline wait as oc-pending: and upload first. Hosts clear the device at sign-out with OpenCanvas.clearOffline() or the /v1/offline/clear iframe and list copies with OpenCanvas.offlineFiles().
  • Added Live blocks in the editor (LIVE-03, LIVE-07, approved prototype, ADR-073): an always-visible header (Live mark, title, the people in it, Open source, options), editing in place with presence, a one-time hint on the first edit, view only, and every failure state (connecting, not up to date, no access with or without the title, deleted or moved, access removed, limits). The header says where the source lives ("from Leadership weekly › Q1") when the host's /access answers the new optional path (≤ 200 characters, shown as text), else the host's name. Inside a live block, "/" offers the same categorised insert menu, filtered by the host profile, without live blocks (depth rule) and without what acts on the embedding canvas (assistant, import, uploads, SDK blocks). "Make live…" in the block menu, "Live block" in the insert menu through the host's own picker (UI_PickLiveBlock → Action_InsertLiveBlock), and paste a block link as a live block, a reference or a link. References refresh on their own and flash once. "Convert to a copy" and "Who can see this" (GET /v1/live/audience). A host answers /access with 410 for a deleted live file. Phones get a compact header and an options sheet. The live block code loads only when a canvas shows one.
  • Added <open-canvas view="block"> (LIVE-06): one live block with compact chrome for chats and side panels; its height follows the content (UI_Resize, oc:resize). The SDK gains insertLiveBlock(), livePicker(), liveBlockUsage() and the oc:pick-live-block, oc:live-block-open and oc:live-block-usage events.
  • Added Search across canvases, server side (SRCH-02/03/05, ADR-065): every saved .ocanvas carries search.json, a plain-text projection with block ids and heading trails for the host to index (comments only with [host.search] comments = true; never in-file history; at most 2 MB). POST /api/v1/extract answers it statelessly for a .ocanvas or Markdown body. Hosts may implement GET /search ([host.search] callback = true); GET /api/v1/search and the MCP tool canvas_search proxy it for user tokens only, 10 a minute per user, dropping files the host's /access refuses. OpenCanvas keeps no index and caches no result. The sample host indexes search.json and serves the callback and a search page.
  • Added Portable live blocks, server side (v0.3, behind [host.flags] live_blocks, off by default): the host contract (LIVE-01, docs/05 §2c, ADR-070): [host.live] checked at start-up, the POST /files callback, /access required (with optional name and callbackToken), the token's perms.live and live claims, derived sessions for embedded live files (POST /v1/live/session) and "Make live" (POST /v1/live/make).
  • Added Live block projections, snapshots, exports and render (LIVE-04/05/06, ADR-072): GET /v1/live/projection with ETags, POST /v1/live/refresh under the snapshot policy, exports that inline only what the exporting person can read, and API operations makeLive, listReferences and renderFile (GET /api/v1/files/{id}/render) in the OpenAPI document, both clients and the conformance suite.

0.2.1 (2026-11-26)

  • Fixed A newly inserted SDK block takes focus when its frame is ready only while it is still selected.

0.2.0 (2026-11-25)

  • Added Headless API is the supported contract. /api/v1 with OpenAPI 3.1, RFC 9457 errors, scoped user tokens shared with MCP, Idempotency-Key, signed cursors, rate limits, the events stream and the sync token. Most of it shipped in 0.1.2 behind [host.flags] api_v1.
  • Added Webhooks for the events-stream events (WH-01): [host.webhooks], signed deliveries (X-OpenCanvas-Signature v2, Idempotency-Key = event id) from a durable outbox (migration 0009_webhook_outbox), retries with backoff, each sent once per cluster, same origin as callback_base only.
  • Added Clients: TypeScript @opencanvas/client and Rust opencanvas-client, generated from the OpenAPI document, with retries, idempotency keys, paging, events resume and webhook verification. They share a conformance suite (HAPI-06, HAPI-07).
  • Added MCP canvas tools are adapters over the API operations, with one scope check, limiter and idempotency store, and a parity contract test (HAPI-08). New operation: POST /api/v1/files/{id}/boards.
  • Added Block SDK (data side): - block.json manifests installed by the operator (OC_BLOCKS_DIR, sha384 integrity, OC_BLOCKS_ORIGIN) and enabled per host with [host.blocks]; - JSON Schema validation of attrs and data on every write path; - one generic extBlock node and an ext root; - declarative export templates and fallbacks; - data versions with declarative migrations (BSDK-01, -02, -05).
  • Added API reference on the website (/api/): guides for authentication, errors, pagination, idempotency, rate limits, events, webhooks and the SDKs, and one page per resource generated from the OpenAPI document, with samples in curl, TypeScript, Rust and Python.
  • Added tools/check-openapi.py: every API operation is documented with examples and its error codes.
  • Changed An editor older than 0.2 that would delete an SDK block is closed with 4426 ("editor out of date: reopen the canvas").
  • Changed A webhook sweep claims at most 40 deliveries, and the next sweep starts at once (SEC-48).
  • Security SEC-46: room updates over the WebSocket are checked against installed SDK block schemas, as API and MCP writes are. A broken block could otherwise make the file unopenable.
  • Security SEC-51: a restore's undo cannot be reached with a crafted restoreId by a user whose id is a suffix of the restorer's.

0.1.2 (2026-11-24)

  • Added Version history with named versions, preview and comparison, restore and temporary undo where supported by the host.
  • Added Headless API under /api/v1 with OpenAPI 3.1, scoped tokens, and idempotency keys on file writes.
  • Added API events stream (SSE and WebSocket) with resume, and a headless sync token.
  • Fixed A Jitsi role change takes precedence over launch tokens issued before the change.

0.1.1 (2026-11-23)

  • Added Jitsi Meet (integrations/jitsi/, JIT-02): mod_opencanvas.lua gives every meeting a shared canvas in Jitsi's Shared document slot, like Etherpad. One Prosody plugin plus .env lines, no Docker image or compose changes. Per-person launch tokens, a fresh token on reload, the meeting end closes the canvas. Tested end to end against a stock docker-jitsi-meet (stable-11509-1) with two browsers; guide in integrations/jitsi/README.md.
  • Added Temporary canvases (storage = "ephemeral", ADR-043, JIT-01) for hosts with no file storage: no load or save callbacks; everything is deleted when the room closes (idle grace or DELETE /v1/files/{id}/session). A server restart or deploy keeps the canvas for the reconnect.
  • Fixed Plugin: tokens signed with Jitsi's luajwtjitsi did not verify (non-standard signature encoding); the plugin now signs with Prosody's own HMAC. Jitsi appends its Etherpad options with ?, which broke the token; the launch URL now ends in &ep=.

0.1.0 (2026-11-23)

  • Added Block schema validation (MOD-01) in oc-model on .ocanvas read, REST patch, import and MCP writes, with JSON-pointer paths; unknown nodes are warnings, kept and counted in oc_schema_warnings_total.
  • Security MCP audience (SEC-33): the MCP token audience comes from [host.ai] mcp_audience or OC_PUBLIC_URL, never from the request's Host header. Without either, MCP is off (404) and the server logs one start-up warning.
  • Security MCP file scope (SEC-34): when the host has no /access callback, an MCP token must name its files in a files claim; a token without one is refused (FILES_REQUIRED). The broad behaviour (one token's role on every file) needs [host.ai] mcp_all_files = true.

0.1.0-alpha.1 (2026-11-23)

  • Added Host integration: HS256, RS256, EdDSA and JWKS launch tokens; signed callbacks; the live role API; host members and revocation; the <open-canvas> embed SDK and postMessage API; access expiry warning and quiet renewal (ADR-036).
  • Added WOPI client mode: discovery, CheckFileInfo, GetFile, PutFile, PUT_RELATIVE conflict copies, assets and mentions, and a reference WOPI host.
  • Added AI assistant and MCP endpoint (experimental, disabled by default): server-side model providers (Claude Platform, OpenAI-compatible servers), plan → approve → act → review → undo runs, suggestions, limits, quotas and audit; MCP at POST /mcp/{hostId} with host-issued tokens (ADR-031 to ADR-035).
  • Fixed Saves kept using a revoked editor's token after a role change (docs/23 PERM-05).
  • Security Callback and outbox tokens sealed at rest with AES-256-GCM under OC_KEK; the server refuses to start without OC_KEK outside development.
