In short

What is OpenCanvas?

OpenCanvas, by CasualOffice, is an open-source, real-time collaborative canvas that other applications embed, the way they embed Collabora Online for office files. One document holds rich text, spreadsheets, databases with Timeline (Gantt) and Workload views, whiteboards and diagrams, with live cursors and comments. Your application keeps the users, the permissions and the file; OpenCanvas does the editing and saves the file back to it.

The facts page has the release, the licence, the stack and the measured capacity, each with its source; the FAQ has short answers.

How it fits

Your app decides. OpenCanvas edits.

Your backend checks who may open which file, signs a short launch token, and opens OpenCanvas in an iframe. From then on OpenCanvas runs the live session and calls your app back to load and save the file. Once a session is saved and idle, it keeps nothing.

  • {{icon:building:16}}Your app ownsSign-in, users, who can view, comment or edit, the file itself, its versions and its retention.
  • {{icon:users:16}}OpenCanvas ownsThe editor, real-time merge, cursors and presence, preview, export, and autosave back to your storage.
  • {{icon:server:16}}One serverA Rust binary with the editor built in. SQLite by default; MySQL or MariaDB and Redis when you run several nodes.
  • {{icon:code:16}}One embedAn iframe form POST, or the <open-canvas> web component, with events for ready, saved, presence and errors.
Why it matters

Three ideas, in plain words.

The names in the strip above are what let OpenCanvas sit inside someone else's product without taking over its data.

  • CRDT

    Edits that cannot collide

    Every change is a small update that merges with everyone else's in any order, the same way on every screen. The server orders and relays updates; it never has to resolve a conflict between two people typing.

    So: live co-editing without locks, and brief disconnects resync on their own.

  • Host callbacks

    The file never moves house

    OpenCanvas loads the file from your app when a session opens and writes it back with a plain HTTP call, signed so you know it is us. If your file changed elsewhere, your chosen policy runs: save a copy, or reload.

    So: your storage, versions and retention rules stay the only ones.

  • Autosave

    Nobody presses Save

    Changes save on a short timer, when the canvas goes idle, when the last person leaves and when the server shuts down. Each save is written to an outbox first, so a restart resends it rather than losing it.

    So: the status reads Saved, and that is true.

{{icon:triangle-alert:18}}Early release: current limits

  • No SLA. Support is best effort. The release notes list the limits and upgrade steps.
  • Durability depends on the mode. Use wal mode or a Redis WAL when every acknowledged edit must be on disk; see operations.
  • Single node is the tested path. Cluster mode passes the crash and chaos drills; scale-out across machines is not yet demonstrated. Benchmarks so far ran on a laptop.
  • Very large canvases open slower than our target. A 50 MB canvas shows its first screen in about 6 s (target 2 s), and spreadsheets do not load on demand yet.
  • The assistant and MCP are experimental and off by default. When turned on, canvas content goes to the model server the operator configures.

What it may do, in plain words

  • {{icon:lock}}It acts as you, and only as youEvery change it makes passes the same server-side role check as your own typing. If you can only view, it cannot run; if you can only comment, it can answer and comment, not edit.{{claim:tested|viewer refused, commenter answer and comment only|crates/oc-server/tests/ai.rs}}
  • {{icon:pencil}}Existing text gets suggestionsBy default, changes to what people wrote arrive as suggestions you accept or reject; new content is added directly. Your operator can change the default per app.{{claim:tested|suggest mode writes only to suggestions|crates/oc-server/tests/ai_tools.rs}}
  • {{icon:circle-check}}Nothing before you approveThe run waits at the plan. Cancel it there and the canvas is unchanged.{{claim:tested|nothing before approval; cancel leaves nothing, over real sockets|crates/oc-server/tests/ai_e2e.rs}}
  • {{icon:undo-2}}Attributed and undoableIts edits carry the assistant's own identity, separate from yours, and Undo run removes them as one step.{{claim:tested|undo reverts the run's origin|crates/oc-server/tests/ai.rs}}
  • {{icon:server}}Content goes only where your operator saysThe canvas text the assistant works on is sent to the model server your operator configures, and nowhere else: the Claude Platform, or a self-hosted model through vLLM, Ollama or llama.cpp. Browsers never call a model or see a key.{{claim:deployment|[ai.providers] in the server's OC_AI_CONFIG file, chosen per app in hosts.toml}}
  • {{icon:shield-check}}Self-hosted models need tool callingThe server checks each model at start-up. A model that cannot call tools gets answer mode only; agent mode stays off for it.{{claim:tested|agent mode needs a tool-calling model|crates/oc-server/tests/ai.rs}}

{{icon:plug:18}} MCP for external agents

Agents outside the editor, such as your own backend or a desktop assistant, can read and edit a canvas through the Model Context Protocol endpoint, POST /mcp/{hostId}. Every change shows live to the people in the canvas.

Your app issues the tokens and OpenCanvas only checks them, with the same keys as launch tokens. A token's scopes can narrow what the user's role allows, never widen it. The endpoint is off until you turn it on. {{claim:tested|off by default; bad tokens refused; a scope narrower than the role wins|crates/oc-server/tests/mcp.rs}}

hosts.toml
[host.ai]
enabled      = true
provider     = "claude"     # a profile in [ai.providers]
default_mode = "suggest"    # for changes to existing text
mcp          = true         # POST /mcp/{hostId}; off by default
mcp_issuer   = "https://id.acme.example"

Integrate

Three steps to a live canvas in your app.

Register your app with the server, embed the editor with a token your backend signs, then answer a few HTTP callbacks. The code below is from the integration guide.

1. Register your host
# opencanvas.hosts.toml
[[host]]
id              = "acme"
name            = "Acme"
mode            = "jwt"
jwt_alg         = "HS256"
jwt_secret      = "env:ACME_OC_SECRET"
api_key         = "env:ACME_OC_API_KEY"
callback_base   = "https://api.acme.example/opencanvas"
allowed_origins = ["https://app.acme.example"]
2. Embed it with a signed token
<script type="module"
  src="https://canvas.example.com/sdk/embed.js"></script>
<open-canvas server="https://canvas.example.com"
  token="{{ jwt }}" theme="auto"
  style="height:100vh"></open-canvas>

// Your backend signs the token after its own ACL check:
// file, user, role (view | comment | edit), perms

3. Answer these callbacks from your backend:

  • {{icon:download:18}}GET /files/{fileId}Load: return the file and its version
  • {{icon:save:18}}PUT /files/{fileId}Save: store it, answer the new version, or 409
  • {{icon:file-up:18}}POST /files/{fileId}/assetsStore an uploaded image or file
  • {{icon:users:18}}GET /files/:id/membersPeople with access to the file, for @mentions
  • {{icon:copy:18}}POST /files/{fileId}/copiesSave a copy when the file changed elsewhere
  • {{icon:fingerprint:18}}X-OpenCanvas-SignatureHMAC-SHA256 on every call, so you know it is us

Block SDK · v0.2

Build your own blocks.

An OKR tracker, a ticket card, a chart from your own service: write it once with @opencanvas/block-sdk. OpenCanvas runs it in a sandbox, keeps its data in the document, lets people edit it together and exports it. The code below is from the Block SDK guide.

1. Write the block
import { defineBlock, h } from "@opencanvas/block-sdk";

defineBlock<{ value: number }>({
  render(el, ctx) {
    const slider = h("input", { type: "range" });
    slider.addEventListener("change", () =>
      ctx.setAttrs({ value: Number(slider.value) / 100 }));
    el.append(slider);
  },
});
2. The host turns it on
# opencanvas.hosts.toml
[host.blocks]
enabled = ["oc.progress", "acme.okr@^1"]

[host.blocks.permissions."acme.okr"]
members = "none"   # narrow what it may read
  • {{icon:shield-check:18}}SandboxedEach block runs in its own frame on a separate origin, with a strict content policy
  • {{icon:fingerprint:18}}CheckedManifests, hashes and schemas are verified; the server re-checks every change
  • {{icon:users:18}}LiveCo-editing, comments and roles work in custom blocks as in built-in ones
  • {{icon:file-text:18}}Never lostA missing or refused package shows its saved copy; the data stays in the file

Self-host

One container to start, more nodes when you need them.

A single node runs on SQLite with no database to set up. For many concurrent users, point several nodes at MySQL or MariaDB and Redis: each room has one owner node, and the others relay to it.

Single node, SQLite

  -e OC_PUBLIC_URL=https://canvas.example.com \
  -e OC_KEK=$(openssl rand -base64 32) \

Questions people ask.

More in the documentation FAQ.

Can I use it in production today?{{icon:chevron-down}}

The current release has best-effort support and no production SLA. Review the known limitations before committing it to a production workflow.

What does the licence allow?{{icon:chevron-down}}

OpenCanvas is open source under the Apache-2.0 licence. You may use, modify, self-host, embed and redistribute it, in open or closed, commercial or non-commercial products. When you redistribute it, keep the NOTICE file. The LICENSE file has the exact terms.

Does OpenCanvas keep my documents?{{icon:chevron-down}}

Only while a session is live. The server keeps a snapshot and the recent updates so it can survive a restart and let late joiners catch up, and deletes them after the session is saved and idle. The file itself lives in your app.

How do users sign in?{{icon:chevron-down}}

They sign in to your app, not to OpenCanvas. Your backend checks access and signs a short-lived launch token naming the file, the user and the role; OpenCanvas trusts that decision for the life of the token and enforces it on every edit.

Can we use it in Jitsi Meet, like Etherpad?{{icon:chevron-down}}

Yes. Add one Prosody plugin and a few .env lines to your Jitsi deployment, with no Docker image or compose changes. Everyone in the meeting opens the same canvas from Shared document. The canvas is temporary: it starts blank or from a template you choose, nothing is stored, and it is deleted when the meeting ends, so people download what they want to keep. See Jitsi Meet.

We already use Collabora through WOPI. Can we reuse that?{{icon:chevron-down}}

Yes. OpenCanvas speaks WOPI as a client: discovery, CheckFileInfo, GetFile, PutFile and PUT_RELATIVE, with an allow-list for the WOPISrc it will call. See WOPI mode.

What can it export?{{icon:chevron-down}}

Markdown, HTML, JSON, its native .ocanvas, Word, and PDF when the operator runs the optional Gotenberg sidecar (otherwise the editor prints to PDF). Whiteboards export as SVG and PNG.
