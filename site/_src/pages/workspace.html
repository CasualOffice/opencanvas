OpenCanvas Workspace · by CasualOffice

Your team's workspace, in one Docker command.

OpenCanvas Workspace is the complete, self-hosted app around the OpenCanvas engine: documents, spreadsheets, whiteboards and databases, with accounts, sharing, search, trash, version history and an admin area. No app of your own to build, no integration: run one container and invite your team.

Run it
docker run -p 8080:8080 -v opencanvas:/data ghcr.io/casualoffice/opencanvas-workspace

Then open http://localhost:8080 and create the first admin. From another machine, enter the one-time setup code printed in the container log. Free and open source under Apache-2.0; linux/amd64 and linux/arm64.

Self-host

One container to try it, compose for production.

The single container keeps everything in the /data volume, on SQLite, with its secrets generated on first start. For production, the same image runs as one Workspace and two engine nodes behind nginx, with MariaDB and Redis.

Behind your HTTPS proxy
docker run -d --name opencanvas \
  --restart unless-stopped \
  -p 8080:8080 -v opencanvas:/data \
  -e WS_PUBLIC_URL=https://canvas.example.com \
  -e WS_TRUST_PROXY=1 \
  ghcr.io/casualoffice/opencanvas-workspace
Compose: Workspace, two engines, MariaDB, Redis
# from a clone of the repository
cp deploy/workspace/.env.example deploy/workspace/.env
# fill in the secrets, then
docker compose -f deploy/workspace/compose.yml \
  --env-file deploy/workspace/.env up -d

{{icon:triangle-alert:18}}What it does not do yet

  • No single sign-on yet. OIDC SSO is on the backlog. Sign-in is passwords, passkeys and invite links.
  • E-mail is not sent yet. Invites, mentions and password resets are links you copy and send yourself.
  • Backups are manual. Back up now in Settings, or copy the volume; no schedule or restore command yet.
  • Files are stored on the volume. S3-compatible storage is not there yet.
  • Early release. One organisation per deployment; best-effort support and no production SLA.

Every item is a row in the project's tracker, and the roadmap is generated from it.

Questions people ask.

More in the Workspace guide.

How is the Workspace different from the OpenCanvas engine?{{icon:chevron-down}}

The engine is what you embed in your own application, which keeps the users, the permissions and the files. The Workspace is a complete application built on the engine through the same public contract, for teams that have no application to embed it in. Both are in the same repository and share version numbers.

Where is my data stored?{{icon:chevron-down}}

In the /data volume on your own machine: a SQLite database, the files, backups and the generated secrets. With the compose file, the databases are in MariaDB. Nothing is sent anywhere else, and the optional AI assistant is off unless the operator configures a model server.

How do I back it up?{{icon:chevron-down}}

Use Back up now in the admin settings, or stop the container and copy the volume. Keep the secrets folder with the backup: without it, saved sessions cannot be read. Scheduled backups and a restore command are planned.

Can people outside the organisation open a file?{{icon:chevron-down}}

Yes, if an admin allows public links. A public link has the highest role the admin permits, and can have an expiry and a password. Guests are another option: they see only what is shared with them.

Is it free?{{icon:chevron-down}}

Yes. OpenCanvas Workspace is open source under the Apache-2.0 licence. Support is best effort, with no production SLA.
