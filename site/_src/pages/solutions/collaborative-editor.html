OpenCanvas by CasualOffice · Use case

A real-time collaborative editor for your application

Building live co-editing yourself means a CRDT, a sync server, presence, permissions, autosave and an editor people enjoy. OpenCanvas is all of that as one open-source server and one embed, the way apps embed Collabora Online for office files.

How it fits into your app

  1. Register your app with the OpenCanvas server: its id, the key it signs with, and the base URL of your callbacks.
  2. Embed the editor with a short-lived launch token your backend signs after its own access check: which file, which user, and the role (view, comment or edit). Use an iframe or the <open-canvas> web component.
  3. Answer a few callbacks. OpenCanvas loads the file from your app, saves it back on its own, stores uploads through you, and asks you who may be @mentioned. Every call is signed.

Already a WOPI host, as for Collabora? OpenCanvas speaks WOPI too. See WOPI mode.

What you get

  • Live co-editing that cannot collide. Edits merge with Yjs, a CRDT, with live cursors, presence, follow mode and comment threads.
  • One editor for many kinds of content. Rich text blocks, databases, an Excel-style spreadsheet, linked charts, whiteboards and diagrams, from one insert menu.
  • Profiles for your product. Each host picks a notebook, meeting, project, diagramming, document or full profile, and can switch whole features off.
  • Autosave, no Save button. Saves go through a durable outbox, so a restart resends them. If the file changed elsewhere, your policy runs: save a copy, or reload.
  • An API around it. A REST API under /api/v1 with TypeScript and Rust clients, signed webhooks, and a Block SDK for your own sandboxed blocks.
  • Small to operate. One Rust server with the editor built in, on SQLite; MySQL or MariaDB and Redis when you run several nodes. Docker image and Helm chart.

What stays yours

Sign-in, users, permissions, the file, its versions and its retention. OpenCanvas keeps only a transient room log and a save outbox while a session is live, and never becomes the system of record.

Measured, with the load stated

The benchmarks page publishes every run with its hardware and load mix, and the sizing guide turns them into server sizes. The runs so far are on a developer laptop, not the reference machine, so rerun them on your own hardware before you size production.

Questions people ask.

More in the documentation FAQ.

Why not build on Yjs and an editor library directly?{{icon:chevron-down}}

You can, and OpenCanvas is built that way. What it adds is the rest: a server that enforces roles on every change, presence, autosave through a durable outbox, host callbacks, exports, a database and spreadsheet model, cluster mode, and the tests and benchmarks around them.

Which frameworks does the embed work with?{{icon:chevron-down}}

Any. The editor runs in an iframe from the OpenCanvas server, opened by a form POST or by the open-canvas web component, and talks to your page through postMessage events. Your backend can be written in any language that signs a JWT.

Can I limit what the editor offers?{{icon:chevron-down}}

Yes. Editor profiles choose which blocks people can insert, and features such as comments, version history, templates, import, diagramming and the assistant can be switched off per host.

Is it ready for production?{{icon:chevron-down}}

It is an early release with best-effort support and no production SLA. Read the known limitations in the release notes before you rely on it.
