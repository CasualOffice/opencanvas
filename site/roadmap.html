Roadmap

Where OpenCanvas stands and what comes next, generated from the project's roadmap and its execution tracker. Every unit of work has a row there; this page shows each row's status as the tracker records it.

This is the project's plan, not a commitment. No dates are promised. "Built, in review" means the work is merged and verified and waits for the owner's approval. Ideas and requests are welcome as GitHub issues.

Release roadmap

OpenCanvas integrates with any third-party application through standardized APIs and SDKs, without depending on specific CasualOffice products. Hosts connect through the documented launch tokens, callbacks, WOPI, REST, postMessage, the <open-canvas> SDK and MCP; nothing in the server or editor assumes a particular host. This keeps the project independent and modular, and open to a broad developer ecosystem (ADR-038).

VersionFocus
v0.1First public alpha: the collaborative editor, databases, whiteboards and embedding
v0.1.2Additional host integrations, structured diagramming, version history, headless API foundation, link previews, team templates and viewer previews

v0.2.0 (released 2026-11-25)Stable headless API (/api/v1) with TypeScript and Rust clients, webhooks, version history, the block SDK, and host editor profiles. Live blocks moved to v0.3
v0.3Portable live blocks, offline-first editing, search and automation (plan proposed 2026-11-26)
v0.4Performance and partial synchronization, as a benchmark, performance and maturity release: partial sync, a benchmark program with published results and CI gates, 10k connections per node and 1,000 editors in a room, lower browser memory and lazy modules; reliability drills and a security audit; also formulas, relations, rollups, virtualized databases, integrations and UX fixes (plan proposed 2026-11-26)
v0.5Plugin ecosystem, developer tooling and enterprise hardening
